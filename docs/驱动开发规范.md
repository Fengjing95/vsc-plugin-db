## 1. 定位与驱动包结构

驱动是 core 与具体数据库之间的**唯一翻译层**：把统一模型（`DatabaseMeta` / `ColumnMeta` / `ResultSet` / `ChangeSet`…）与方言（SQL / 命令）互相转换。驱动**不含** UI 逻辑、不含缓存策略（缓存由 core 的 `MetadataCache` 负责）、不含危险操作判定（由 `DangerGuard` 负责）。

```
driver-xxx/
├── src/
│   ├── index.ts          # 导出 createDriver()
│   ├── driver.ts         # 实现 IDatabaseDriver
│   ├── connection.ts     # 实现 IConnection
│   ├── metadata.ts       # 元数据自省 SQL / 命令
│   ├── rows.ts           # fetchRows / 筛选下推 / 分页
│   ├── changes.ts        # previewChanges / applyChanges
│   ├── errors.ts         # 原生错误 → DriverError 映射
│   └── schema.ts         # getConnectionFormSchema
├── package.json          # 见 §9
└── README.md             # 必须声明：能力矩阵、权限要求、版本兼容
```

命名：npm 包 `@db-explorer/driver-<id>`（官方）或 `<scope>/vscode-db-<id>`（社区）；驱动 `id` 为小写字母/数字/连字符，全局唯一。

## 2. API 版本协商

- `DRIVER_API_VERSION` 当前为 `1`，由 core 导出，驱动以 `readonly apiVersion = 1` 声明
- `DriverRegistry.register()` 时校验：主版本不一致 → 拒绝注册并提示“驱动 X 要求 API vN，请升级/降级插件”；次版本（未来引入）向前兼容
- 破坏性接口变更必须升主版本；新增**可选**方法/字段不升主版本，但必须在 JSDoc 标注 `@since`

## 3. 驱动接口全集（类型定义）

```ts
import { Disposable, EventEmitter } from 'vscode';

// ───────────────────────── 类型归一 ─────────────────────────
type NormalizedType =
  | 'string' | 'integer' | 'decimal' | 'float' | 'boolean'
  | 'date' | 'time' | 'datetime' | 'json' | 'binary' | 'uuid' | 'unknown';

type NodeLevel =
  | 'connection' | 'database' | 'folder'
  | 'table' | 'view' | 'collection'
  | 'column' | 'key' | 'index';

// ───────────────────────── 能力声明 ─────────────────────────
interface DriverCapabilities {
  supportsSQL: boolean;                    // Console 是否可用
  supportsTransaction: boolean;            // applyChanges 可否单事务（false 时必须逐条说明补偿策略）
  supportsInteractiveTransaction: boolean; // 可否手动 BEGIN/COMMIT（openSession）
  supportsMultipleDatabases: boolean;
  supportsMultiStatement: boolean;         // 一次 query 传多语句
  supportsCancel: boolean;                 // 真正响应 AbortSignal（契约测试强制）
  supportsDdl: boolean;                    // 树上暴露 DDL 查看
  /** @since v0.1.2（M8-B2）：表结构编辑器（概要 §5.9）——声明为 true 时必须实现 buildCreateTable/buildAlterTable */
  supportsDdlEditor?: boolean;
  /** @since v0.1.11（M8-DBDDL / D-19）：库级 DDL——声明为 true 时按需实现 buildCreateDatabase/
   *  buildAlterDatabase/buildDropDatabase + getDatabaseFormSchema（方法存在性裁剪菜单） */
  supportsDatabaseDdl?: boolean;
  /** @since v0.1.15（表设计器批次 B，交互稿 §12.2）：表设计器各 Tab 能力——uniqueKeys/foreignKeys/
   *  foreignKeyAlter/indexes/indexTypes/refActions；未声明 = 对应 Tab 隐藏（编辑器回落纯列编辑）。
   *  例外：SQLite foreignKeyAlter=false（无原地 ALTER 约束语法），alter 态外键 Tab 只读 + 驱动 E_UNSUPPORTED */
  tableDesign?: { uniqueKeys?: boolean; foreignKeys?: boolean; foreignKeyAlter?: boolean; indexes?: boolean; indexTypes?: string[]; refActions?: string[] };
  /** @since v0.1.15（M8-ER，概要 §5.11 / D-22）：ER 图查看——声明 = listKeys 的 FK 元数据完整可用
   *  （关系收集零新增驱动方法，只消费 listObjects/listColumns/listKeys 自省）；未声明树无入口 */
  supportsErDiagram?: boolean;
  hierarchy: NodeLevel[];                  // 树渲染层级
  editable: boolean;                       // 表格编辑可用
  pagination: 'offset' | 'cursor' | 'none';
  lazyCell?: boolean;                      // 支持 fetchCell 按需取大字段
  /** @since v0.1.5（M8-PG B6）：内部/测试驱动——不暴露给连接表单的数据库类型选择
   *  （如 mock 契约基准驱动）；驱动仍可注册（历史连接可打开），仅 UI 入口隐藏 */
  internal?: boolean;
}

// ───────────────────────── 驱动入口 ─────────────────────────
interface IDatabaseDriver {
  readonly id: string;                     // 'mysql'，全局唯一
  readonly displayName: string;            // 'MySQL'
  readonly icon?: string;                  // codicon id 或扩展内 icon path
  readonly apiVersion: number;             // 当前 = 1
  readonly capabilities: DriverCapabilities;

  /** 连接表单 schema，见 §3.1 */
  getConnectionFormSchema(): FormSchema;

  /** 测试连通性。禁止缓存连接；失败抛 DriverError */
  testConnection(cfg: ConnectionConfig, secret: string): Promise<TestResult>;

  /** @since v0.1.4（M8-PG B5，可选）：连接表单「默认库」动态建议数据源
   *  （FormSchema 字段 dynamicOptions='databases' 时被调用）。自建临时连接（testConnection 同源，
   *  不复用池、不落盘），建连库自行兜底（PG 引导链 postgres→用户名→template1）；
   *  失败/不可达一律 resolve 空数组、禁止 reject——UI 无感降级为自由手输 */
  listDatabaseOptions?(cfg: ConnectionConfig, secret: string): Promise<string[]>;

  /** 建立连接（内部含连接池初始化）。secret = SecretStorage 取回的密码明文 */
  connect(cfg: ConnectionConfig, secret: string): Promise<IConnection>;
}

interface TestResult {
  ok: boolean;
  latencyMs?: number;
  serverVersion?: string;   // 如 '8.0.36'，树节点 tooltip 展示
  error?: DriverError;
}

// ───────────────────────── 连接句柄 ─────────────────────────
interface IConnection extends Disposable {
  readonly connectionId: string;

  /** 失败抛 E_CONN。用于空闲保活与健康检测 */
  ping(): Promise<void>;

  listDatabases(): Promise<DatabaseMeta[]>;
  listObjects(db: string): Promise<ObjectMeta[]>;
  listColumns(db: string, obj: string): Promise<ColumnMeta[]>;

  /** 以下为可选能力，声明在 capabilities.hierarchy 中才需实现 */
  listIndexes?(db: string, obj: string): Promise<IndexMeta[]>;
  listKeys?(db: string, obj: string): Promise<KeyMeta[]>;

  /** 分页取数（表格视图主路径） */
  fetchRows(req: FetchRowsRequest): Promise<ResultSet>;

  /** 执行查询/命令（SQL Console 主路径） */
  query(req: QueryRequest): Promise<ResultSet[]>;

  /** 变更预览：与 applyChanges 同源生成语句，保证“预览即执行” */
  previewChanges(db: string, obj: string, cs: ChangeSet): Promise<PreviewItem[]>;

  /** 变更提交：驱动内部保证事务性（§8） */
  applyChanges(db: string, obj: string, cs: ChangeSet): Promise<ApplyResult>;

  /** 大字段按需拉取（capabilities.lazyCell = true 时实现） */
  fetchCell?(db: string, obj: string, rowKey: RowKey, column: string): Promise<string>;

  /** DDL 生成（capabilities.supportsDdl = true 时实现，如 MySQL SHOW CREATE TABLE） */
  getDdl?(db: string, obj: string): Promise<string>;

  /** @since v0.1.2（M8-B2，capabilities.supportsDdlEditor = true 时实现）
   *  生成建表语句序列（概要 §5.9）。语句为方言原文（DDL 不可参数化，转义纪律见 §10）；
   *  可能丢数据的语句（删列/改类型等）必须标 destructive=true，供 UI 确认分级 */
  buildCreateTable?(db: string, spec: TableSpec): Promise<DdlStatement[]>;

  /** @since v0.1.2（M8-B2，capabilities.supportsDdlEditor = true 时实现）
   *  生成变更语句序列：驱动自行 diff `spec`（目标结构）与 `current`（库内当前结构，Host 实时派生）。
   *  `obj` 为目标表现名（重命名时为旧名）；无结构差异时返回空数组（UI 提示「无变更」） */
  buildAlterTable?(db: string, obj: string, spec: TableSpec, current: TableSpec): Promise<DdlStatement[]>;

  /** @since v0.1.15（表设计器批次 A，交互稿 §12.3）：列 Tab 类型建议词表——方言各自维护（C-14 同源，
   *  禁止跨驱动复用），纯静态数据不需建连；未实现 = 编辑器类型框无感降级为纯手输（建议不是白名单） */
  listDataTypes?(): DataTypeOption[];

  /** @since v0.1.11（M8-DBDDL / D-19，capabilities.supportsDatabaseDdl = true 时按需实现）
   *  库级 DDL 三方法：语句为方言原文（destructive 标记、标识符 fail-closed E_VALIDATION，同 buildCreateTable 口径）。
   *  各驱动只实现有意义的操作，菜单按方法存在性裁剪：MySQL 全三（charset/collation）；
   *  PG 建/删 schema（D-15「库」即 schema——DROP SCHEMA CASCADE 必须标 destructive）；Mongo 建/删库
   *  （修订：建库 = DatabaseSpec.collection 首个 collection 隐式创建，dropDatabase 删库） */
  buildCreateDatabase?(spec: DatabaseSpec): Promise<DdlStatement[]>;
  /** diff `spec` 与 `current`（listDatabases 命中项）：无差异返回空数组 */
  buildAlterDatabase?(db: string, spec: DatabaseSpec, current: DatabaseMeta): Promise<DdlStatement[]>;
  buildDropDatabase?(db: string): Promise<DdlStatement[]>;
  /** 建库/编辑库表单（形状同 §3.1 FormSchema；编辑时 Host 以 DatabaseMeta 预填 name/charset/collation）。
   *  未实现时 Host 回落最小字段集（name 必填） */
  getDatabaseFormSchema?(): FormSchema;

  /** 交互式事务会话（capabilities.supportsInteractiveTransaction = true 时实现） */
  openSession?(): Promise<ISession>;

  /** 补全数据源（表名/列/函数/关键字），core 负责缓存与上下文过滤。
   *  @since v0.1.6 方言词表硬性要求见 §3.2（keywords/functions/snippets 全量、completion.ts 纯数据） */
  getCompletionSource(db?: string): Promise<CompletionSource>;

  /** 标识符引用，如 name => \`name\`；未实现时 core 用 dialect.quote 兜底 */
  quoteIdentifier?(name: string): string;

  readonly dialect?: DialectInfo;
}

interface ISession extends Disposable {
  execute(req: QueryRequest): Promise<ResultSet[]>;
  commit(): Promise<void>;
  rollback(): Promise<void>;
}

interface DialectInfo {
  id: string;                 // 'mysql' | 'postgresql' | ...
  quote: [string, string];    // ['`','`'] / ['"','"']
  formatter: string;          // sql-formatter dialect 名
  keywords: string[];
  functions?: string[];
}

interface CompletionSource {
  keywords: string[];
  functions: string[];
  databases: string[];
  tables: Array<{ name: string; comment?: string }>;
  columns: Array<{ table: string; name: string; comment?: string }>;
  snippets?: Array<{ label: string; body: string; description?: string }>;
}

// ───────────────────────── 表结构编辑（@since v0.1.2，概要 §5.9）─────────────────────────

/** 列定义（编辑器输入模型；与 ColumnMeta 的关系：同为结构投影，但 dataType 为用户输入的
 *  方言类型原文，不含 normalizedType——规范化由驱动在建表后经 listColumns 返回） */
interface ColumnSpec {
  name: string;
  dataType: string;           // 方言类型原文（含长度/精度，如 varchar(64) / numeric(10,2)）
  nullable: boolean;
  isPrimaryKey: boolean;
  autoIncrement?: boolean;
  /** 值原文（如 `0`、`active`、`CURRENT_TIMESTAMP`，**不含引号**——字符串由驱动加引号转义）；
   *  undefined/'' = 无默认值。roundtrip 对齐 information_schema 的 COLUMN_DEFAULT（去引号） */
  defaultValue?: string;
  comment?: string;
  ordinal: number;            // 1-based，编辑器行序
}

interface TableSpec {
```

### 3.2 方言补全词表（@since v0.1.6）

**背景**：SQL 方言差异是本质性的（UPSERT 语法 `ON DUPLICATE KEY UPDATE` vs `ON CONFLICT DO …`、标识符引用反引号 vs 双引号、`ILIKE`/`RETURNING` 等关键字互不通用、函数集各异；键值数据源无 SQL 而走命令域）。补全词表**必须按驱动各持一份**，禁止跨驱动复用或假设"一份通用 SQL 词表"。

**要求（新驱动接入硬性项，AGENTS C-14；现有 mysql/pg 见各驱动 `src/completion.ts` 纯数据模块）**：

1. **词表文件**：SQL 数据源驱动在 `src/completion.ts` 导出三份纯数据——`KEYWORDS`（关键字 + 常用数据类型 + 方言特有语法形状，覆盖该方言主版本的常用面，如 MySQL 8 窗口函数/CTE、PG 的 ON CONFLICT/RETURNING）、`FUNCTIONS`（方言内置函数：聚合/窗口/字符串/日期/JSON 等）、`COMPLETION_SNIPPETS`（方言惯用模板优先：UPSERT、方言特有写法；通用 SELECT/JOIN/分页模板由 core `GENERIC_SNIPPETS` 提供，勿重复）。
2. **下发**：`getCompletionSource` 必须将三份词表注入 `CompletionSource`（keywords/functions/snippets）；词表散落 `index.ts` 内联属于违规（AGENTS 补全锚点）。
3. **键值数据源**（`supportsSQL = false`）：补全走命令域，`getCompletionSource` 的 keywords/functions 填**命令/子命令全量词表**（先例 driver-redis；MongoDB 的 mongosh 命令域同构——keywords = shell 方法与帮助命令、functions = 聚合阶段/cursor 方法，词表在 driver-mongo `src/completion.ts`），同样要求全量。
4. **DialectInfo**（quote/formatter/keywords）如实填写，与词表同源。
5. **验收**：驱动单测断言词表非空且规模达标（关键字 > 50、函数 > 20 量级）；连接实测补全命中方言特有关键字（如该方言的 UPSERT 形状）。

## 4. 请求/响应对象

```ts
type RowKey = Record<string, unknown>;   // 主键列 → 值

  | 'in' | 'notIn'

  values?: unknown[];   // in / notIn / between

interface FetchRowsRequest {
  db: string;
  obj: string;
  schema?: string;
  columns?: string[];                 // 缺省 = 全部列
  filters?: FilterCondition[];        // 多条件 AND 语义；OR 为 P2
  sorts?: Array<{ column: string; dir: 'asc' | 'desc' }>;
  search?: string;                    // 全局关键字，驱动决定实现（LIKE / 全文），必须转义

                                      // 属用户自撰 SQL 而非数据值，不做转义/参数化（§10 例外）
  orderBySql?: string;                // 用户手写 ORDER BY 片段（≤500 字符）：追加在 sorts 之后；

  maxRows: number;                    // 截断保护；超出置 ResultSet.truncated
  timeoutMs: number;
  signal?: AbortSignal;
}

interface ResultSet {
  columns: Array<{ name: string; type: NormalizedType }>;
  rows: unknown[][];                  // 行式存储；值遵循 §5 值编码契约
  rowCount: number;
  totalCount?: number;                // 可缺省，避免全表 COUNT
  primaryKey?: string[];              // 行可编辑时必须给出

  affectedRows?: number;              // 非 SELECT 语句
  messages?: string[];                // 警告（如 MySQL Notes）

}

  rowKey?: RowKey;                    // update/delete
  sql: string;                        // 参数化语句（占位符形式）
  params?: unknown[];                 // 语句含 ? 占位符时必须按序携带（契约强制）：
                                      // Webview 预览回填实际值依赖此字段，缺失则预览只剩 ?
```

**通用规则**
- 多语句：`supportsMultiStatement = true` 时，`QueryRequest.sql` 可能含多条语句，驱动必须返回**等数量**的 `ResultSet[]`（非 SELECT 语句返回 `columns: []` + `affectedRows`）；为 false 时 core 先切分再逐条调用
- 标识符：所有生成语句中的标识符必须经 `quoteIdentifier` 引用，防关键字/特殊字符
- 大小写折叠：未加引号的标识符按方言规则折叠（PG 折小写、MySQL 视系统变量），保证 `listColumns` 返回名与用户输入可互相匹配
- `db` 参数语义按驱动定义：多数 SQL 驱动为数据库名；**PG 驱动 = schema 名**（D-15——PG 连接协议绑定单库，树 database 层即 schema，连接与对象引用口径见 §5.2）；**SQL Server 驱动 = schema 名**（D-21，D-15 同构——连接绑定单库（Initial Catalog），树 database 层 = 当前库内非系统 schema，见 §5.6）；**SQLite 驱动 = 恒为 `main`**（D-16——单文件单库，`listDatabases()` 返回单节点，见 §5.4）；**MongoDB 驱动 = database 名，`obj` = collection 名**（D-17，`schema` 参数恒缺省，见 §5.5）
- `listDatabases()` 必须硬过滤系统库/系统 schema（@since v0.1.12）：MySQL 排除 `information_schema` / `mysql` / `performance_schema` / `sys`（对齐 D-15 在 PG 上的非系统 schema 口径）——树上展示与契约套件的样例发现（firstTable 按库序取样）同一口径；此前 MySQL 未过滤已修（发布准备批次）
- `FetchRowsRequest.filters` 与 `sorts` 必须在 SQL 层下推（WHERE / ORDER BY），禁止取全表后内存过滤

## 5. 值编码契约与类型映射

**核心规则**（与《概要设计》4.4 一致，违反即契约测试失败）：

| 场景 | JS 运行时值 |
|---|---|
| NULL | `null`（与 `''` 严格区分） |
| 整数（|v| ≤ 2^53） | `number` |
| 整数超限 / DECIMAL / NUMERIC | `string`（原样保留精度） |
| 浮点 | `number` |
| 布尔 | `boolean` |
| DATE | `'YYYY-MM-DD'` |
| TIME | `'HH:mm:ss.SSS'`（越界值如 MySQL `-838:59:59` 按原样字符串传输，列 type 记 `string`） |
| DATETIME / TIMESTAMP | `'YYYY-MM-DD HH:mm:ss.SSS'`（**按连接会话时区**，不带偏移量） |
| JSON | 已解析的对象/数组 |
| 二进制 | base64 字符串（列 type 标记 `binary`） |
| UUID | `string`（type 标记 `uuid`） |

编辑回传时驱动收到的同样是上述编码（如 `'2024-01-01 00:00:00'`），驱动负责转为原生参数——**必须走参数化绑定，不得拼接 SQL**。驱动侧转换注记（@since v0.1.13，契约 CI 实跑暴露，P-53）：**MySQL 的 JSON 列写参数必须 JSON.stringify**——mysql2（sqlstring）会把 JS 对象/数组参数 `.toString()` 成 `[object Object]` 再发服务器（JSON 列报 `ER_INVALID_JSON_TEXT`），`changes.ts` 在参数构建边界统一收口（对象/数组 → JSON 文本，Buffer 透传）；**PG 无此问题**（pg 原生对对象参数 JSON.stringify），但其 binary 列需 base64→Buffer 钩子（applyChanges 传 `encodeParam`，preview 不传保持 §5 编码回填）、数组列依赖 pg 原生数组序列化。

### 5.1 MySQL 类型映射

| MySQL 类型 | NormalizedType | 说明 |
|---|---|---|
| TINYINT/SMALLINT/INT/BIGINT（≤2^53） | `integer` | BIGINT UNSIGNED 超限 → `decimal`(string) |
| DECIMAL / NUMERIC | `decimal` | string 保精度 |
| FLOAT / DOUBLE | `float` | |
| BOOLEAN | `boolean` | `TINYINT(1)` 默认按 `integer`，驱动如做特殊处理必须在 README 声明 |
| CHAR / VARCHAR / TEXT / ENUM / SET | `string` | ENUM/SET 返回原始字符串 |
| DATE / TIME / DATETIME / TIMESTAMP | `date` / `time` / `datetime` | mysql2 需配置 `dateStrings: true` 或显式格式化，防时区漂移 |
| JSON | `json` | |
| BINARY / VARBINARY / BLOB | `binary` | base64 |
| GEOMETRY | `binary` | WKB 的 base64 |
| 其它 | `unknown` | 展示原样字符串 |

### 5.2 PostgreSQL 类型映射（要点）

| PG 类型 | NormalizedType |
|---|---|
| smallint / integer / bigint | `integer`（int8 值超 2^53 → `decimal` 字符串） |
| numeric | `decimal` |
| real / double precision | `float` |
| boolean | `boolean` |
| text / varchar / char / enum | `string` |
| date / time / timestamp / timestamptz | `date` / `time` / `datetime`（timestamptz 按会话时区渲染，tooltip 标注偏移） |
| json / jsonb | `json` |
| uuid | `uuid` |
| bytea | `binary` |
| 数组类型 | `json`（pg 数组 → JSON 数组） |

**解析与编码口径（M8-PG 定稿）**
- int8（bigint）pg 默认返回字符串：`|v| ≤ 2^53` 转回 `number`（integer），超限保留字符串（decimal）——不丢精度；numeric 同理恒为字符串
- timestamp / timestamptz：驱动覆写 pg 类型解析器取服务端原文，禁用 JS Date 转换（防时区漂移，同 mysql2 `dateStrings` 口径）——`timestamp`（无时区）规范化为 `'YYYY-MM-DD HH:mm:ss.SSS'`；`timestamptz` 剥去尾部偏移量、保留服务端会话时区的墙上时间（概要 §4.4）；DATE / TIME 同理取原文规范化
- bytea：Buffer → base64（列 type `binary`）；json / jsonb：pg 默认已解析对象（列 type `json`）；数组类型：pg 默认解析为 JS 数组，按 JSON 数组传输（列 type `json`）；enum / domain 按基类型归一，默认 `string`

**连接与 db 语义（D-15，M8-PG 定稿）**
- PG 连接协议绑定单一数据库（无 USE 类跨库切换）：FormSchema `database` 字段 = 连接字符串的**真库名**（hint 消歧：树上「库」为 schema）；连接节点 tooltip 展示真实库名
- `listDatabases()` 返回当前库内**非系统 schema**（排除 `pg_*` 前缀与 `information_schema`），树 database 层即 schema；`IConnection` 全部方法的 `db` 参数 = **schema 名**，`obj` 恒为裸表/视图名（无全限定名，含点标识符 `"a.b"` 天然安全）
- 对象引用一律显式 `"schema"."table"` 限定，不依赖 search_path；`QueryRequest.db` ≠ 连接默认 schema 时，经池内专用连接 `SET search_path` 后执行、用毕 RESET（防池化连接状态残留，P-36 同族）——search_path 仅兜底用户手写的未限定语句

### 5.3 Redis 特化约定

- 非 SQL 数据源：`supportsSQL = false` 仅关闭 SQL 补全/格式化与危险 SQL 判定，仍提供命令控制台（复用 Console UI）；`query()` 只接受合法命令文本（如 `GET key`），`E_SYNTAX` 表达命令错误；危险命令判定由 core 用命令白名单执行
- Key 浏览用 `fetchRows`：`obj` 为 key 模式（如 `user:*`），底层**必须用 `SCAN`**（禁止 `KEYS`），pagination 固定 `cursor`
- Hash/List/Set/ZSet 值统一编码为 `json`（数组或对象）；二进制 value → `binary`
- 列元数据由驱动虚拟化（如 Hash → field/value 两列）；`primaryKey` 恒为 `['key']`
- TTL 作为虚拟列暴露（`__ttl`，`integer`，只读）

### 5.4 SQLite 特化约定（M8-SQLite，D-16）

**执行引擎（D-16）**：**sql.js（WASM）单引擎**——整库驻留内存，**限用中小库（建议 ≤ 100MB）**；同步执行：`supportsCancel = false`（同步不可中断）、`supportsMultiStatement = false`（Console 按 Host 切分单语句执行）。持久化 = **写批次后原子落盘**（序列化整库字节 → 临时文件 → rename 覆写；applyChanges 批次 / Console 写语句批次 / 交互式事务 commit 各为一个批次；只读连接与未提交会话不落盘）。`node:sqlite` 直接依赖与双引擎方案均否决（D-16「可行性结论」：基线 ^1.85 宿主缺失 + Node 22.x experimental 漂移）。

**类型映射**（按**声明类型**归一——SQLite 为动态类型，列类型即建表声明原文，值可为任意存储类）：

| 声明类型（含其字串） | NormalizedType | 说明 |
|---|---|---|
| INT / INTEGER / BIGINT / SMALLINT / TINYINT… | `integer` | 值经 BigInt 通道读出：\|v\| ≤ 2^53 → `number`，超限 → `decimal` 字符串（不丢精度） |
| REAL / FLOAT / DOUBLE | `float` | |
| NUMERIC / DECIMAL | `decimal` | SQLite 无独立 DECIMAL 存储：NUMERIC affinity 下整数按 INTEGER、小数按 REAL 存储，读回转字符串（C-7）；**超大 decimal 经 REAL 存储有精度损失（引擎本质），超高精度列应声明 TEXT** |
| TEXT / VARCHAR / CHAR / CLOB | `string` | |
| DATE / TIME / DATETIME / TIMESTAMP | `date` / `time` / `datetime` | SQLite 无日期类型：按声明类型归一，值即存储原文（通常 TEXT），**不做格式规范化、无时区语义**（C-7 的 DATETIME 格式由写入方保证） |
| BOOLEAN / BOOL | `boolean` | 惯例 0/1 存储：写 `boolean`→1/0，读 1→`true`、0→`false`，其余值透传 |
| JSON / JSONB | `json` | 存 TEXT：写对象/数组 JSON.stringify，读 JSON.parse（解析失败回落原文字符串） |
| BLOB | `binary` | base64；编辑回传 base64 → Uint8Array 绑定（applyChanges 侧，预览 params 保持 base64——P-22/P-45 同族） |
| 其它（含无类型声明列） | `unknown` | 值按存储类判定：BLOB 存储（Uint8Array）恒编码 base64 |

**连接与树语义**
- 单文件单库：`listDatabases()` 恒返回 `[{ name: 'main' }]`（SQLite 逻辑主库；`ATTACH` 附加库为后续扩展口）；`db` 参数恒为 `main`，`obj` 恒为裸表/视图名；对象自省走 `sqlite_master`（排除 `sqlite_%` 内部对象），行数估算**不执行 COUNT**（rowEstimate 缺省，C-9）
- FormSchema：`path`（string，必填，支持 `~/` 与相对工作区路径展开——展开由扩展侧注入的 resolver 完成）+ `readonly`（boolean，高级组：只读打开，写语句 → `E_READONLY`，且永不落盘）；**无认证字段，不涉 SecretStorage**（secret 恒为空串）
- 文件必须已存在，**不自动创建**（缺失 → `E_NOT_FOUND`）；打开前校验文件头魔数 `SQLite format 3\0`——非 SQLite 文件拒绝（`E_VALIDATION`），**防 SQLite「<100 字节文件当空库」语义误覆写用户文件**；0 字节文件视为合法新库
- 元数据自省用 `PRAGMA table_info / index_list / index_info / foreign_key_list`——PRAGMA 不可参数化，表名经 `quoteIdentifier`（双引号 + `""` 转义）拼入（内部自省值，非用户数据）

**语句与编码口径**
- 占位符：`?`（原生匿名参数）；previewChanges/applyChanges 同源，预览 params 与 `?` 等长携带（P-22）
- `RETURNING`（SQLite ≥ 3.35）：insert 主键回填用 `INSERT … RETURNING` 主键列（§8-3）；sql.js 1.14 内嵌 SQLite 3.49 满足
- 主键与自增：`INTEGER PRIMARY KEY`（rowid 别名单列主键）即自增——listColumns 对「INTEGER 声明 + 单列主键」标 `autoIncrement`；DDL 生成中 AUTOINCREMENT 仅允许 INTEGER 类型（SQLite 硬约束，其余声明类型归一为 INTEGER）
- 筛选下推 `LIKE`：保持方言原生大小写不敏感语义，通配符经 `ESCAPE '\'` 转义；`search` 关键字用 `instr(col, ?) > 0`（**大小写敏感子串**、无通配符语义——与契约内存基准 `includes` 严格一致，特殊字符零转义风险）
- DDL 编辑（`supportsDdlEditor = true`）：加列 `ADD COLUMN`；**其余结构变更（删列/改类型/改默认值/改主键）SQLite 不支持原地 ALTER，统一走表重建序列**：`PRAGMA foreign_keys=OFF` → `CREATE TABLE <t__dbx_rebuild>`（目标结构）→ `INSERT…SELECT` 回拷公共列 → `DROP TABLE` 旧表 → `RENAME` → `PRAGMA foreign_keys=ON`，整组标 `destructive`；**索引/触发器不随重建迁移**（驱动为纯函数层，无索引自省输入——已知限制，README 声明）

### 5.5 MongoDB 特化约定（M8-Mongo，D-17）

**能力与定位（D-17 / D-18）**：`supportsSQL = false`（mongosh 命令控制台）、`editable = true`（D-18 文档编辑，字段级 `$set` 乐观锁）、`supportsTransaction = false`（多文档事务需副本集，standalone 不支持——契约混合原子性两项检查按能力跳过）、`pagination = 'cursor'`、`hierarchy = ['connection','database','folder','collection','column']`（hierarchy 含 `column` 时树为 collection 节点展开「字段/索引」目录）。`db` 参数 = database 名、`obj` = collection 名、`schema` 参数恒缺省。

**连接语义**
- FormSchema 最小字段集：`host`/`port`（必填）、`username`/`password`（可选，type=password 入 SecretStorage）、`authDatabase`（默认 `admin`）、`database`（默认库，可选）；高级组 `directConnection`（默认 true——IP 直连目标的最稳口径，副本集自动发现可关闭）；URI 串 / `mongodb+srv` / TLS 留后续批次
- `listDatabases()` 过滤系统库（`admin`/`config`/`local`）；`listObjects()` 返回用户 collection（`kind='collection'`，`schema='Collections'` 分组，排除 `system.*`）
- 建连死线（P-30 同族）：`serverSelectionTimeoutMS` 兜底（默认 10s），不可达主机/端口 → `E_CONN`

**动态列（采样推断）**
- `listColumns` / `fetchRows` 的列集 = 采样顶层字段并集：`_id` 恒为首列（ordinal 1，RowKey/游标位点恒定），其余字段按采样首见序排列，**采样上限 200 篇**
- 字段缺失 = NULL 语义：单元格编码为 `null`；`isNull` 同时命中显式 `null` 与缺失字段（`{ f: null }` 的 Mongo 原生语义即两者命中，与内存基准一致）；全部采样命 null 的列 `normalizedType='unknown'`
- 同字段异型（schema-free）列类型取首个非 null 样本的类型，驱动不做多型合并（README 声明）

**BSON → NormalizedType 映射（值遵循 §5 编码契约）**

| BSON 类型 | NormalizedType | 编码形态 |
|---|---|---|
| ObjectId | `string`（dataType `objectId`） | 24 位 hex 字符串 |
| String | `string` | 原样 |
| Int32 / Int64（Long） | `integer` | `\|v\| ≤ 2^53` → `number`，超限 → `decimal` 字符串（不丢精度） |
| Double | `float` | number |
| Decimal128 | `decimal` | 字符串（保精度） |
| Boolean | `boolean` | 原样 |
| Date | `datetime` | `'YYYY-MM-DD HH:mm:ss.SSS'`（**UTC 墙上时间**，不带时区——BSON Date 即 epoch ms，无会话时区概念，§4.4 口径） |
| Timestamp（内部） | `unknown` | 字符串化 |
| Object / Array（嵌套文档/数组） | `json` | **已解析对象/数组**，内嵌 BSON 类型深度转换（嵌套 ObjectId→hex、Date→datetime 文本、Binary→base64、Long/Decimal128→string） |
| BinData（Binary） | `binary` | base64 |
| Null / Undefined | — | `null`（严格区分 `''`） |
| MinKey / MaxKey / Code / Symbol / RegExp | `unknown` | 字符串化 |

**筛选下推（FilterOp → 查询文档）**：值为「绑定」语义——只出现在查询文档的值位置（经采样列类型转回 BSON 原生值，如 datetime 文本 → `Date`、objectId hex → `ObjectId`），**禁止任何字符串拼接进查询结构**（P-9 同口径，单测断言）；未采样到的列按原样值匹配。

| FilterOp | Mongo 查询文档 | NULL 语义说明 |
|---|---|---|
| eq | `{ f: v }` | — |
| ne | `{ f: { $nin: [v, null] } }` | 缺失/NULL 行按 SQL 三值逻辑排除（`$nin` 含 null 时同时排除缺失字段） |
| gt / ge / lt / le | `{ f: { $gt/$gte/$lt/$lte: v } }` | 比较天然排除缺失/NULL |
| like | `{ f: { $regex: '^<转义子串>' } }` 环绕 `.*` | 子串语义（通配符 `%`/`_` 原样转义，与契约内存基准 `includes` 一致），大小写敏感 |
| notLike | `{ $nor: [{ f: { $regex: … } }] }` | 同上；NULL 行排除（SQL 三值） |
| in / notIn | `{ f: { $in: vs } }` / `{ f: { $nin: [...vs, null] } }` | notIn 的 NULL 行排除同 ne |
| isNull | `{ f: null }` | 命中显式 `null` 与缺失字段（文档模型口径） |
| isNotNull | `{ f: { $ne: null } }` | 同时排除显式 `null` 与缺失 |
| between | `{ f: { $gte: lo, $lte: hi } }` | — |
| search | `{ $or: [各 string 列 { c: { $regex: '^<转义>' } }] }` | 全局关键字子串，特殊字符零抛错（转义） |

**分页（cursor）**
- 游标 = opaque `base64url(BSON)`：`{ v: 1, id: <最后行 _id 原生值>, sk: <排序键数组>, sv: <排序值 BSON 元组> }`——解码经 `BSON.deserialize` 还原原生类型（P-27：游标自包含位点，非法游标 → `E_VALIDATION`）
- 无排序时默认 `{ _id: 1 }`（P-10）；用户排序存在时 `_id: 1` 作**末位追加**（不前置，v0.1.3 修订口径），带排序翻页按「排序值 + `_id`」复合 `$gt/$lt` 位点 resume（同值字段不跳行）；游标内记录排序键，翻页请求排序与游标不一致属未定义（Webview 改排序即重置游标）
- `offset` 兼容翻译：无游标时 `skip(offset)`（契约 offset 组实跑口径，同 Redis「SCAN 起始跳过」）；`whereSql`/`orderBySql` 片段不适用（`E_VALIDATION`，契约 supportsWhereSql=false 跳过）
- 尽头判定：取 `limit+1` 探测，未取尽返回 `nextCursor`；已取尽不返回（契约「已取尽时不应返回 nextCursor」）

**Console（mongosh 命令域）**
- `query()` 只接受单条命令文本（每行一条，Host 切分）；命令形状：`db.<coll>.<method>(args)`、`db.getCollection('<coll>').<method>(args)`、`db.runCommand({...})`、`show dbs|collections`；**游标链式调用（`.limit().sort()`）首批不支持**（`E_SYNTAX`，README 声明）
- **参数字面量解析（禁 eval）**：驱动自建受限解析器——对象/数组/字符串（`''`/`""`）/数字/布尔/null + 构造器包装 `ObjectId('hex')`/`ISODate('…')`/`NumberLong('n')`/`NumberDecimal('d')`/`BinData(s, base64)`；`function(…){…}` 源码按 BSON Code 透传（服务端执行，如 `$where`）；其余标识符/运算符 → `E_SYNTAX`
- **首批只读（D-17，B2 已放开文档写）**：命令白名单在 core（`services/mongoCommands.ts`，与 `redisCommands` 同构，editGuard/consoleService 按驱动 id 选白名单）——provablyRead：`find/findOne/aggregate（管道无 $out/$merge）/count/countDocuments/estimatedDocumentCount/distinct/getIndexes/getCollectionNames/stats/explain/show/runCommand（读命令子集）`；dangerous（横幅原因）：`drop/dropDatabase/deleteMany/deleteOne/updateMany/updateOne/replaceOne/insertOne/insertMany/bulkWrite/findOneAnd*/createCollection/renameCollection/createIndex/dropIndex/eval`；**文档写命令（insertOne/insertMany/updateOne/updateMany/replaceOne/deleteOne/deleteMany/findOneAnd*）经危险判定链后可执行（D-18）；结构类命令（drop/dropDatabase/createCollection/renameCollection/createIndex/dropIndex/eval/mapReduce/bulkWrite/adminCommand）恒 `E_UNSUPPORTED`**
- `use <db>` 由 Host 拦截改 Console 绑定不下发（P-36 同构，命令模式分支）；命令结果集编码同 fetchRows（find → 动态列表格，count → 单元格，文档型回复 → key/value 行）

**编辑与变更集（D-18，M8-Mongo B2）**
- 映射（preview/apply 同源生成）：
  - insert → `insertOne(values)`——`_id` 缺省由服务器生成，回填 24 位 hex 到 `items[].rowKey`（§8-3）；values 按 §5 编码形态传入、经采样列类型转回 BSON 原生值绑定
  - update → 字段级 `$set`：`updateOne({ _id: <RowKey>, <变更列>: 原值… }, { $set: { 字段: 新值… } })`——**乐观锁 = RowKey + 变更列原值**（D-03 同构，多字段变更以 AND 全部入 WHERE）；原值 null/缺失统一条件 `{ f: null }`（命中显式 null 与缺失，与读侧口径自洽）；`matchedCount ≠ 1` → `E_CONFLICT`
  - 清空（新值 = null）→ `$set { f: null }`（不引入 `$unset`，D-18）
  - delete → `deleteOne({ _id: <RowKey> })`
- `_id` 不可编辑（RowKey 锁定）；json 列（嵌套文档）整值替换（编辑回传 JSON 文本解析后 `$set`）；二进制 base64 → Binary、objectId hex → ObjectId、datetime 文本 → Date（`toBsonValue` 同源）
- 事务：`supportsTransaction = false`——逐条顺序执行、**失败即停**：首个错误抛出含 kind/tempId/rowKey 定位（§8-1），message 注明已应用项数（无事务「部分成功」如实口径 §8-5）；契约混合原子性两项检查按该能力跳过
- preview：`PreviewItem.sql` 为 **mongosh 伪语句**（如 `db.user.updateOne({ _id: ?, age: ? }, { $set: { age: ? } })`），`params` 与 `?` 等长携带（P-22——Webview 预览回填实际值；§5 编码形态）

### 5.6 SQL Server 特化约定（M8-MSSQL，D-21）

**能力与定位**：`mssql` ^11（tedious ^18 内核，纯 JS 无 native 硬依赖，D-05 口径）；`supportsSQL = true`、`editable = true`、`supportsTransaction = true`（mssql.Transaction 单连接短事务）、`supportsInteractiveTransaction = true`、`supportsCancel = true`（`request.cancel()` 发送 TDS ATTENTION，服务端取消当前 batch 后连接可复用）、`pagination = 'offset'`（OFFSET-FETCH）。已知限制（README 如实声明）：SSMS 风格 `GO` 批不支持（core 扫描器按 `;` 切分，`GO` 是客户端伪指令）；带启用触发器的表不支持 INSERT 回填（`OUTPUT` 子句的 T-SQL 约束）；IDENTITY 不可原地增删（结构编辑抛 `E_UNSUPPORTED`）；仅 SQL Server 登录认证（无 Windows 集成/Entra 认证）。

**连接与树语义（D-15 同构）**
- 连接绑定单一数据库：FormSchema `database` 字段 = Initial Catalog（缺省 `master`，`dynamicOptions='databases'` 经 master 列用户库）；`instanceName` 命名实例经 SQL Browser 解析（填写后端口忽略）；`ssl` 开关（Encrypt，默认不加密）+ `sslInsecure`（trustServerCertificate，hint 风险标注）
- 树 database 层 = 当前库内**非系统 schema**（`sys.schemas` 排除 `sys`/`information_schema`/`guest`/`db_*` 九个固定角色架构，`dbo` 保留）；全部接口的 `db` 参数 = **schema 名**，`obj` 恒为裸表/视图名，驱动生成语句显式 `[schema].[table]` 两段名限定（标识符方括号引用，`]` 翻倍转义）
- Console 用户手写**未限定名按登录默认 schema 解析**（SSMS 同款行为，文档声明）；跨库查询手写三段名 `[db].[schema].[table]`；`USE` 语句被 Host 层 P-36 拦截改绑定不下发（池化下 USE 只改写单个物理连接）——驱动 README 明确禁用

**类型映射（值遵循 §5 编码契约）**

| SQL Server 类型 | NormalizedType | 编码形态 |
|---|---|---|
| tinyint / smallint / int / bigint | `integer` | bigint ≤ 2^53 → number，超限 → decimal 字符串（tedious 恒返回字符串，读侧安全转数值） |
| decimal / numeric / money / smallmoney | `decimal` | 字符串（保精度） |
| float / real | `float` | number |
| bit | `boolean` | tedious 原生 boolean |
| char / varchar / nchar / nvarchar / text / ntext / xml | `string` | XML 按文本 |
| date | `date` | `'YYYY-MM-DD'`（tedious `useUTC` 下按 UTC 组件读出还原服务端墙上时间） |
| time(n) | `time` | `'HH:mm:ss.SSS'` |
| datetime / smalldatetime / datetime2 / datetimeoffset | `datetime` | `'YYYY-MM-DD HH:mm:ss.SSS'`（不带时区；datetimeoffset 按 UTC 渲染，偏移量丢失） |
| uniqueidentifier | `uuid` | 字符串 |
| binary / varbinary / image / rowversion | `binary` | base64 |
| sql_variant / geography / geometry / hierarchyid | `unknown` | 原样文本展示 |

**参数绑定（编辑回传最后一跳）**：日期时间文本经 **tedious 原生类型显式绑定**（`TypedDateParam` → `mssql.TYPES.DateTime2/Date/Time`，UTC 组件解析与读侧对称）——字符串直传 NVarChar 触发受会话 DATEFORMAT 影响的非确定性隐式转换（ISO 8601 带 `T` 才有确定性保证，不依赖）；binary base64 → Buffer（VarBinary）；对象/数组 → `JSON.stringify`（P-53 同族收口，SQL Server 无原生 JSON 类型、nvarchar 文本承载）；其余（decimal 字符串、bigint 字符串）按 NVarChar 隐式转换（数值文本解析无方言歧义）。preview 不传转换钩子（§5 编码回填，P-22）。

**分页与筛选下推**：OFFSET `n` ROWS FETCH NEXT `m` ROWS ONLY（T-SQL 无 LIMIT；FETCH 必须带 OFFSET，缺省补 `OFFSET 0`；二者必须存在 ORDER BY，无排序时补 `ORDER BY (SELECT NULL)`）；占位符 `@pN` 命名参数；LIKE 带 `ESCAPE '\'`（T-SQL LIKE 默认无转义符）；主键升序兜底排序（P-10，追加口径）。

**变更集（§8）**：短事务（mssql.Transaction）+ 字段级乐观锁（WHERE = RowKey + 变更列原值，NULL 原值 `IS NULL`）；INSERT 携带 `OUTPUT INSERTED.<主键列>` 回填（§8-3，PG RETURNING 同构；触发器表限制见上）；`rowsAffected ≠ 1` → `E_CONFLICT` 回滚。

**元数据自省与 DDL**：自省走 `sys.` 目录视图（schemas/objects/columns/indexes/key_constraints/foreign_keys/default_constraints/extended_properties + sys.partitions 行估算——元数据统计非全表 COUNT，C-9）；`dataType` 原文由 sys.types + max_length（nvarchar 半宽）/precision/scale 组装（nvarchar(64)、decimal(12, 2)、nvarchar(max)）；默认值经 `sys.default_constraints.definition` 去括号/去 N 引号 roundtrip（P-49 同款口径）；注释 = MS_Description 扩展属性（`sp_addextendedproperty`/`sp_updateextendedproperty`）；表结构编辑的约束名（`PK__…`/`DF__…` 服务端随机后缀）由连接层先查目录视图再传入纯函数生成层；库级 DDL = `CREATE SCHEMA` / `DROP SCHEMA`（destructive；T-SQL 无 CASCADE，非空 schema 由服务端拒绝）；建表自增 = `IDENTITY(1,1)`。

### 5.7 Oracle 特化约定（M8-Oracle，D-23）

**能力与定位**：`oracledb`（node-oracledb）^7 **thin 模式**（默认，纯 JS 无 native 硬依赖，D-05 口径；要求数据库 12.1+）；npm 包内捆绑的 thick 预编译二进制**永不触达**（不调 `initOracleClient()`）——esbuild 标 `oracledb` external + 构建期闭包物化（P-32/P-35 同族，`build/` 二进制目录不物化）。已知限制（README 如实声明）：空串即 NULL（引擎语义，见下）；Console 路径 >2^53 NUMBER 经 JS number 精度失真；`TIMESTAMP WITH TIME ZONE` 渲染丢失原始偏移；DATE/TIMESTAMP 按客户端进程本地时区解释；IDENTITY 不可原地增删（结构编辑抛 `E_UNSUPPORTED`）；Oracle 禁止同形外键重复（同列引用同目标的约束全库唯一，ORA-02275）；TCPS/SSL 暂不支持；仅 SQL Server 登录认证口径同款：仅用户名/密码 + SYSDBA 角色（无 Windows 域/代理认证）。

**连接与树语义（D-15/D-21 同构）**
- 连接绑定单个 PDB：FormSchema `serviceName` 字段 = service name 或 SID（EZConnect `host:port/name` 两种寻址均可命中）；驱动组装完整描述符（携带 `CONNECT_TIMEOUT`/`RETRY_COUNT` 死线，P-30 同族）——**host/serviceName 经字符集校验 fail-closed**（描述符参数可经括号注入，非 SQL 注入面）；高级组 `connectString` 完整描述符覆盖 + `sysdba` 布尔（`privilege: SYSDBA`）
- 树 database 层 = 当前 PDB 内**非系统 schema**：`ALL_USERS` 排除 `ORACLE_MAINTAINED='Y'`（12.2+），**当前用户排首位**（`ORDER BY CASE WHEN username = USER …`——业务默认 schema 先见，契约组 `dbs[0]` 取样同口径）；`PDBADMIN` 视同业务 schema 保留（mssql `dbo` 同口径）；全部接口的 `db` 参数 = **schema 名**，`obj` 恒为裸表/视图名，对象引用显式 `"schema"."table"` 两段名限定（双引号 + `""` 翻倍转义）
- **不实现 `listDatabaseOptions`**：树上「库」（schema）与连接寻址（service/PDB）不是同一层——`serviceName` 无动态建议（自由手输 + placeholder 示例）
- `USE` 语句不存在于 Oracle 方言（连接即绑定 PDB，P-36 拦截分支天然不触达）；Console 未限定名按连接用户默认 schema 解析

**取回与值编码（thin 语义，实测口径）**
- **fetchRows 执行级 `fetchInfo` 按列整形**：NUMBER → STRING（保精度，`|v| ≤ 2^53` 且 scale=0 整形回 number）、CLOB/NCLOB → STRING、BLOB → BUFFER——连接级 `fetchAsString`/`fetchTypeHandler` 在 thin 模式**被静默忽略**（实测），全局 `oracledb.fetchAsString` 有效但进程级污染（P-44 精神，否决）；`fetchInfo` 键 = Oracle 返回列名（未引号列大写）
- **query（Console）路径**：列集执行前未知，NUMBER 按 JS number 展示（>2^53 失真，README 声明）；CLOB/BLOB 为 Lob 流对象 → `getData()` 消化
- DATE/TIMESTAMP → JS Date 按**客户端进程本地时区**解释（实测 `ALTER SESSION SET TIME_ZONE` 不影响该转换）——读侧按 Date 本地组件格式化 `'YYYY-MM-DD HH:mm:ss.SSS'`、写侧按本地组件解析回 Date，两侧对称即往返稳定；编辑回传一律参数化绑定（Date 原生绑定）
- **空串即 NULL（引擎本质）**：`''` 存入即 NULL、永远读不回——编辑输入空串落 NULL（UI 提示，不阻断）；契约值编码组 `c_empty` 用例 `read: null` 特化断言（套件 `'read' in c` 判定，`??` 会吞 null 预期）；乐观锁原值 '' ≡ NULL → `IS NULL`，D-03 无特化分支
- NUMBER 家族：`NUMBER(p,0)` → integer（值安全整形）、`NUMBER(p,s)`/裸 `NUMBER` → decimal 字符串、`FLOAT(p)`/`BINARY_DOUBLE`/`BINARY_FLOAT` → float；RAW/BLOB → binary base64；ROWID/UROWID → string；XMLType/对象/集合/INTERVAL → unknown 尽力展示

**变更集与分页**：占位符 `:N` 位置绑定（preview params 只含输入绑定，执行时连接层尾部追加 `RETURNING … INTO` 的 out 绑定对象）；短事务 = 池 checkout 单连接承载批次（BEGIN 隐式于首条 DML，COMMIT/ROLLBACK 显式，归还前终结——release 未提交即回滚）；INSERT 回填 = `RETURNING <主键列> INTO :k+n`（out 绑定 STRING 取回后按列类型整形）；IDENTITY 列（`all_tab_identity_cols`）自增标记，契约混入 insert 跳过自增列（通用口径）。分页 = `OFFSET/FETCH`（12c+，无 ROWNUM legacy 分支）；取消 = **`connection.break()`**（OOB 带外中断，ORA-01013 → E_CANCELED，连接可复用后归还）——在途查询独占借出连接，abort 信号定向 `break()`。**连接池自锁红线**：禁止在 `withConnection` 回调内嵌套调用其他借连接的驱动方法（ER 并发收集下 hold-and-wait 自锁，queueTimeout 60s 满即 NJS-040，实跑踩——`listKeys` 内的 `listColumns` 必须先行于连接租借）。

**元数据自省与 DDL**：`all_tables`/`all_views`（对象 + `num_rows` 行估算——**无优化器统计时为 NULL**，rowEstimate 缺省不 COUNT，C-9）、`all_tab_columns`（列——data_precision/data_scale/char_length/char_used 组装 `NUMBER(12, 2)`/`VARCHAR2(64 CHAR)` 原文；`data_default` 为 LONG 型，字符串默认值带引号 → 去引号 roundtrip，P-49 同族）、`all_constraints`+`all_cons_columns`（PK/UK/FK——**两段查询**：先本表约束列，再逐外键经 `r_constraint_name` 回链引用侧；三表合流 LEFT JOIN 在字典统计缺失的实例上单表秒级，实测拖垮 ER 收集）、`all_indexes`+`all_ind_columns`（**仅独立二级索引**——约束-backed 索引经 `all_constraints.index_name` 反查排除，函数基/LOB/DOMAIN 排除）、`all_tab_identity_cols`（自增）、`all_tab_comments`/`all_col_comments`（注释）。DDL 查看 = `DBMS_METADATA.GET_DDL`（transform 减噪：SEGMENT_ATTRIBUTES/STORAGE/TABLESPACE=FALSE——**会话级状态在独占借出的连接上设置后同连接取用**，P-36 同族；自有对象免角色，跨 schema 需 `SELECT_CATALOG_ROLE`）。表结构编辑 = 生成器自研：**DEFAULT 必须先于 NOT NULL**（Oracle 语法序，颠倒 ORA-00907）；类型翻译层（契约/编辑器通用类型 bigint/int/varchar(n)… → NUMBER/VARCHAR2 natives，词表外透传）；类型比较大小写折叠（存储形态恒大写，防假 ALTER）；注释 = `COMMENT ON`（删除语义 `IS NULL`）；UNIQUE 删除走 `DROP CONSTRAINT`（名来自基线）、主键 `DROP PRIMARY KEY`（无需名）；**库级 DDL = `CREATE USER`（密码必需，`DatabaseSpec.password` @since——预览/日志掩码）与 `DROP USER … CASCADE`（destructive）；无 ALTER（用户不可重命名）**；新建 schema 需 `CREATE USER`/`DROP USER` 及被授予权限的 `WITH ADMIN OPTION`。

## 6. 错误码规范

驱动抛出的所有错误必须是 `DriverError`：

```ts

  readonly code: DriverErrorCode;   // UI 依据此码路由文案/动作
  readonly detail?: string;         // 原始错误摘要（已脱敏，§10）
  readonly retryable: boolean;
  constructor(code: DriverErrorCode, message: string, opts?: { detail?: string; cause?: unknown });
}

type DriverErrorCode =
  | 'E_CONN'        // 建连失败/连接中断（网络、拒绝、握手）
  | 'E_AUTH'        // 认证失败
  | 'E_TIMEOUT'     // 操作超时（含锁等待超时）
  | 'E_CANCELED'    // 用户取消（AbortSignal）
  | 'E_READONLY'    // 只读连接拒绝写
  | 'E_CONFLICT'    // 乐观并发冲突（affectedRows=0/≠1）或序列化冲突
  | 'E_CONSTRAINT'  // 约束冲突（唯一键/外键/非空/CHECK）
  | 'E_SYNTAX'      // 语句/命令语法错误
  | 'E_PERMISSION'  // 权限不足
  | 'E_NOT_FOUND'   // 库/表/键不存在
  | 'E_VALIDATION'  // 请求参数非法
  | 'E_UNSUPPORTED' // 能力不支持（如对不支持的语句/类型）
  | 'E_CAPACITY'    // 结果/负载超限被拒绝
```

## 7. 取消、超时与连接池

- **AbortSignal**：core 对所有请求恒传 `signal`。驱动必须在以下检查点响应：SQL 下发前、逐批读取结果时（每批 ≤100 行检查一次）、元数据分页循环中。响应后抛 `DriverError('E_CANCELED')`。`supportsCancel` 声明为 true 而实际不响应 → 契约测试失败
- **超时**：以 `timeoutMs` 为准（语句级 timeout / `maxExecutionTime` / 等效机制），超时抛 `E_TIMEOUT` 并尽力取消服务端执行
- **连接池**：驱动内部自建池（mysql2 `createPool` / pg `Pool`），建议参数：min 0、max 4、idle 30s；`testConnection` 不复用池
- **保活**：`ping()` 实现为轻量探活（`SELECT 1` / Redis `PING`），core 每 60s 调用一次
- **dispose()**：必须幂等；结束所有池连接、清理事件监听；dispose 后再调用任何方法应抛 `E_CONN`（detail 注明已关闭）

## 8. 事务与变更集要求

`applyChanges(db, obj, cs)` 的强制语义：

1. `supportsTransaction = true` 时，整个 ChangeSet 包在**单个事务**内：任一语句失败 → 全量 ROLLBACK 并抛出首个错误（含定位信息：kind/tempId/rowKey），不得半提交
2. UPDATE 的 WHERE = RowKey（主键值）+ **变更列**的 original 原值（字段级乐观锁，D-03 评审确认）；DELETE 的 WHERE = RowKey；**原值为 NULL 的列必须生成 `IS NULL`**（`col = NULL` 永不匹配，会使乐观锁失效）；`affectedRows ≠ 1` → 抛 `E_CONFLICT` 并回滚
3. INSERT 必须回填生成主键（`RETURNING` / `LAST_INSERT_ID`）到 `items[].rowKey`
4. 无主键表：core 会在 `allowNoPrimaryKey` 开启时传入全列匹配的 ChangeSet，驱动照常执行；未开启时 core 不会下发（驱动无需处理，但收到无 `rowKey` 且无 `original` 的变更应抛 `E_VALIDATION` 兜底）
5. `supportsTransaction = false` 的数据源（如部分 Redis 场景、MongoDB——多文档事务需副本集，D-18）：驱动必须实现**逐条顺序执行 + 失败即停**，并在 `ApplyResult.items` 如实汇报已执行项，由 core 提示用户“部分成功”；首个失败错误必须含 kind/tempId/rowKey 定位，message 注明已应用项数
6. `previewChanges` 与 `applyChanges` 必须共享同一套语句生成代码（同一函数的两个入口），禁止两套逻辑

## 9. 注册与加载机制（L1/L2/L3）

三种方式最终都经 `DriverRegistry.register()` 注册：除 §2 的 apiVersion 校验外，**driverId 必须全局唯一**——冲突时拒绝后注册者，UI 提示来源（内置 / 扩展 ID + 版本）。

### 9.1 L1 内置驱动
monorepo 内静态注册：

```ts
// packages/extension/src/drivers.ts
import { mysqlDriver } from '@db-explorer/driver-mysql';
registry.register(mysqlDriver);
```

### 9.2 L2 配置驱动扩展
用户在设置中声明驱动**扩展 ID**：

```json
{ "dbExplorer.drivers": ["acme.vscode-db-mongo"] }
```

core 激活时（或设置变更时）：

```ts
for (const extId of cfg.drivers) {
  const ext = vscode.extensions.getExtension(extId);
  if (!ext) { warn(`驱动扩展 ${extId} 未安装`); continue; }
  const contrib: DriverContribution = (await ext.activate()) ?? ext.exports;
  for (const d of contrib?.drivers ?? []) registry.register(d);
}
```

### 9.3 L3 扩展点贡献
驱动扩展 `package.json`：

```json
{
  "extensionDependencies": ["acme.db-explorer"],
  "contributes": {
    "databaseDrivers": [ { "driverId": "mongo", "displayName": "MongoDB" } ]
  }
}
```

`extensionDependencies` 保证 core 先激活；驱动在自身 `activate()` 中经 core 导出 API 注册：

```ts
export async function activate(context: vscode.ExtensionContext) {
  const core = vscode.extensions.getExtension<CoreExports>('acme.db-explorer')!.exports;
  context.subscriptions.push(core.registerDriver(new MongoDriver()));
  // registerDriver 内部完成 apiVersion 校验，失败时抛出带指引的错误
}
```

> L2 与 L3 的差异仅在激活时机（L2 由 core 拉起、L3 随自身激活注册），注册后行为完全一致。`contributes.databaseDrivers` 目前仅作声明性元数据（命令面板展示、市场搜索），后续可用于信任校验（遗留问题 #5）。

### 9.4 第三方驱动信任边界（M7 收尾复核，关闭遗留 #5）

| 项 | 结论 |
|---|---|
| 信任根 | **扩展安装行为 + VSCode 工作区信任**。安装第三方驱动扩展 = 信任其代码（驱动与宿主同进程运行，D-05）；Restricted Mode 下本插件不激活，L2/L3 驱动天然不加载——依赖平台既有信任模型，不自建签名/沙箱体系 |
| 自建签名的取舍 | 不做。与 Marketplace 发布者机制重叠，成本高收益低；`contributes.databaseDrivers` 仅作展示性元数据，不作为安全边界 |
| 显式提示面 | L2 配置（`dbExplorer.drivers`）中声明的驱动扩展首次激活时，输出面板提示「已加载第三方驱动 X（来源扩展 ID）——第三方驱动与本插件同进程运行，请确认信任其来源」，不阻塞 |
| 隔离演进 | 第三方驱动报告 native 崩溃等 D-05 触发条件时，可按驱动标记隔离（UtilityProcess），架构已预留（DriverHost 抽象），无需提前建设 |

## 10. 安全要求

| 项 | 要求 |
|---|---|
| 参数化 | 所有含用户输入值的语句必须参数化；唯一例外是标识符（必须 `quoteIdentifier`） |
| **DDL 例外（@since v0.1.2；校验口径 v0.1.16 修订）** | DDL 语句（buildCreateTable/buildAlterTable 产物）**不可参数化**（MySQL/PG 的 PREPARE 均不支持多数 DDL 形状）：标识符必须 `quoteIdentifier`（方言引号 + 内嵌引号双写转义）**且**做危险字符校验（**v0.1.16 黑名单口径**：只拒绝方言引号字符与控制字符 → `E_VALIDATION`，fail-closed；连字符/点/空格/中文等真实合法名放行——`test-api` 类库名曾被白名单误拒）。**不可引用插值**（如 MySQL `CHARACTER SET`/`COLLATE` 关键字）保持严格白名单（`[A-Za-z0-9_$]`）；字面量（列默认值/表注释）按方言转义函数处理；注释文本中的换行/控制字符必须剥离或转义。禁止把用户输入原文拼进任何语句 |
| 密码 | 仅经 `secret` 参数获得；禁止写入日志、错误信息、遥测、任何文件 |
| 日志脱敏 | `DriverError.detail` 输出前过滤 DSN/密码/Token；连接串一律打码 |
| SSL | 默认校验证书；驱动提供“跳过校验”选项时，必须在表单该项旁标注风险（M7 起经 FormSchema 的 `hint` 字段承载，见 §3.1） |
| 超时与取消 | 见 §7，`supportsCancel` 不可虚报 |
| 依赖 | 纯 JS 依赖优先；引入 native 模块必须在 README 声明平台矩阵（引入即自动纳入 D-05 隔离评估） |

## 11. 契约测试

`@db-explorer/driver-conformance` 提供统一套件，**所有驱动 CI 必须调用并通过**：

```ts
import { runDriverConformanceSuite } from '@db-explorer/driver-conformance';
import { createTestConnection } from './helpers';   // 起本地库（docker/testcontainer）并建表

runDriverConformanceSuite(() => createTestConnection(), {
  capabilities: { supportsCancel: true, lazyCell: false },
});
```

场景组（与《概要设计》12.2 对应）：

| 组 | 断言要点 |
|---|---|
| 连接 | 错误密码 → E_AUTH；不可达地址 → E_CONN；dispose 后调用 → E_CONN |
| 元数据 | 列含 PK 标记与 ordinal（严格递增）；名称唯一；索引/键可列出且列名与 listColumns 一致；KeyMeta PK 与列级标记一致；声明 supportsDdl 时 getDdl 输出非空（未实现跳过） |
| 分页 | offset 翻页稳定（按 PK 排序）；totalCount 可缺省；cursor 模式闭环 |
| 筛选下推 | 每个 FilterOp 结果与内存过滤一致；生成语句含参数占位（无值拼接） |
| 变更集 | insert 回填主键；update 冲突 → E_CONFLICT 且库中数据未变；insert/update/delete 混合事务原子性 |
| 取消 | 下发长查询后 abort → E_CANCELED，且服务端连接可复用 |
| 值编码 | §5 每种 NormalizedType 写入→读出往返一致（重点：DECIMAL 精度、DATETIME 时区、二进制、NULL vs ''）；SQL 驱动 @since M8-PG 经 `buildCreateTable` 建 fixture 表 → `applyChanges` 写入 → `fetchRows` 读回**实跑往返**（探针口径同 P-19：方法不存在整组跳过；键值数据源维持内容表形状断言） |
| 表结构编辑（@since v0.1.2；声明 supportsDdlEditor 才跑——**未声明而方法存在**按 P-19 同族视为已实现照跑） | buildCreateTable 语句执行后 listColumns 与 spec 一致（列名/nullable/PK/ordinal）；buildAlterTable 覆盖 加列/删列/改类型/改注释/PK 变更 → 执行后 listColumns 反映；非法标识符（引号/分号）→ E_VALIDATION（fail-closed）；删列语句必须标 destructive；无结构差异 → 空数组。@since v0.1.15（listKeys/listIndexes 已实现时实跑）：键/外键/索引 建表声明→回读一致（UK/FK 按列形状断言——SQLite UNIQUE 名为引擎合成的 sqlite_autoindex_*）、alter 增删唯一键/索引/外键（外键 alter 以 E_UNSUPPORTED=能力边界 skip，探测写 check 外层防 P-19 双重计数）、**基线原样提交 → 空数组（防误删红线）** |
| 关系收集（@since v0.1.15；M8-ER / D-22，`runRelationGraphChecks`——listKeys 未实现整组跳过，已实现必须全过） | fixture（buildCreateTable 造 cf_er_* 六表：单列 FK / 复合 FK / 自引用 FK / 无 FK 表）→ 关系收集断言：表集只入 kind=table 且列按 ordinal 序、PK 标记一致；单列/复合 FK 合并为单边且 **sourceColumns/targetColumns 按约束声明列序对齐**（PG ORDINALITY / MySQL ORDINAL_POSITION / MSSQL constraint_column_id 口径）；自引用边保留；selection 裁剪端点不全的边不绘制并计入 hiddenEdges |
