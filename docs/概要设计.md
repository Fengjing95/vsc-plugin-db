## 1. 背景与目标

### 1.1 背景
日常开发中，查看/修改数据库需要频繁在 IDE 与数据库客户端（Navicat / DBeaver / DataGrip / RedisInsight）之间切换，存在：
- 上下文割裂：表名、字段名、SQL 语句要手动复制粘贴
- 无代码补全：编写 SQL 时没有表结构提示
- 修改数据风险不可控：多数客户端直接落库，缺少“暂存 - 预览 - 提交”的安全流程

### 1.2 产品目标
在 VSCode 内提供**统一的、可插拔的数据库访问入口**，覆盖“看结构 → 查数据 → 改数据 → 写 SQL”的完整链路。

### 1.3 核心价值主张
| 价值 | 说明 |
|---|---|
| 不离开 IDE | 侧边栏树 + 表格视图 + SQL Console 全部内嵌 |
| 可插拔驱动 | 新增数据库类型不改动核心代码 |
| 安全编辑 | 表格改动先暂存，显式提交才落库，支持事务回滚 |
| 上下文感知 | SQL 补全感知当前连接 / 库 / 表 / 字段 |

### 1.4 非目标（本期不做）
- 数据库运维（备份、主从、监控、慢日志分析）
- 数据可视化 BI 报表
- 团队协作 / 云端连接同步
- 完整 DDL 建模器（ER 图设计器）
- **Web 版 VSCode（github.dev）支持**：桌面端 MVP 优先，Web 端需代理层，见遗留问题 #1

### 1.5 术语表
| 术语 | 含义 |
|---|---|
| 驱动（Driver） | 实现统一接口的数据库适配器，负责方言翻译 |
| ChangeSet | 表格编辑的暂存变更集，提交前不落库 |
| RowKey | 行定位键（主键列值集合），见 4.3 |
| Session | 有事务上下文的数据库会话 |
| capabilities | 驱动能力声明，UI 据此降级渲染 |
| L1/L2/L3 | 驱动接入的三种方式，见 5.1.2 |

## 2. 用户画像与核心场景

### 2.1 用户画像
- **后端开发**：调试期频繁查表、改测试数据、跑临时 SQL
- **数据/测试同学**：导出 CSV 做分析、核对数据
- **DBA（轻度）**：查看索引、键、表结构

### 2.2 核心场景（User Story）

| 编号 | 场景 | 关键诉求 |
|---|---|---|
| US-01 | 我在写代码时想快速看一眼某张表的数据 | 3 次点击内打开表格 |
| US-02 | 我要改一条测试数据的某个字段 | 单元格可编辑、提交前可回滚、失败可重试 |
| US-03 | 我要写一条复杂 SQL 查询 | 有表名/字段名补全、结果可导出 |
| US-04 | 我要同时管理 MySQL 和 Redis | 同一个树里并存，操作体验一致 |
| US-05 | 我要把查询结果给同事 | 一键导出 CSV / JSON / Markdown |
| US-06 | 我担心误删生产数据 | 生产连接可标记只读，危险操作二次确认 |

## 3. 产品整体架构

```
┌─────────────────────────────────────────────────────────────────┐
│                          表现层 (UI)                              │
│  ┌──────────────┐  ┌────────────────────┐  ┌─────────────────┐  │
│  │ 资源树        │  │ 表格视图/结果面板    │  │ SQL Console     │  │
│  │ (TreeView)   │  │ (Webview: React)   │  │ (原生 Editor)   │  │
│  └──────┬───────┘  └────────┬───────────┘  └────────┬────────┘  │
└─────────┼──────────────────┼─────────────────────────┼─────────┘
          │ TreeData          │ RPC（zod 校验，见 7.4）   │ Completion
          └────────────┬─────┴──────────────────────────┘
                       ▼
┌─────────────────────────────────────────────────────────────────┐
│                   核心服务层 (Extension Host)                      │
│  ConnectionManager  │ DriverRegistry │ DriverHost(隔离抽象)        │
│  MetadataCache      │ ChangeSetService(权威副本) │ SessionManager │
│  QueryService       │ ResultExporter │ DangerGuard              │
│  CompletionProvider │ SecretStore │ Telemetry(默认关闭)          │
└───────────────────────────┬─────────────────────────────────────┘
                            ▼  IDatabaseDriver（apiVersion=1，见驱动规范）
┌─────────────────────────────────────────────────────────────────┐
│                驱动抽象层（可插拔、错误码统一）                       │
│  mysql-driver │ redis-driver │ pg-driver │ sqlite-driver …      │
└───────────────────────────┬─────────────────────────────────────┘
                            ▼
                   数据源 / SSH 隧道 / 代理
```

**分层原则**
1. UI 层不感知具体数据库类型，只消费 `TreeNode` / `ResultSet` / `ChangeSet` 等**统一模型**
2. 驱动层只负责“翻译”，不含 UI 逻辑；所有驱动调用经 `DriverHost` 中转（见 7.6），便于未来进程隔离
3. 能力差异（如 Redis 无表概念）通过 `capabilities` 声明，UI 据此降级渲染
4. **ChangeSet 的权威副本在 Extension Host**，Webview 只持编辑视图——Webview 崩溃/重载不丢编辑（见 5.4.5）
5. 所有跨层错误携带统一错误码（`DriverErrorCode`），UI 只认错误码不解析消息文本

## 4. 核心概念与数据模型

### 4.1 连接配置

```ts
interface ConnectionConfig {
  id: string;                 // uuid
  name: string;               // 显示名 "本地 MySQL"
  driverId: string;           // 'mysql' | 'redis' | ...
  group?: string;             // 分组（可选）
  color?: string;             // 标识色，用于区分环境
  readOnly?: boolean;         // 只读保护
  env?: 'dev' | 'test' | 'prod';
  options: Record<string, any>; // 驱动专属：host/port/user/database/...
  ssl?: SslOptions;
  ssh?: SshTunnelOptions;
  secretRef: string;          // 指向 SecretStorage 中的密钥 key
}
```

> **密码永不落盘到 settings.json**，统一存 `vscode.SecretStorage`。连接配置本体存 `globalState`，导出时密码以 `${secret}` 占位。

### 4.3 结果集模型

```ts
interface ResultSet {
  columns: { name: string; type: NormalizedType }[];
  rows: unknown[][];              // 行式存储，减少 webview 序列化开销
  rowCount: number;
  totalCount?: number;            // 分页总数（可能为 undefined，避免全表 count）
  primaryKey?: string[];          // 用于编辑定位（RowKey）；为空则默认只读
  nextCursor?: string;            // pagination=cursor 时由驱动返回
  affectedRows?: number;          // 非 SELECT 语句
  messages?: string[];            // 警告/提示（如 MySQL Notes）
  executionMs: number;
  truncated?: boolean;            // 是否因行数上限被截断
}

// RowKey = 主键列名 → 值 的映射，如 { id: 42 }
// 编辑定位一律使用 RowKey，不使用行号（分页翻页后行号失义）
```

### 4.4 值编码契约（v0.2 新增，关键）

Webview 与 Extension Host 之间、编辑回传与驱动参数之间，值的表示**统一遵循下表**，避免 JS number 精度丢失与时区歧义。完整类型映射示例（MySQL / PG / Redis 逐类型展开）见[《驱动开发规范》§5](./驱动开发规范.md)。

| 场景 | 传输表示 |
|---|---|
| NULL | `null`（与空串 `''` 严格区分，UI 提供切换） |
| 整数 | `number`；超出 `Number.MAX_SAFE_INTEGER` 一律按 `decimal` 字符串处理 |
| DECIMAL / NUMERIC / BIGINT 超限 | `string`（原样保留精度） |
| 浮点 | `number` |
| 布尔 | `boolean` |
| DATE | `'YYYY-MM-DD'` |
| TIME | `'HH:mm:ss.SSS'` |
| DATETIME / TIMESTAMP | `'YYYY-MM-DD HH:mm:ss.SSS'`（不含时区，按连接会话时区渲染，tooltip 标注） |
| JSON | 已解析的对象/数组（非字符串） |
| BINARY / BLOB | base64 字符串，配合列类型 `binary` 解释为 hex / 图片 / 文件 |
| 超长单元格（> cellMaxChars） | 占位符 + 按需 `fetchCell` 拉取（需驱动 `lazyCell` 能力） |

`NormalizedType`（v0.2 扩展）：

```ts
type NormalizedType =
  | 'string' | 'integer' | 'decimal' | 'float' | 'boolean'
  | 'date' | 'time' | 'datetime' | 'json' | 'binary' | 'uuid' | 'unknown';
```

### 4.5 变更集模型（表格编辑核心）

```ts
interface ChangeSet {
  inserts: Array<{ tempId: string; values: Record<string, unknown> }>;
  updates: Array<{
    rowKey: Record<string, unknown>;         // 主键值
    original: Record<string, unknown>;       // 原值（用于乐观并发校验）
    changes: Record<string, { old: unknown; new: unknown }>;
  }>;
  deletes: Array<{ rowKey: Record<string, unknown>; original: Record<string, unknown> }>;
}
```

> **权威副本规则（v0.2 决策 D-06）**：ChangeSet 单一事实源在 Extension Host 的 `ChangeSetService`。Webview 本地缓存用于低延迟编辑（单元格编辑即时生效），并以 300ms debounce 同步到 Host；Webview 重载后凭 `stateId` 从 Host 恢复，编辑不丢失。

### 4.6 事务会话模型（v0.2 决策 D-09）

| 事务形态 | 触发方式 | 生命周期 | 阶段 |
|---|---|---|---|
| 短事务 | `applyChanges` 内部自动 BEGIN…COMMIT/ROLLBACK | 单次提交，毫秒~秒级 | M4 |
| 交互式事务（手动） | Console 显式 BEGIN / COMMIT / ROLLBACK | 跨语句，由 `SessionManager` 管理 | P2 |

交互式事务约束：`SessionManager` 强制空闲超时（默认 5min，超时自动 ROLLBACK 并释放连接）；单连接同时最多 1 个交互式会话；持有交互式会话的连接在树上显示“事务进行中”徽标，防止用户遗忘。

### 5.1 驱动插件体系（可插拔）

> 本节为概要；接口全集、错误码规范、值编码映射、打包加载细则统一收敛到[《驱动开发规范》](./驱动开发规范.md)，此处不重复。

#### 5.1.1 驱动接口（概要）

```ts
export interface IDatabaseDriver {
  readonly id: string;                  // 'mysql'
  readonly displayName: string;         // 'MySQL'
  readonly icon?: string;
  readonly apiVersion: number;          // 与核心协商，当前 = 1
  readonly capabilities: DriverCapabilities;
  getConnectionFormSchema(): FormSchema;
  testConnection(cfg: ConnectionConfig, secret: string): Promise<TestResult>;
  connect(cfg: ConnectionConfig, secret: string): Promise<IConnection>;
}
```

`IConnection` 提供：元数据自省（库/对象/列/键/索引）、分页取数 `fetchRows`、SQL 执行 `query`、变更提交 `applyChanges`、**变更预览 `previewChanges`（v0.2 新增，与 applyChanges 同源生成 SQL，保证“预览即执行”）**、可选 `fetchCell` / `openSession` / `getCompletionSource`。完整签名见[驱动规范 §3](./驱动开发规范.md)。

#### 5.1.2 驱动注册方式（三级可扩展）

| 级别 | 方式 | 适用场景 |
|---|---|---|
| L1 | 内置驱动（monorepo 内静态注册） | 官方维护 MySQL / Redis / PG / SQLite |
| L2 | 配置项加载驱动扩展：`dbExplorer.drivers = ["acme.db-mongo"]` | 用户按需安装的第三方驱动扩展 |
| L3 | 扩展激活后经核心导出 API 注册（`contributes.databaseDrivers` 声明元数据 + `extensionDependencies` 保证激活顺序） | 驱动与其它功能打包在一起的插件 |

> **id 唯一性**：`DriverRegistry.register()` 校验 `driverId` 全局唯一，冲突时拒绝后注册者，Toast 指明来源（内置驱动 / 扩展 ID + 版本）。
> **验收标准**：新增一个 SQLite 驱动，只需实现 `IDatabaseDriver` + 声明，**核心代码 0 改动**。
> L2/L3 激活时序、版本协商细节见[驱动规范 §9](./驱动开发规范.md)（对应决策 D-07）。

#### 5.1.3 能力差异处理（以 Redis 为例）

| 层级 | MySQL | PostgreSQL（D-15） | SQLite（D-16） | Redis |
|---|---|---|---|---|
| 一级 | 连接 | 连接 | 连接 | 连接 |
| 二级 | Database | Database（= schema，非系统 schema 列表） | Database（恒为 `main` 单节点） | Database (0-15) |
| 三级 | 表 / 视图 目录 | 表 / 视图 目录 | 表 / 视图 目录 | Keys 目录（可按类型/前缀分组） |
| 四级 | 表 / 视图 | 表 / 视图 | 表 / 视图 | Key |
| 五级 | 列 / 键 / 索引 目录 | 列 / 键 / 索引 目录 | 列 / 键 / 索引 目录 | — |
| 六级 | 具体列 | 具体列 | 具体列 | — |

> PG 驱动（M8-PG）按 D-15 将 schema 映射到树 database 层：PG 连接协议绑定单库，`listDatabases()` 返回连接库内非系统 schema，各接口 `db` 参数 = schema 名、`obj` 恒为裸表名——核心/树/RPC 零改动（详见 ADR D-15 与驱动规范 §5.2）。
>
> SQLite 驱动（M8-SQLite）单文件单库：`listDatabases()` 恒返回 `[{ name: 'main' }]`（SQLite 逻辑主库，ATTACH 附加库为后续扩展口），各接口 `db` 参数恒为 `main`、`obj` 为裸表/视图名（sqlite_master 自省，排除 `sqlite_%` 内部对象）——树/协议同样零改动（详见 ADR D-16 与驱动规范 §5.4）。

UI 通过 `capabilities.hierarchy` 决定渲染哪些层级，**不做硬编码**。

> Redis 类非 SQL 数据源：`supportsSQL = false` 仅关闭 SQL 补全/格式化与危险 SQL 判定；仍提供**命令控制台**（复用 Console UI 与结果面板），危险判定改用命令白名单（见驱动规范 §5.3）。

#### 连接生命周期（v0.2 决策 D-10）
- **懒连接**：树上的连接节点默认“未连接”态，展开/查询时才建立连接；插件激活时不自动连任何库
- **断线处理**：驱动调用失败若错误码为 `E_CONN`，节点转为“已断开”，下次操作自动重连；空闲 `ping` 检测间隔 60s（可关）
- **重连退避**：自动重连指数退避（1s/2s/4s，上限 3 次），期间 UI 明示“重连中”，避免请求风暴
- **密码获取**：连接时经 `secretRef` 从 SecretStorage 取回；取不到（如导入的配置）→ 弹一次性输入框，不暴露错误堆栈
- **密钥生命周期**：`secretRef` 统一命名 `dbExplorer.secrets.<connId>`；删除连接时同步删除对应 SecretStorage 条目（防孤儿密钥）；复制连接经 SecretStorage API 迁移密钥，明文不出现在剪贴板/日志/导出文件

#### 5.3.1 层级结构

```
▾ 🟢 本地 MySQL (connection)
  ▾ 📁 information_schema (database)
    ▾ 📂 表 (table)              ← 目录节点
      ▸ 📋 users                 ← 表
      ▸ 📋 orders

  ▾ 📁 myapp
    ▾ 📂 表

        ▾ 📂 键 (key)

          • FK  role_id → roles.id
        ▾ 📂 索引 (index)
```

#### 5.3.2 实现方式

采用 **VSCode 原生 `TreeDataProvider`**（非 Webview），理由：
- 天然支持懒加载 `getChildren`、右键菜单 `contributes.menus`、`view/item/context`
- 性能好（万级节点虚拟滚动）
- 与 VSCode 主题 / 折叠 / 键盘导航一致

```ts
interface DbTreeNode {
  id: string;                       // 稳定唯一 id，用于 expand 状态持久化
  type: 'connection'|'database'|'folder'|'table'|'view'|'column'|'key'|'index';

  description?: string;             // 右侧灰色描述，如 "bigint PK"

  collapsibleState: vscode.TreeItemCollapsibleState;
  contextValue: string;             // 控制右键菜单显示
  iconId: string;                   // 主题图标
  payload: Record<string, any>;     // 定位信息：connId/db/table/column...
}
```

#### 5.3.3 懒加载策略

| 节点 | 加载时机 | 缓存 TTL |
|---|---|---|
| 连接（列表） | 视图激活（仅列表，不建立 DB 连接） | 常驻 |
| Database 列表 | 展开连接 | 60s |
| 表/视图目录 | 展开 database | 常驻（手动刷新才失效） |
| 表列表 | 展开“表”目录 | 60s |
| 列/键/索引 | 展开表 | 5min |

- 展开中的节点显示 `loading~` 占位（VSCode `TreeItem` 支持）
- 全局 `Refresh` 按钮清空缓存并重载当前展开路径

#### 5.4.3 编辑与提交（核心流程）

```
用户编辑单元格
   ↓
前端写入本地 ChangeSet（300ms debounce 同步到 Host 权威副本），单元格标黄
   ↓
用户点击 [提交变更 (N)]
   ↓
Host 调用 connection.previewChanges() → 弹窗预览：将执行的 SQL/命令（可折叠，参数化占位）
   ↓
用户确认 → 调用 connection.applyChanges()
   ↓
驱动在【单个事务】内执行：
   - 无主键表：默认只读；开启“全列匹配模式”后用全部原始列做 WHERE（决策 D-03）
   - UPDATE 的 WHERE = 主键 + 变更列原值（字段级并发，评审确认）；原值为 NULL 的列用 IS NULL；DELETE 仅按主键
   - 任一语句 affectedRows ≠ 预期 → 抛 E_CONFLICT，中止并回滚
   ↓
成功 → 清空 ChangeSet，刷新当前页，Toast “已提交 3 条变更”
失败 → 事务回滚，ChangeSet 保留，错误行高亮（错误码 → 文案），提供“重试/放弃”
```

**规则约束**
| 场景 | 处理 |
|---|---|
| 表无主键 | 默认只读；设置 `dbExplorer.edit.allowNoPrimaryKey` 开启“全列匹配模式”并显示风险提示（D-03） |
| 字段为 BLOB / 二进制 | 只读展示，点击弹出十六进制/图片预览 |
| 字段为 JSON | 单元格内可展开格式化编辑 |
| 字段超长文本 | 单元格显示截断，点击弹出大文本编辑器（`lazyCell` 按需拉取） |
| NULL vs 空串 | 区分标识，右键可切换为 NULL（见交互稿 §4.5） |
| 只读连接 | 所有编辑入口置灰，Tooltip 说明原因 |
| 生产环境 | 提交前强制输入表名确认（5.8） |

#### 5.4.4 大数据量性能

- 服务端分页（`LIMIT/OFFSET` 或游标），**默认不执行 `COUNT(*)`**，用估算或显示“≥ N 行”
- 行数据以数组形式传输（非对象），减少 50%+ 序列化体积
- Webview 侧使用虚拟滚动（只渲染可视区 ~40 行）
- 单次传输上限 5000 行 / 5MB，超出截断并提示

#### 5.4.5 ChangeSet 权威副本与崩溃恢复（v0.2）

- Host 端 `ChangeSetService` 以 `viewId → ChangeSet` 持有权威副本；Webview 编辑消息 debounce 300ms 上行
- Webview 重载（崩溃/后台释放）→ 发送 `sys.handshake { stateId }` → Host 回放快照（当前筛选、分页、ChangeSet、选中态）
- 关闭表格视图且存在未提交变更 → 确认弹窗“放弃 N 条未提交变更？”，防止误关丢失

#### 5.5.3 补全实现

```ts
vscode.languages.registerCompletionItemProvider('sql', {
  async provideCompletionItems(doc, position) {
    const ctx = parseContext(doc, position);   // 解析出 db / 表 / 别名 / 前缀（单库范围，D-04）
    const src = await metadataCache.getCompletionSource(ctx.connectionId, ctx.db);
    return [
      ...src.keywords,        // SELECT / FROM / WHERE ...
      ...src.functions,       // COUNT / NOW / JSON_EXTRACT ...
      ...src.databases,       // 库名
      ...src.tables,          // 表名（带 description: 注释）
      ...src.columns.filter(c => c.table === ctx.table),  // 按上下文过滤
      ...src.snippets,        // 代码片段
    ];
  }
});
```

**补全作用域（评审修订 P1-1）**：provider 内部按文档绑定过滤——仅绑定了连接的 Console 文档返回库/表/列补全；用户自己的普通 `.sql` 文件给关键字 + 常用标准函数 + 通用片段（不含连接元数据），状态栏提示“未绑定连接，点击选择”；文件级关联持久化放 P2。

**词表与排序（v0.2.10，排序口径 v0.2.12 调整）**：方言关键字/函数为全量常用面（各驱动 `completion.ts` 纯数据：MySQL 含窗口函数/CTE/UPSERT/JSON，PG 含 ON CONFLICT/RETURNING/JSONB/数组）；补全片段经 `CompletionSource.snippets` 下发（通用片段 + 方言片段）；**排序关键字置顶**（列位：关键字→列→函数；任意位：关键字→表/列→片段→函数→库；表位保持表/库优先），extension 按序号生成 sortText，防 VSCode 按字母重排。

**上下文感知规则**
| 光标位置 | 优先补全 |
|---|---|
| `SELECT ` 后 | **关键字置顶（v0.2.12）**、列名（当前 FROM 表）、函数、`*` |
| `FROM ` 后 | 表名、视图名、库名 |
| `别名.` 后 | 该别名对应表的所有列 |
| `WHERE ` 后 | **关键字置顶（v0.2.12）**、列名 + 运算符 |
| `JOIN ` 后 | 表名 |
| `CALL ` 后 | 存储过程名 |

> v0.2.11 注：列上下文（`SELECT … FRO`、`… WHE`、`x = 1 AN` 等最高频书写位置）原只出列+函数，关键字零提示——现补齐。v0.2.12 注：排序按用户口径调整为**关键字置顶**（列位与任意位），前缀过滤保证精准命中不受排序影响。

**元数据缓存**：进入 Console 时预热当前库的表 + 列；DDL 变更后失效联动（7.5）。

### 5.7 导出服务（v0.2 新增）

导出不在 Webview 内做（避免阻塞 UI 与 OOM），统一由 Host 端 `ResultExporter` 执行：

```
Webview: export.run { viewId, format, scope: 'page'|'result'|'selection' }
   ↓
Host: withProgress('导出中...') + 可取消（AbortSignal）
   循环：fetchRows(分页, chunkRows 默认 1000) → 流式写入 fs.WriteStream
   每批回报进度事件 evt:export.progress { rows, bytes }
   ↓
完成：Toast “已导出 100,000 行 → 路径”，点击定位文件
```

| 项 | 方案 |
|---|---|
| CSV / JSON / NDJSON / Markdown / SQL INSERT | P0~P1，流式写，行数无上限（受超时与取消约束） |
| Excel (xlsx) | P2，`exceljs` 流式；选型注意 License（遗留问题 #4） |
| 目标位置 | 用户经 SaveDialog 选择；默认目录为工作区 `.db-export/`（gitignore 建议） |
| 大任务 | **后台执行（M8 交付，#16）**：`export.run` 在 SaveDialog 选定目标后**立即回执 `{ exportId }`**，导出在 Extension Host 后台继续（进度进通知中心 `withProgress(Notification)`，通知上可取消，多任务并发互不阻塞）；进度经 `evt:export.progress`、终态经 `evt:export.done`（成功/取消/失败三路）回执；完成/失败 Toast 由 Host 发（不依赖 Webview 存活）；Webview 侧工具栏 chip 按 exportId 追踪并可取消 |
| 敏感数据 | 不做任何上传/遥测；仅写本地文件 |

### 5.8 安全护栏 DangerGuard（v0.2 收敛）

所有“危险”判定与确认集中在一个服务，避免各处自建：

| 检测点 | 触发源 | 规则 |
|---|---|---|
| 表格变更提交 | applyChanges 前 | `env === 'prod'` 强制输入表名确认；变更预览强制展开（不可跳过） |
| Console 语句 | 执行前 | AST 解析（`node-sql-parser`）：无 WHERE 的 UPDATE/DELETE、DROP、TRUNCATE、ALTER…DROP → 强提示确认；**解析失败降级为正则匹配 + 强提示**（宁可误报不漏报）——此为普通连接的**确认路径**，只读连接走下方 fail-closed 拦截路径 |
| 树节点操作 | 删表/删列/删索引 | 统一确认 Modal（输入名称匹配），生产环境额外显示红条 |
| 只读连接 | ConnectionManager 层 | 写语句/变更集直接拒绝（`E_READONLY`）；**fail-closed**：无法证明语句是读（AST 解析失败且正则不可判）时一律拒绝，防注释混淆/方言特性绕过；UI 置灰只是第一道防线 |
| 危险等级 | — | 只读连接 + prod 环境的组合可配置为“完全禁止写”（默认关闭） |

### 5.9 表结构编辑器（DDL，v0.2.4 新增，M8-B2）

对表的增删改（新建 / 修改结构 / 删除）与列的增删改，统一收敛在一个**表结构编辑器**页面（新建与修改共用，列操作内嵌其中）；删除列支持从树列节点确认后直删。模型、驱动接口、安全例外详见[驱动开发规范 §3/§10](./驱动开发规范.md)；交互线框见[交互设计稿 §12](./交互设计稿.md)。

| 项 | 设计 |
|---|---|
| 能力开关 | `capabilities.supportsDdlEditor`（驱动声明；未声明时树菜单不出现入口，编辑器页面提示不支持） |
| 统一模型 | `TableSpec { name, comment?, columns: ColumnSpec[] }`；`ColumnSpec { name, dataType, nullable, isPrimaryKey, autoIncrement?, defaultValue?, comment?, ordinal }`（驱动方言类型原文，见规范 §3） |
| 语句生成 | **驱动负责**：`buildCreateTable(db, spec)` / `buildAlterTable(db, obj, spec, current)`（可选方法，@since）。驱动自行 diff 出 ALTER 序列；`current` 由 Host 在**预览与执行前分别实时**从 `listColumns` 派生（避免基于过期基线生成变更，DDL 无乐观锁） |
| RPC | `ddl.load { connId, db, obj? }` → `{ kind: 'create'\|'alter', spec }`；`ddl.preview { connId, db, obj?, spec }` → `{ kind, statements: DdlStatement[] }`；`ddl.execute { connId, db, obj?, spec }` → `{ executed, failed? }`。**预览与执行同源**：execute 由 Host 重新调用同一 builder 生成语句，不信任 Webview 回传 SQL |
| 执行 | 复用驱动 `query()` 逐条执行、失败即停并定位语句序号（DDL 多数服务端隐式提交、无法单事务回滚——UI 明示）；成功后 `invalidateDb` + 树刷新（§7.5 DDL 失效联动） |
| 危险护栏 | `DdlStatement.destructive` 由驱动标记（删列/改类型等可能丢数据的语句）；任一 destructive 或 kind=alter → dev/test 确认 Modal、prod 输入表名确认（§5.8 延伸）；DROP TABLE / TRUNCATE 树操作走 §6 危险确认 Modal（输入名称匹配） |
| 只读连接 | 编辑器只读打开（可看可改不可执行——Host 层 `E_READONLY` 拦截执行，同 §5.8 第一道防线语义） |
| 范围外（P2+） | 索引/外键的可视化编辑、列排序（AFTER）、分区与存储引擎选项、结构对比 |

### 5.10 操作日志（v0.2.13 新增，M8 后续优化）

数据库连接、查询等操作的 info/error 级日志进 VSCode 自带输出面板（Output）——`createOutputChannel('Database Explorer', { log: true })` 的 **LogOutputChannel** 原生形态：info/warn/error/debug 分级、自动时间戳、面板右上角级别过滤下拉与 error 徽标。

| 项 | 设计 |
|---|---|
| 门面 | Extension Host 侧 `services/logger.ts` 的 `Logger` 类包装 LogOutputChannel，各服务经门面打点、**不直接持有 channel**；保留 `[源标签]` 前缀（conn/console/ddl/dangerGuard/rpc/form/export/query）便于 grep；webview 侧不打点（日志只在 Extension Host） |
| 统一拦截（v0.2.14） | **DriverHost 装饰器** `LoggingDriverHost`（ADR D-05「core 调用驱动的统一入口」）：fetchRows / query / applyChanges 全量 info（用户口径——所有查询动作都记录）、previewChanges debug（高频、非实际执行）、失败 error（code 可见）、E_CANCELED info；connId 经懒连接缓存回查（`ConnectionManager.connIdOf`）。Console/DDL/表格取数/编辑提交/导出全部经同一实例；**事务内语句不经 DriverHost**（SessionManager.execute 直连驱动 ISession），由 SessionManager 自行打点。与 Console run 汇总日志粒度不同（动作级 vs 批次级），并存不冲突 |
| 点位 | **连接域**：建连成功/失败（connId、连接名、驱动、host:port、耗时）、断开、自动重连（断开保护窗口内建连）、SSH 隧道建立/失败、连接表单「测试连接」成功/失败；**查询域**：执行完成/取消（语句数、行数、耗时）、执行失败（DriverError code + message）、危险语句判定/确认/拦截（§5.8）；**DDL**（§5.9）：执行/删表/删列完成与失败（含耗时）；**导出**（§5.7）：任务开始/完成/取消/失败（回执同点） |
| 级别约定 | info/error 为主，高频路径 debug——完成/确认/绑定类 → info；拦截与协议异常（fail-closed 拒绝、prod 确认未通过、横幅取消、非法 RPC 帧）→ warn；失败（连接/执行/DDL/导出/补全预热）→ error；高频路径（补全数据源耗时）→ debug（面板默认 Info 过滤不显示） |
| 脱敏（C-10） | 日志永不出现密码/凭证/连接串密钥部分：只打 host:port 等非敏感地址信息，`options` 整体不打；错误经 `describeError` 输出 DriverError code + message（C-6 文案映射层已保证不含凭证） |
| 与错误码关系 | 日志是 DriverError 错误码链路的**补充**（诊断面板可 grep），不改变 C-6 错误码与 UI 错误映射行为 |
| 面板入口 | 不自动 show()（不打断用户）；命令面板「数据库: 打开日志」（`dbExplorer.showLog`）聚焦频道 |
| 范围外 | telemetry（§6 #15）、日志落盘文件、webview 日志桥接、按级别配置项（LogOutputChannel 自带面板级过滤） |

### 7.2 关键技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 构建 | esbuild / tsdown | 快速，产物小 |
| 包管理 | pnpm workspace | monorepo |
| MySQL 驱动 | `mysql2` | 支持 Promise、预编译语句、连接池 |
| Redis 驱动 | `ioredis` | 功能全、支持 Cluster/Sentinel |
| PG 驱动 | `pg` | 标准 |
| SQLite 驱动 | `sql.js`（WASM） | 零 native 依赖、VSIX 平台无关、引擎随驱动固定不随宿主漂移（**D-16 定稿**，与本表初选 better-sqlite3 不一致处一并收口）；同步执行限中小库，node:sqlite/better-sqlite3 备选均否决（见 D-16） |
| 表格 UI | React + TanStack Table + TanStack Virtual | 无头、可控、虚拟滚动 |
| 状态 | Zustand | 轻量 |
| SQL 解析/格式化 | `node-sql-parser` + `sql-formatter` | 语句切分、危险语句 AST 判定、格式化 |
| RPC 校验 | zod | 双端运行时校验（决策 D-06） |
| 单测 | vitest | 与 esbuild 生态一致 |
| e2e | @vscode/test-electron | 官方方案，CI 用 sqlite 驱动免网络 |
| CSV 导出 | 流式写（`fs.createWriteStream`） | 大结果集不 OOM |
| 通信 | Webview ↔ Extension：`postMessage` + 请求/响应 id 映射（RPC 封装） | 类型安全 |

> 本表为**初选（推荐稿）**。逐项市面候选对比、利弊与决策记录见[《技术选型》](./技术选型.md)（T-01~T-14）；**2026-09-29 已全部确认按推荐执行**（ADR D-12），Redis 客户端修正为 node-redis（ioredis 已转维护模式），Webview 组件库采用 shadcn/ui（M3 前接入脚手架）。

### 7.3 稳定性设计

| 风险 | 对策 |
|---|---|
| 驱动阻塞 Extension Host | 所有驱动调用强制超时 + AbortSignal（7.6）；进程隔离预案就绪（D-05） |
| 大结果集撑爆内存 | 分页 + 行数上限 + 流式导出 |
| 连接泄漏 | `ConnectionManager` 统一持有连接池，窗口关闭 / 插件 deactivate 时 `dispose()` |
| Webview 崩溃/重载 | `retainContextWhenHidden: true` + Host 快照恢复（5.4.5），ChangeSet 不丢 |
| 驱动异常 | 统一映射为 `DriverError`（错误码），UI 展示用户可读文案 + “查看详情”跳输出面板 |
| 激活耗时 | `activationEvents: onView` 懒激活；驱动按需 import，未用到的驱动不加载 |

### 7.4 Webview ↔ Extension RPC 协议（v0.2 新增）

#### 7.4.1 帧格式

单一 `postMessage` 通道，三类帧：

```ts
interface RpcRequest  { kind: 'req'; id: string; method: string; params?: unknown }
interface RpcResponse { kind: 'res'; id: string; ok: boolean; result?: unknown;
                        error?: { code: string; message: string; detail?: string } }
interface RpcEvent    { kind: 'evt'; event: string; payload?: unknown }   // Host → Webview 单向推送
```

- 请求超时：Webview 侧默认 30s，按 method 可覆盖（长交互 method 置 0 不设限：`console.execute` 靠事件推送保活、`export.run` 含 SaveDialog 用户交互——M8 起导出本体在 Host 后台执行，回执即时）
- 取消：`rpc.cancel(reqId)`，Host 转为 AbortSignal 下传驱动 → 驱动返回 `E_CANCELED`
- 错误码：复用 `DriverErrorCode`（含 `E_VALIDATION`），RPC 层仅另加 `E_UNKNOWN_METHOD`、`E_STATE_LOST`

#### 7.4.2 方法注册表（初始清单）

| method | 说明 |
|---|---|
| `sys.handshake` | Webview 就绪/重载恢复：入参 `{ stateId? }`，返回快照（视图参数 + ChangeSet + 选中态） |
| `table.fetchRows` | 分页取数（FilterCondition / sorts / search / cursor） |
| `table.previewChanges` | 生成将执行的 SQL 预览（与 applyChanges 同源） |
| `table.applyChanges` | 提交变更集 |
| `table.revertChanges` | 撤销全部/指定行 |
| `meta.getColumns` | 列元数据（列设置、编辑器类型渲染） |
| `export.run` / `export.cancel` | **M8 后台化**：run 在 SaveDialog 后立即回执 `{ exportId, canceled? }`，导出后台执行；cancel 按 exportId 取消任务 |
| `ddl.load` / `ddl.preview` / `ddl.execute` | **M8-B2 表结构编辑器（§5.9）**：载入当前结构（create 时空白）、生成语句预览（驱动 buildCreateTable/buildAlterTable，预览与执行同源）、逐条执行（失败即停 + 危险确认 + 缓存失效联动） |
| `console.execute` | 执行 SQL（结果面板 Webview） |
| `console.getState` | Console 状态（结果面板引导/恢复；consoleId 空 = 最近执行） |
| `conn.getStatus` | 连接状态（工具栏徽标） |

事件：`evt:changeset.updated`（N 变化，工具栏角标）、`evt:conn.status`、`evt:export.progress`（逐批行数/字节）、`evt:export.done`（M8：导出终态回执，成功/取消/失败三路）、`evt:row.error`（提交失败行定位）。

#### 7.4.3 校验与治理

- 消息 schema 定义在 `@db-explorer/protocol`（zod），**双端运行时校验**：Host 校验请求，Webview 校验响应
- 校验失败 → 返回 `E_VALIDATION` 并输出到日志通道，**不崩溃、不静默**
- 协议带 `protocolVersion`（handshake 协商），不兼容时 Webview 显示“插件与视图版本不一致，请重载窗口”

### 7.5 元数据缓存设计（v0.2 新增）

```
层次：connection → databases(60s) → objects(手动失效) → columns/keys/indexes(5min)
存储：内存 Map + TTL；不落盘（避免过期结构误导，P2 再评估 workspaceState 持久化）
```

> **持久化评估结论（M7 收尾，关闭遗留 #6）：维持内存 + TTL，不落盘。** 理由：① 离线浏览结构是低频场景，重连后元数据懒加载重建成本可接受；② 过期结构误导是真实风险（表结构已变而用户据旧结构写 SQL/编辑），持久化必须引入 staleness 语义，复杂度大于收益。未来若做（触发条件：离线浏览成为真实需求），形态限定为：workspaceState 按 `connId+db` 存 JSON（带 schema 版本 + 抓取时间戳），仅在连接失败时降级展示并明示「离线快照 · 抓取于 xx」。

| 事件 | 失效动作 |
|---|---|
| 树节点手动刷新 | 仅失效该子树 |
| 全局 Refresh | 清空全部缓存并重载展开路径 |
| Console 执行 DDL（AST 判定 CREATE/ALTER/DROP） | 失效该库 objects + 该表 columns，并联动树刷新 |
| applyChanges 成功 | 仅失效该表 `rowEstimate`（列结构未变） |
| 补全预热 | 打开 Console 后台拉取当前库表+列，显示“补全加载中”占位 |

并发防护：同一 key 的加载请求合并（in-flight dedup），避免展开一棵树触发 N 次相同查询。

### 7.6 进程隔离与阻塞防护（v0.2 决策 D-05）

- **抽象先行**：core 从 M0 起经 `DriverHost` 接口调用驱动（`InProcessDriverHost` 为默认实现），方法签名与 `IConnection` 一一对应，切换成本 ≈ 0
- **MVP 策略**：驱动运行在 Extension Host 进程内；所有调用强制超时（默认 15s）+ AbortSignal 取消
- **隔离预案**：`UtilityProcessDriverHost`（基于 `vscode.UtilityProcess`），触发条件（满足其一即评估切换）：
  1. 驱动 CPU 密集操作（大结果集解析/序列化）导致 UI 命令响应 P95 > 200ms
  2. 某驱动 native 依赖崩溃，进程内无法兜底
- 观测手段：遥测记录驱动调用耗时分布（遥测关闭时仅本地输出面板可见）

## 11. 关键决策记录（ADR，v0.2 新增）

> v0.1 第 11 章“开放问题”全部在此关闭。格式：决议 / 理由 / 代价与缓解。若后续推翻某条决策，在此追加记录，不改写历史。

### D-01 表格视图：Webview（React + TanStack Table）
- **决议**：Webview 实现，TreeView 不承担表格职能
- **理由**：排序/筛选/行内编辑/列冻结/虚拟滚动是网格能力，TreeView 无法承载（v0.1 的倾向项，正式确认）
- **代价与缓解**：需维护 webview-ui 包与 RPC 协议；Webview 资源全部本地打包（不走 CDN，CSP 收紧到 `default-src 'none'`），崩溃恢复由 Host 快照兜底（5.4.5）

### D-02 SQL Console：原生 Editor（MVP）+ 独立结果 Webview
- **决议**：方案 A；编辑器交互封装为 `ConsoleEditor` 门面，保留迁移 Monaco 的预案
- **理由**：免费获得语法高亮/主题/快捷键/IME 兼容；Monaco in Webview 的主题与快捷键维护成本高
- **代价与缓解**：结果无法默认内联在编辑器正下方——结果面板为 Webview Panel（用户可拖到下方编辑组），`Ctrl+Alt+R` 快速聚焦结果

### D-03 无主键表编辑：默认只读，可开关“全列匹配”
- **决议**：`dbExplorer.edit.allowNoPrimaryKey`（默认 false）；开启后以**全部列原始值**作 WHERE，affectedRows ≠ 1 即视为冲突回滚；含二进制列的表即使开启也不可编辑。**有主键表的乐观锁 WHERE = 主键 + 变更列原值**（字段级并发，评审确认：不同列的并发编辑互不冲突，同行同列可检出）；原值为 NULL 的列用 `IS NULL`；DELETE 仅按主键
- **理由**：无定位键的 UPDATE 本质是全表扫描级风险，默认必须关闭；开关满足“必须改”的场景
- **备注**：以 UNIQUE 索引作 RowKey 的增强放 P2 评估

### D-04 跨库 JOIN 补全：P2
- **决议**：M5 补全上下文解析仅处理单库 + 别名；跨库（`db.table.column`）放 P2
- **理由**：跨库需要一次性拉取多库元数据，预热成本高、命中率低

### D-05 驱动进程隔离：MVP 进程内 + DriverHost 抽象预留
- **决议**：M0 引入 `DriverHost` 抽象，默认进程内实现；满足 7.6 触发条件时切换 `vscode.UtilityProcess` 实现，驱动代码零改动
- **理由**：mysql2/pg/ioredis 均为纯 JS 异步 IO，真正阻塞 EH 的是 CPU 密集序列化，且导出已流式化；过早隔离增加调试与序列化成本
- **裁决时点**：M6（Redis 驱动接入后）复查
- **复核记录（2026-10-02，M6）**：按 §7.6 两个触发条件对 Redis 驱动实测，**结论：不启用 UtilityProcess，维持进程内实现**。实测（node-redis v5 / Redis 7.2 / 本机 localhost）：
  - 条件 1（CPU 密集序列化致 UI 命令 P95 > 200ms）：**未触发**——5 万 field hash 全量取数（最重的序列化场景）进行中，同进程模拟 UI 命令（PING）P95 = 0.3ms（空载基线同为 0.3ms）；1MB string Value 取回 7.5ms；hash 5000 行单页 17~33ms。await 边界让出事件循环，序列化不阻塞命令调度。
  - 条件 2（native 依赖崩溃）：**不适用**——node-redis 纯 JS、无原生模块（driver-mysql 的 mysql2 亦纯 JS）。
  - 复测入口：`D05_EVAL=1 npx vitest run packages/driver-redis/src/d05.eval.test.ts`（非门禁用例）。
  - 后续再评估触发点：新增 native 依赖的驱动接入（规范 §10），或引入同步/大缓冲驱动路径（如 SQLite 大库全表导出）时重跑本用例口径。
- **复核记录（2026-10-04，M7 收尾）**：批次 B/C 引入 ssh2 与 exceljs，按本记录口径复核：
  - 条件 2（native 依赖崩溃）：**不适用**——exceljs 纯 JS；ssh2 本体纯 JS，`cpu-features` 为可选 native 加速（try/catch require，缺省降级）且 esbuild 标 external，不构成强制 native 依赖。
  - 条件 1（CPU 密集序列化）：**未触发**——SSH 隧道（网络 IO）与 xlsx 流式写出（磁盘 IO）均为异步边界，不在事件循环热路径上做 CPU 密集序列化；导出管线维持批量生成器 + 背压。
  - 结论：**维持进程内实现**；下次复核触发点不变（新增 native 依赖的驱动接入）。
- **复核记录（2026-10-09，M8-SQLite）**：SQLite 驱动（D-16，sql.js 同步引擎）接入，D-05 此前预埋的「同步/大缓冲驱动路径」触发点到点复核。实测（sql.js 1.14 / 本机 arm64）：
  - 条件 2（native 依赖崩溃）：**不适用**——sql.js 为 WASM 纯 JS 加载 + .wasm 静态资产，无 .node 原生模块。
  - 条件 1（CPU 密集序列化致 UI 命令 P95 > 200ms）：**大结果集场景触发，常规路径未触发**——空载 ping P95 = 0.2ms；整库载入 6MB/40MB = 4.4/12.8ms；40MB 库 100 行写批次（含整库原子落盘）= 98.1ms；全表 COUNT(*) = 38.4ms，均远低于阈值。**5 万行单次取数 = 205.6ms 期间，调度的模拟 UI 命令体感延迟 P50 = 144.3ms / P95 = 234.5ms → 触发**（同步执行在微任务突发内完成，timer 类 UI 命令只能等事件循环空出）。
  - 结论：**维持进程内实现**，与 D-16 的工程约束配套生效——限用中小库（建议 ≤ 100MB）、表格取数恒带 LIMIT（分页量级阻塞窗口毫秒级）、默认不执行全表 COUNT（C-9）；5 万行级大结果集属导出/极端路径，非浏览主路径。若未来大库/大导出常态化，重评估 UtilityProcess（本 ADR 预留）。
  - 复测入口：`D05_EVAL=1 npx vitest run packages/driver-sqlite/src/d05.eval.test.ts`（非门禁用例）。

### D-06 RPC 协议：zod 双端运行时校验 + 类型单一来源
- **决议**：消息类型定义于 `@db-explorer/protocol`，TS 类型由 zod schema 推导（`z.infer`），双端运行时校验；ChangeSet 权威副本在 Host（4.5）
- **理由**：Webview 是不可信边界，且需防护协议版本漂移；单一来源避免类型与校验两套定义不一致

### D-07 开源与驱动分发：核心开源 + 三级接入
- **决议**：核心与官方驱动（monorepo）开源（Apache-2.0，评审确认）；社区驱动以独立扩展发布到 Marketplace，经 L2 配置或 L3 扩展点接入；不做“运行时 npm install”
- **理由**：VSCode 扩展沙箱不支持运行时装包；扩展化分发天然获得版本管理、签名与更新
- **影响**：L2/L3 激活时序、API 版本协商见[驱动规范 §9](./驱动开发规范.md)

### D-08 值编码契约（新增决策）
- **决议**：见 4.4——DECIMAL/BIGINT 超限用字符串、DATETIME 不含时区、二进制 base64、JSON 传对象
- **理由**：JS `number` 精度丢失与时区歧义是数据库工具最常见的数据 bug；契约层解决一次，全链路受益

### D-09 事务模型：短事务自动 + 交互式事务 P2
- **决议**：见 4.6——表格提交为驱动内部短事务；Console 手动事务 P2，且必须接受 SessionManager 空闲超时回收
- **理由**：避免长事务占用连接池与锁；交互式事务防遗忘机制是安全底线

### D-10 连接生命周期：懒连接 + 指数退避重连
- **决议**：见 5.2——激活不连库，操作时才连；`E_CONN` 自动重连退避
- **理由**：激活耗时与安全（不自动触碰生产库）双重要求

### D-11 运行时基线（新增决策）
- **决议**：`engines.vscode ^1.85`、Node ≥ 18、ES2022；仅桌面版（Web 版 P3，遗留 #1）；i18n 使用 `vscode.l10n`，M2 起中英双语
- **理由**：1.85 覆盖 UtilityProcess 与稳定的 SecretStorage API；桌面限定使驱动可自由使用原生模块
- **复核（2026-09-29）**：技术选型评审后确认维持 ^1.85（保守基线）；如需 `node:sqlite` 等 Node 20+ 能力再修订本条

### D-12 技术选型确认（2026-09-29）
- **决议**：T-01~T-14 全部按[《技术选型》](./技术选型.md)推荐执行。要点：pnpm monorepo、esbuild（扩展端）+ Vite（Webview）、React 18、TanStack Table + Virtual（网格）、**shadcn/ui（Base UI 基座，映射 `--vscode-*` 变量）**、Zustand、自研 RPC + zod、node-sql-parser + sql-formatter、驱动库 mysql2 / pg / **node-redis（修正，ioredis 已转维护模式）** / sql.js / ssh2、vitest + @vscode/test-electron、ESLint 9 + Prettier、Actions + vsce + changesets
- **理由**：详见《技术选型》各项对比与已核实的市场事实

### D-13 执行计划可视化形式（M7 批次 C，关闭遗留 #2）
- **决议**：**表格 + 树形缩进**（复用 Console 结果面板），不做火焰图/独立图形视图。Console 检测 `EXPLAIN` 语句：MySQL 表格式 EXPLAIN 按结果集 `id` 列推导层级（id 升序为嵌套深度），首列渲染树形缩进前缀；其余驱动/形状退化为普通表格
- **理由**：EXPLAIN 产出的本质是行集，表格承载信息密度最高且复用现有虚拟网格（零协议/驱动改动）；火焰图需要运行时采样数据（EXPLAIN 不提供），属过度设计；独立图形视图的布局成本高、收益低
- **代价与缓解**：嵌套推导对复杂子查询的层级表达有限——后续若需精确结构，按驱动增加 `getPlan(db, sql)` 可选方法（结构化 plan JSON），本决议不阻塞该演进

### D-14 Excel 导出选型：exceljs（M7 批次 C，关闭遗留 #4）
- **决议**：**exceljs**（MIT），流式写（`WorkbookWriter`）接入 §5.7 导出管线；格式枚举 `xlsx` 加入 export.run / console.export
- **理由**：MIT 许可无授权疑虑；npm 正常分发、API 稳定；`WorkbookWriter` 逐行落盘，与既有流式导出架构（大结果集不 OOM）同构。SheetJS 社区版自 0.18 起官方 npm 停更、转为自有渠道分发 tarball，供应链与升级路径不可控（授权差异之外的实际决定性因素）
- **代价与缓解**：exceljs 已转维护态（低频修复）——xlsx 写出路径隔离在独立模块（xlsxWriter），后续可替换实现而不动导出管线

### D-15 PG schema 上树：schema 映射 database 层（M8-PG，2026-10-06）
- **决议**：PostgreSQL 驱动的 `listDatabases()` 返回连接库内**非系统 schema**（排除 `pg_*` 前缀与 `information_schema`），树 database 层即 schema；`IConnection` 全部方法的 `db` 参数在 PG 驱动 = **schema 名**，`obj` 恒为裸表/视图名；SQL 生成对对象引用显式 `"schema"."table"` 限定（PG 连接协议绑定单库，无跨库语义）；连接表单「默认库」= 连接字符串真库名，经 FormSchema hint 与树上「库」（schema）消歧
- **理由**：① Host 侧删表路径按 `q(db).q(obj)` 生成（ddlService），本方案恰好输出合法 PG `DROP TABLE "schema"."t"`——PG 无三段名，folder 方案下该路径生成非法语句；② 核心/树/RPC/Console 绑定/补全/元数据缓存零改动，菜单 when 子句零新增 contextValue（P-40 风险归零）；③ `obj` 恒为裸名，无 `schema.table` 全限定名拆分，含点标识符（`"a.b"`）天然安全；④ PG 单连接恒绑定一个数据库，真实库名不因映射丢失（连接节点 tooltip 展示）
- **代价与缓解**：`DatabaseMeta` 在 PG 驱动承载 schema（语义注记写入驱动规范 §3/§5.2，树节点 description 可标注）；用户手写未限定语句依赖 search_path——`QueryRequest.db` ≠ 默认 schema 时经池内专用连接 `SET search_path` 后执行、用毕 RESET（P-36 同族防池污染）；系统 schema 硬过滤，如需浏览系统表后续加配置开关（P2）
- **否决案（folder 节点）**：库下加 schema folder 层 + `obj` 全限定名——树多一层、Host 删表/`TableSpec.name` 均需处理点号拆分或驱动接管删表，改动面与边角风险显著更大，收益仅为多展示一层真实库节点（PG 单连接恒一库，无信息增量）

### D-16 SQLite 执行引擎与持久化：sql.js（WASM）单引擎 + 写批次原子落盘（M8-SQLite，2026-10-09）
- **决议**：SQLite 驱动采用 **sql.js（WASM）单引擎**——整库载入内存执行，**限用中小库（建议 ≤ 100MB）**；同步执行：`supportsCancel = false`（契约组自动跳过取消组）、`supportsMultiStatement = false`（Console 按 Host 切分单语句执行）。持久化：**每个写批次后原子落盘**（序列化整库字节 → 写临时文件 → rename 覆写；applyChanges 批次 / Console 写语句批次 / 交互式事务 commit 各为一个批次，只读连接与未提交会话不落盘）。树层级（§5.1.3）：`listDatabases()` 恒返回单节点 `main`（SQLite 逻辑主库，ATTACH 附加库为后续扩展口），`db` 参数恒为 `main`；连接表单「数据库文件路径」为 string 字段（支持 `~/` 与相对工作区路径，文件必须已存在不自动创建）；无认证字段、不涉 SecretStorage。
- **理由**：零 native 依赖——D-05 条件 2（native 崩溃）不适用，VSIX 保持平台无关（.wasm 为静态资产随包分发，无 Electron ABI 重编译/平台分包），且 sql.js 本就是 D-12 驱动清单列项；引擎与内嵌 SQLite 版本随驱动固定（sql.js 1.14 内嵌 SQLite 3.49），不随宿主 VSCode 的 Electron/Node 版本漂移，行为矩阵可测可控；「编辑即持久」由写批次落盘保障，符合数据库工具「提交即落盘」的用户预期。
- **node:sqlite 可行性结论（2026-10-09，用户裁决收口）**：新版宿主（Electron 35+ / Node ≥ 22.14）探测可用、API 面实测够用（BigInt 通道/数组行/只读打开均验证通过），但 **不作直接依赖**——① D-11 基线 `engines.vscode ^1.85`（Node 18）宿主完全缺失该模块，直接依赖即崩溃，留用则必然引入兜底第二引擎；② Node 22.x 仍标 experimental，特性跨版本漂移（BigInt 通道/数组行/列名 API 需逐一特性探测）；③ 内嵌 SQLite 版本随宿主漂移，行为矩阵不可控。
- **代价与缓解**：① 同步执行阻塞 Extension Host、不可中断——中小库与常规语句阻塞窗口为毫秒~百毫秒级；重查询（大库加载/全表扫描）期间 UI 命令排队，量化复核按 D-05 口径实跑（复核记录随后续批次提交追加）；缓解 = docs 声明限用中小库、fetchRows 恒带 LIMIT、默认不执行全表 COUNT（C-9）；未来若需大库支持，重评估 UtilityProcess（D-05 预留口子）或 better-sqlite3（触发 D-05 条件 2 复核 + VSIX 平台分包）。② 整库驻留内存 + 写放大（每次落盘序列化整库字节）——按批次合并落盘、原子覆写（temp+rename）防半写损坏；落盘耗时随库体积线性，由「限中小库」口径覆盖。
- **否决案**：better-sqlite3（native：D-05 条件 2 复核 + Electron ABI 重编译 + VSIX 平台分包三重成本，收益仅真流式大库——当前限中小库口径下不需要）；`node:sqlite` 直接依赖（见上「可行性结论」）；「node:sqlite 优先 + sql.js 兜底」双引擎（本条修订前的草案：为单一优化点维护两套引擎路径与双份契约面，复杂度不成比例，否决）。
- **修订记录**：2026-10-09——初版（同批次 c89d43f）曾定为「node:sqlite 优先 + sql.js 兜底」双引擎；经用户裁决（评估 node:sqlite 直接依赖可行性后）收口为**仅 sql.js 单引擎**，本条按最终决议改写并在此注记历史（ADR 不改写原则下的修订留痕）。

## 12. 测试与验收策略（v0.2 新增）

### 12.1 分层
| 层 | 工具 | 范围 |
|---|---|---|
| 单元测试 | vitest | core 服务（mock 驱动）、protocol schema、SQL 切分/危险判定 |
| 驱动契约测试 | `driver-conformance`（自研套件） | 所有驱动必须通过的行为集（12.2），跑真实库（docker） |
| 集成测试 | docker-compose 起 MySQL/PG/Redis | 核心服务与真实驱动联合 |
| e2e | @vscode/test-electron | 关键用户旅程，CI 仅用 sqlite 驱动（零网络依赖） |

### 12.2 驱动契约测试（必过清单，节选）
1. 连接：错误密码 → `E_AUTH`；不可达 → `E_CONN`
2. 元数据：列含 PK 标记、ordinal 有序；索引/键可列出
3. 分页：offset 翻页结果稳定（按 PK 排序）；`totalCount` 可缺省
4. 筛选下推：每种 `FilterOp` 生成**参数化**语句，结果与内存过滤一致
5. 变更集：insert 回填生成主键；update 冲突 → `E_CONFLICT` 且事务回滚（无半提交）；含 NULL 原值的行正确生成 `IS NULL` 匹配
6. 取消：AbortSignal 生效 → `E_CANCELED`
7. 值编码：每种 `NormalizedType` 写入→读出往返一致（4.4 契约）

套件提供 `runDriverConformanceSuite({ createConnection })`，各驱动在自己的 CI 中调用。

### 12.3 安全用例（专项）
- 全文检索仓库与导出文件：不得出现明文密码/DSN（含错误信息路径）
- 只读连接：穷举所有写入口（表格/Console/树操作）均被 Host 层拒绝
- prod 连接：所有危险路径均触发确认，且无法通过改配置绕过

### 12.4 性能回归
第 9 章指标落为 `perf/` 基准脚本（sqlite + 本地 MySQL 容器），每次 release 前跑一轮，超基线 20% 阻断。

### 12.5 兼容性矩阵
VSCode Stable / Insiders × Win / macOS / Linux（Remote-SSH 场景列入 M7 验证）。
CI 矩阵：契约测试仅 Linux runner（docker 依赖）；M6 起 CI 内置 `redis:7` service ×2（常规 + requirepass），覆盖 Redis 契约（评审 P2-3 落地）；M8-PG 起增补 `postgres:16` service，覆盖 PostgreSQL 契约（本地无实例，`PG_HOST` 等环境变量门控：本地 skip、CI 实跑——见驱动规范 §11）；e2e 覆盖三平台，使用 sqlite 驱动（零网络依赖）。
