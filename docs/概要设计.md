## 1. 背景与目标

### 1.1 背景
日常开发中，查看/修改数据库需要频繁在 IDE 与数据库客户端（Navicat / DBeaver / DataGrip / RedisInsight）之间切换，存在：
- 上下文割裂：表名、字段名、SQL 语句要手动复制粘贴
- 无代码补全：编写 SQL 时没有表结构提示
- 修改数据风险不可控：多数客户端直接落库，缺少“暂存 - 预览 - 提交”的安全流程

### 1.2 产品目标
在 VSCode 内提供**统一的、可插拔的数据库访问入口**，覆盖“看结构 → 查数据 → 改数据 → 写 SQL”的完整链路。

### 1.3 核心价值主张
| 价值 | 说明 |
|---|---|
| 不离开 IDE | 侧边栏树 + 表格视图 + SQL Console 全部内嵌 |
| 可插拔驱动 | 新增数据库类型不改动核心代码 |
| 安全编辑 | 表格改动先暂存，显式提交才落库，支持事务回滚 |
| 上下文感知 | SQL 补全感知当前连接 / 库 / 表 / 字段 |

### 1.4 非目标（本期不做）
- 数据库运维（备份、主从、监控、慢日志分析）
- 数据可视化 BI 报表
- 团队协作 / 云端连接同步
- 完整 DDL 建模器（ER 图设计器）
- **Web 版 VSCode（github.dev）支持**：桌面端 MVP 优先，Web 端需代理层，见遗留问题 #1

### 1.5 术语表
| 术语 | 含义 |
|---|---|
| 驱动（Driver） | 实现统一接口的数据库适配器，负责方言翻译 |
| ChangeSet | 表格编辑的暂存变更集，提交前不落库 |
| RowKey | 行定位键（主键列值集合），见 4.3 |
| Session | 有事务上下文的数据库会话 |
| capabilities | 驱动能力声明，UI 据此降级渲染 |
| L1/L2/L3 | 驱动接入的三种方式，见 5.1.2 |

## 3. 产品整体架构

```
┌─────────────────────────────────────────────────────────────────┐
│                          表现层 (UI)                              │
│  ┌──────────────┐  ┌────────────────────┐  ┌─────────────────┐  │
│  │ 资源树        │  │ 表格视图/结果面板    │  │ SQL Console     │  │
│  │ (TreeView)   │  │ (Webview: React)   │  │ (原生 Editor)   │  │
│  └──────┬───────┘  └────────┬───────────┘  └────────┬────────┘  │
└─────────┼──────────────────┼─────────────────────────┼─────────┘
          │ TreeData          │ RPC（zod 校验，见 7.4）   │ Completion
          └────────────┬─────┴──────────────────────────┘
                       ▼
┌─────────────────────────────────────────────────────────────────┐
│                   核心服务层 (Extension Host)                      │
│  ConnectionManager  │ DriverRegistry │ DriverHost(隔离抽象)        │
│  MetadataCache      │ ChangeSetService(权威副本) │ SessionManager │
│  QueryService       │ ResultExporter │ DangerGuard              │
│  CompletionProvider │ SecretStore │ Telemetry(默认关闭)          │
└───────────────────────────┬─────────────────────────────────────┘
                            ▼  IDatabaseDriver（apiVersion=1，见驱动规范）
┌─────────────────────────────────────────────────────────────────┐
│                驱动抽象层（可插拔、错误码统一）                       │
│  mysql-driver │ redis-driver │ pg-driver │ sqlite-driver …      │
└───────────────────────────┬─────────────────────────────────────┘
                            ▼
                   数据源 / SSH 隧道 / 代理
```

**分层原则**
1. UI 层不感知具体数据库类型，只消费 `TreeNode` / `ResultSet` / `ChangeSet` 等**统一模型**
2. 驱动层只负责“翻译”，不含 UI 逻辑；所有驱动调用经 `DriverHost` 中转（见 7.6），便于未来进程隔离
3. 能力差异（如 Redis 无表概念）通过 `capabilities` 声明，UI 据此降级渲染
4. **ChangeSet 的权威副本在 Extension Host**，Webview 只持编辑视图——Webview 崩溃/重载不丢编辑（见 5.4.5）
5. 所有跨层错误携带统一错误码（`DriverErrorCode`），UI 只认错误码不解析消息文本

## 4. 核心概念与数据模型

### 4.1 连接配置

```ts
interface ConnectionConfig {
  id: string;                 // uuid
  name: string;               // 显示名 "本地 MySQL"
  driverId: string;           // 'mysql' | 'redis' | ...
  group?: string;             // 分组（可选）
  color?: string;             // 标识色，用于区分环境
  readOnly?: boolean;         // 只读保护
  env?: 'dev' | 'test' | 'prod';
  options: Record<string, any>; // 驱动专属：host/port/user/database/...

  ssh?: SshTunnelOptions;

```

> **密码永不落盘到 settings.json**，统一存 `vscode.SecretStorage`。连接配置本体存 `globalState`，导出时密码以 `${secret}` 占位。

### 4.2 统一元数据模型

```ts
interface DatabaseMeta {
```

### 4.3 结果集模型

```ts
interface ResultSet {
  columns: { name: string; type: NormalizedType }[];
  rows: unknown[][];              // 行式存储，减少 webview 序列化开销
  rowCount: number;
  totalCount?: number;            // 分页总数（可能为 undefined，避免全表 count）
  primaryKey?: string[];          // 用于编辑定位（RowKey）；为空则默认只读
  nextCursor?: string;            // pagination=cursor 时由驱动返回
  affectedRows?: number;          // 非 SELECT 语句
  messages?: string[];            // 警告/提示（如 MySQL Notes）
  executionMs: number;
  truncated?: boolean;            // 是否因行数上限被截断
}

// RowKey = 主键列名 → 值 的映射，如 { id: 42 }
// 编辑定位一律使用 RowKey，不使用行号（分页翻页后行号失义）
```

### 4.4 值编码契约（v0.2 新增，关键）

Webview 与 Extension Host 之间、编辑回传与驱动参数之间，值的表示**统一遵循下表**，避免 JS number 精度丢失与时区歧义。完整类型映射示例（MySQL / PG / Redis 逐类型展开）见[《驱动开发规范》§5](./驱动开发规范.md)。

| 场景 | 传输表示 |
|---|---|
| NULL | `null`（与空串 `''` 严格区分，UI 提供切换） |
| 整数 | `number`；超出 `Number.MAX_SAFE_INTEGER` 一律按 `decimal` 字符串处理 |
| DECIMAL / NUMERIC / BIGINT 超限 | `string`（原样保留精度） |
| 浮点 | `number` |
| 布尔 | `boolean` |
| DATE | `'YYYY-MM-DD'` |
| TIME | `'HH:mm:ss.SSS'` |
| DATETIME / TIMESTAMP | `'YYYY-MM-DD HH:mm:ss.SSS'`（不含时区，按连接会话时区渲染，tooltip 标注） |
| JSON | 已解析的对象/数组（非字符串） |
| BINARY / BLOB | base64 字符串，配合列类型 `binary` 解释为 hex / 图片 / 文件 |
| 超长单元格（> cellMaxChars） | 占位符 + 按需 `fetchCell` 拉取（需驱动 `lazyCell` 能力） |

`NormalizedType`（v0.2 扩展）：

```ts
type NormalizedType =
  | 'string' | 'integer' | 'decimal' | 'float' | 'boolean'
  | 'date' | 'time' | 'datetime' | 'json' | 'binary' | 'uuid' | 'unknown';
```

### 4.5 变更集模型（表格编辑核心）

```ts
interface ChangeSet {
  inserts: Array<{ tempId: string; values: Record<string, unknown> }>;
  updates: Array<{
    rowKey: Record<string, unknown>;         // 主键值
    original: Record<string, unknown>;       // 原值（用于乐观并发校验）
    changes: Record<string, { old: unknown; new: unknown }>;
  }>;
  deletes: Array<{ rowKey: Record<string, unknown>; original: Record<string, unknown> }>;
}
```

> **权威副本规则（v0.2 决策 D-06）**：ChangeSet 单一事实源在 Extension Host 的 `ChangeSetService`。Webview 本地缓存用于低延迟编辑（单元格编辑即时生效），并以 300ms debounce 同步到 Host；Webview 重载后凭 `stateId` 从 Host 恢复，编辑不丢失。

### 4.6 事务会话模型（v0.2 决策 D-09）

| 事务形态 | 触发方式 | 生命周期 | 阶段 |
|---|---|---|---|
| 短事务 | `applyChanges` 内部自动 BEGIN…COMMIT/ROLLBACK | 单次提交，毫秒~秒级 | M4 |
| 交互式事务（手动） | Console 显式 BEGIN / COMMIT / ROLLBACK | 跨语句，由 `SessionManager` 管理 | P2 |

交互式事务约束：`SessionManager` 强制空闲超时（默认 5min，超时自动 ROLLBACK 并释放连接）；单连接同时最多 1 个交互式会话；持有交互式会话的连接在树上显示“事务进行中”徽标，防止用户遗忘。

## 5. 功能模块详设

### 5.1 驱动插件体系（可插拔）

> 本节为概要；接口全集、错误码规范、值编码映射、打包加载细则统一收敛到[《驱动开发规范》](./驱动开发规范.md)，此处不重复。

#### 5.1.1 驱动接口（概要）

```ts
export interface IDatabaseDriver {
  readonly id: string;                  // 'mysql'
  readonly displayName: string;         // 'MySQL'
  readonly icon?: string;
  readonly apiVersion: number;          // 与核心协商，当前 = 1
  readonly capabilities: DriverCapabilities;
  getConnectionFormSchema(): FormSchema;
  testConnection(cfg: ConnectionConfig, secret: string): Promise<TestResult>;
  connect(cfg: ConnectionConfig, secret: string): Promise<IConnection>;
}
```

`IConnection` 提供：元数据自省（库/对象/列/键/索引）、分页取数 `fetchRows`、SQL 执行 `query`、变更提交 `applyChanges`、**变更预览 `previewChanges`（v0.2 新增，与 applyChanges 同源生成 SQL，保证“预览即执行”）**、可选 `fetchCell` / `openSession` / `getCompletionSource`。完整签名见[驱动规范 §3](./驱动开发规范.md)。

#### 5.1.2 驱动注册方式（三级可扩展）

| 级别 | 方式 | 适用场景 |
|---|---|---|
| L1 | 内置驱动（monorepo 内静态注册） | 官方维护 MySQL / Redis / PG / SQLite |
| L2 | 配置项加载驱动扩展：`dbExplorer.drivers = ["acme.db-mongo"]` | 用户按需安装的第三方驱动扩展 |
| L3 | 扩展激活后经核心导出 API 注册（`contributes.databaseDrivers` 声明元数据 + `extensionDependencies` 保证激活顺序） | 驱动与其它功能打包在一起的插件 |

> **id 唯一性**：`DriverRegistry.register()` 校验 `driverId` 全局唯一，冲突时拒绝后注册者，Toast 指明来源（内置驱动 / 扩展 ID + 版本）。
> **验收标准**：新增一个 SQLite 驱动，只需实现 `IDatabaseDriver` + 声明，**核心代码 0 改动**。
> L2/L3 激活时序、版本协商细节见[驱动规范 §9](./驱动开发规范.md)（对应决策 D-07）。

#### 5.1.3 能力差异处理（以 Redis 为例）

| 层级 | MySQL | PostgreSQL（D-15） | SQLite（D-16） | Redis | MongoDB（D-17） | Oracle（D-23） |
|---|---|---|---|---|---|
| 一级 | 连接 | 连接 | 连接 | 连接 | 连接 | 连接（绑定单个 PDB，service 寻址） |
| 二级 | Database | Database（= schema，非系统 schema 列表） | Database（恒为 `main` 单节点） | Database (0-15) | Database（非系统库，排除 `admin`/`config`/`local`） | Database（= schema，ALL_USERS 排除 oracle-maintained，当前用户首位） |
| 三级 | 表 / 视图 目录 | 表 / 视图 目录 | 表 / 视图 目录 | Keys 目录（可按类型/前缀分组） | collection 目录（单目录） | 表 / 视图 目录 |
| 四级 | 表 / 视图 | 表 / 视图 | 表 / 视图 | Key | collection | 表 / 视图 |
| 五级 | 列 / 键 / 索引 目录 | 列 / 键 / 索引 目录 | 列 / 键 / 索引 目录 | — | 字段 / 索引 目录（字段目录 = 采样推断顶层字段） | 列 / 键 / 索引 目录 |
| 六级 | 具体列 | 具体列 | 具体列 | — | 具体字段（列节点，采样类型标注） | 具体列 |

> PG 驱动（M8-PG）按 D-15 将 schema 映射到树 database 层：PG 连接协议绑定单库，`listDatabases()` 返回连接库内非系统 schema，各接口 `db` 参数 = schema 名、`obj` 恒为裸表名——核心/树/RPC 零改动（详见 ADR D-15 与驱动规范 §5.2）。
>
> SQLite 驱动（M8-SQLite）单文件单库：`listDatabases()` 恒返回 `[{ name: 'main' }]`（SQLite 逻辑主库，ATTACH 附加库为后续扩展口），各接口 `db` 参数恒为 `main`、`obj` 为裸表/视图名（sqlite_master 自省，排除 `sqlite_%` 内部对象）——树/协议同样零改动（详见 ADR D-16 与驱动规范 §5.4）。
>
> MongoDB 驱动（M8-Mongo）按 D-17 只读浏览：`db` 参数 = database 名、`obj` = collection 名；**列集由采样推断（动态列）**——采样顶层字段并集，`_id` 恒为首列，`listColumns` 与 `fetchRows` 的列集随采样波动是文档模型的既定口径（详见 ADR D-17 与驱动规范 §5.5）；collection 节点经 `capabilities.hierarchy` 含 `column` 声明展开「字段/索引」目录（树数据驱动，无数据源硬编码）。

UI 通过 `capabilities.hierarchy` 决定渲染哪些层级，**不做硬编码**。

> Redis 类非 SQL 数据源：`supportsSQL = false` 仅关闭 SQL 补全/格式化与危险 SQL 判定；仍提供**命令控制台**（复用 Console UI 与结果面板），危险判定改用命令白名单（见驱动规范 §5.3；MongoDB 同构，命令域为 mongosh，见驱动规范 §5.5）。

| 导入/导出连接配置 | 导出不含密码（`${secret}` 占位） | P2 |

#### 连接生命周期（v0.2 决策 D-10）
- **懒连接**：树上的连接节点默认“未连接”态，展开/查询时才建立连接；插件激活时不自动连任何库
- **断线处理**：驱动调用失败若错误码为 `E_CONN`，节点转为“已断开”，下次操作自动重连；空闲 `ping` 检测间隔 60s（可关）
- **重连退避**：自动重连指数退避（1s/2s/4s，上限 3 次），期间 UI 明示“重连中”，避免请求风暴
- **密码获取**：连接时经 `secretRef` 从 SecretStorage 取回；取不到（如导入的配置）→ 弹一次性输入框，不暴露错误堆栈
- **密钥生命周期**：`secretRef` 统一命名 `dbExplorer.secrets.<connId>`；删除连接时同步删除对应 SecretStorage 条目（防孤儿密钥）；复制连接经 SecretStorage API 迁移密钥，明文不出现在剪贴板/日志/导出文件

### 5.3 数据库资源树（侧边栏）

#### 5.3.1 层级结构

```
▾ 🟢 本地 MySQL (connection)
  ▾ 📁 information_schema (database)
    ▾ 📂 表 (table)              ← 目录节点
      ▸ 📋 users                 ← 表
      ▸ 📋 orders
    ▾ 📂 视图 (view)             ← 目录节点
      ▸ 👁 v_user_summary
  ▾ 📁 myapp
    ▾ 📂 表
      ▾ 📋 users
        ▾ 📂 列 (column)
          • id          bigint  PK  NOT NULL
          • name        varchar(64)    NULL
          • email       varchar(128)
        ▾ 📂 键 (key)
          • PK  id
          • FK  role_id → roles.id
        ▾ 📂 索引 (index)
          • idx_email  (email)  UNIQUE
```

#### 5.3.2 实现方式

采用 **VSCode 原生 `TreeDataProvider`**（非 Webview），理由：
- 天然支持懒加载 `getChildren`、右键菜单 `contributes.menus`、`view/item/context`
- 性能好（万级节点虚拟滚动）
- 与 VSCode 主题 / 折叠 / 键盘导航一致

```ts
interface DbTreeNode {
  id: string;                       // 稳定唯一 id，用于 expand 状态持久化
  type: 'connection'|'database'|'folder'|'table'|'view'|'column'|'key'|'index';
  label: string;
  description?: string;             // 右侧灰色描述，如 "bigint PK"
  tooltip?: vscode.MarkdownString;
  collapsibleState: vscode.TreeItemCollapsibleState;
  contextValue: string;             // 控制右键菜单显示
  iconId: string;                   // 主题图标
  payload: Record<string, any>;     // 定位信息：connId/db/table/column...
}
```

#### 5.3.3 懒加载策略

| 节点 | 加载时机 | 缓存 TTL |
|---|---|---|
| 连接（列表） | 视图激活（仅列表，不建立 DB 连接） | 常驻 |
| Database 列表 | 展开连接 | 60s |
| 表/视图目录 | 展开 database | 常驻（手动刷新才失效） |
| 表列表 | 展开“表”目录 | 60s |
| 列/键/索引 | 展开表 | 5min |

- 展开中的节点显示 `loading~` 占位（VSCode `TreeItem` 支持）
- 全局 `Refresh` 按钮清空缓存并重载当前展开路径
- 缓存实现细节见 7.5

#### 5.3.4 树节点操作（右键菜单）

| 节点类型 | 操作 | 快捷键 |
|---|---|---|
| connection | 连接/断开、刷新、编辑、复制、删除、**新建库（M8-DBDDL，D-19，按驱动能力）**、新建查询、打开 Console | — |
| database | 刷新、**编辑库 / 删除库（M8-DBDDL，D-19，按驱动方法存在性显隐）**、新建查询（USE 该库）、设为默认库、生成 DDL、**新建表（M8-B2，§5.9）** | — |
| table | **打开表格视图**（单击默认行为）、查看 DDL、**修改表结构（M8-B2，§5.9）**、复制表名、生成 SELECT、**删除表（M8-B2，§5.8 确认 Modal）**、导出 | Enter / 双击 |
| view | 打开数据、查看 DDL、复制名称 | — |
| column | 复制列名、复制 `a.b`、复制为 WHERE 条件、设为筛选、**编辑列 / 新增列 / 删除列（M8-B2，§5.9；确认后直删）** | — |
| index/key | 查看详情、删除索引 | — |
| 空白区 | 新建连接、刷新全部、折叠全部 | — |

> M8-B2 修订（v0.2.5）：表目录/列目录节点只有「新建表/新增列」；「清空表」移除（v0.2.2 设计稿曾含，实机复核裁撤）。
>
> M8-DBDDL（v0.2.21，D-19）：库级操作按驱动能力显隐——MySQL 建/改/删库、PG 建/删 schema、Mongo 删库（matrix 见 ADR）；新建/编辑走 Webview 动态表单弹窗（驱动自定义字段），删除走树右键名称确认（prod 分级同 §5.8）；只读连接一律拒绝。

**危险操作保护**：`DROP TABLE` / `DELETE` / `TRUNCATE` 走统一 `DangerGuard.confirmDangerousAction()`（见 5.8）。

#### 5.4.2 工具栏功能

| 分组 | 功能 | 说明 |
|---|---|---|
| 数据操作 | 新增行、删除选中行、刷新 | 新增/删除先进入 ChangeSet |
| 提交 | **提交变更 (N)**、撤销全部 | 有未提交变更时高亮闪烁 |
| 查询 | 关键字全局搜索、列筛选、排序 | 服务端下推 WHERE / ORDER BY（结构化 FilterCondition，见驱动规范 §4） |
| 导出 | CSV / JSON / Markdown / SQL INSERT / Excel | 支持“当前页/全部结果/选中行”，走统一导出服务（5.7） |

| 高级 | 生成 SELECT、打开 SQL Console（带当前筛选）、复制为 IN 列表 | — |
| 性能 | 只取前 N 行（默认 1000，可配）、超时设置 | 防止大表卡死 |

#### 5.4.3 编辑与提交（核心流程）

```
用户编辑单元格
   ↓
前端写入本地 ChangeSet（300ms debounce 同步到 Host 权威副本），单元格标黄
   ↓
用户点击 [提交变更 (N)]
   ↓
Host 调用 connection.previewChanges() → 弹窗预览：将执行的 SQL/命令（可折叠，参数化占位）
   ↓
用户确认 → 调用 connection.applyChanges()
   ↓
驱动在【单个事务】内执行：
   - 无主键表：默认只读；开启“全列匹配模式”后用全部原始列做 WHERE（决策 D-03）
   - UPDATE 的 WHERE = 主键 + 变更列原值（字段级并发，评审确认）；原值为 NULL 的列用 IS NULL；DELETE 仅按主键
   - 任一语句 affectedRows ≠ 预期 → 抛 E_CONFLICT，中止并回滚
   ↓
成功 → 清空 ChangeSet，刷新当前页，Toast “已提交 3 条变更”
失败 → 事务回滚，ChangeSet 保留，错误行高亮（错误码 → 文案），提供“重试/放弃”
```

**规则约束**
| 场景 | 处理 |
|---|---|
| 表无主键 | 默认只读；设置 `dbExplorer.edit.allowNoPrimaryKey` 开启“全列匹配模式”并显示风险提示（D-03） |
| 字段为 BLOB / 二进制 | 只读展示，点击弹出十六进制/图片预览 |
| 字段为 JSON | 单元格内可展开格式化编辑 |
| 字段超长文本 | 单元格显示截断，点击弹出大文本编辑器（`lazyCell` 按需拉取） |
| NULL vs 空串 | 区分标识，右键可切换为 NULL（见交互稿 §4.5） |
| 只读连接 | 所有编辑入口置灰，Tooltip 说明原因 |
| 生产环境 | 提交前强制输入表名确认（5.8） |

#### 5.4.4 大数据量性能

- 服务端分页（`LIMIT/OFFSET` 或游标），**默认不执行 `COUNT(*)`**，用估算或显示“≥ N 行”
- 行数据以数组形式传输（非对象），减少 50%+ 序列化体积
- Webview 侧使用虚拟滚动（只渲染可视区 ~40 行）
- 单次传输上限 5000 行 / 5MB，超出截断并提示

#### 5.4.5 ChangeSet 权威副本与崩溃恢复（v0.2）

- Host 端 `ChangeSetService` 以 `viewId → ChangeSet` 持有权威副本；Webview 编辑消息 debounce 300ms 上行
- Webview 重载（崩溃/后台释放）→ 发送 `sys.handshake { stateId }` → Host 回放快照（当前筛选、分页、ChangeSet、选中态）
- 关闭表格视图且存在未提交变更 → 确认弹窗“放弃 N 条未提交变更？”，防止误关丢失

#### 5.5.3 补全实现

```ts
vscode.languages.registerCompletionItemProvider('sql', {
  async provideCompletionItems(doc, position) {
    const ctx = parseContext(doc, position);   // 解析出 db / 表 / 别名 / 前缀（单库范围，D-04）
    const src = await metadataCache.getCompletionSource(ctx.connectionId, ctx.db);
    return [
      ...src.keywords,        // SELECT / FROM / WHERE ...
      ...src.functions,       // COUNT / NOW / JSON_EXTRACT ...
      ...src.databases,       // 库名
      ...src.tables,          // 表名（带 description: 注释）
      ...src.columns.filter(c => c.table === ctx.table),  // 按上下文过滤
      ...src.snippets,        // 代码片段
    ];
  }
});
```

**补全作用域（评审修订 P1-1）**：provider 内部按文档绑定过滤——仅绑定了连接的 Console 文档返回库/表/列补全；用户自己的普通 `.sql` 文件给关键字 + 常用标准函数 + 通用片段（不含连接元数据），状态栏提示“未绑定连接，点击选择”；文件级关联持久化放 P2。

**词表与排序（v0.2.10，排序口径 v0.2.12 调整）**：方言关键字/函数为全量常用面（各驱动 `completion.ts` 纯数据：MySQL 含窗口函数/CTE/UPSERT/JSON，PG 含 ON CONFLICT/RETURNING/JSONB/数组）；补全片段经 `CompletionSource.snippets` 下发（通用片段 + 方言片段）；**排序关键字置顶**（列位：关键字→列→函数；任意位：关键字→表/列→片段→函数→库；表位保持表/库优先），extension 按序号生成 sortText，防 VSCode 按字母重排。

**上下文感知规则**
| 光标位置 | 优先补全 |
|---|---|
| `SELECT ` 后 | **关键字置顶（v0.2.12）**、列名（当前 FROM 表）、函数、`*` |
| `FROM ` 后 | 表名、视图名、库名 |
| `别名.` 后 | 该别名对应表的所有列 |
| `WHERE ` 后 | **关键字置顶（v0.2.12）**、列名 + 运算符 |
| `JOIN ` 后 | 表名 |
| `CALL ` 后 | 存储过程名 |

> v0.2.11 注：列上下文（`SELECT … FRO`、`… WHE`、`x = 1 AN` 等最高频书写位置）原只出列+函数，关键字零提示——现补齐。v0.2.12 注：排序按用户口径调整为**关键字置顶**（列位与任意位），前缀过滤保证精准命中不受排序影响。

**元数据缓存**：进入 Console 时预热当前库的表 + 列；DDL 变更后失效联动（7.5）。

### 5.7 导出服务（v0.2 新增）

导出不在 Webview 内做（避免阻塞 UI 与 OOM），统一由 Host 端 `ResultExporter` 执行：

```
Webview: export.run { viewId, format, scope: 'page'|'result'|'selection' }
   ↓
Host: withProgress('导出中...') + 可取消（AbortSignal）
   循环：fetchRows(分页, chunkRows 默认 1000) → 流式写入 fs.WriteStream
   每批回报进度事件 evt:export.progress { rows, bytes }
   ↓
完成：Toast “已导出 100,000 行 → 路径”，点击定位文件
```

| 项 | 方案 |
|---|---|
| CSV / JSON / XLSX | **已实现**（v0.2.23 对账）：`export.run` 格式枚举 `csv|json|xlsx`，流式写，行数无上限（受超时与取消约束）；XLSX 为 exceljs 流式（D-14） |
| NDJSON / Markdown / SQL INSERT | P2（设计保留；「复制为」菜单已覆盖 Markdown/INSERT 的剪贴板形态） |
| 目标位置 | 用户经 SaveDialog 选择；默认目录为工作区 `.db-export/`（gitignore 建议） |
| 大任务 | **后台执行（M8 交付，#16）**：`export.run` 在 SaveDialog 选定目标后**立即回执 `{ exportId }`**，导出在 Extension Host 后台继续（进度进通知中心 `withProgress(Notification)`，通知上可取消，多任务并发互不阻塞）；进度经 `evt:export.progress`、终态经 `evt:export.done`（成功/取消/失败三路）回执；完成/失败 Toast 由 Host 发（不依赖 Webview 存活）；Webview 侧工具栏 chip 按 exportId 追踪并可取消 |
| 敏感数据 | 不做任何上传/遥测；仅写本地文件 |

### 5.8 安全护栏 DangerGuard（v0.2 收敛）

所有“危险”判定与确认集中在一个服务，避免各处自建：

| 检测点 | 触发源 | 规则 |
|---|---|---|
| 表格变更提交 | applyChanges 前 | `env === 'prod'` 强制输入表名确认；变更预览强制展开（不可跳过） |
| Console 语句 | 执行前 | AST 解析（`node-sql-parser`）：无 WHERE 的 UPDATE/DELETE、DROP、TRUNCATE、ALTER…DROP → 强提示确认；**解析失败降级为正则匹配 + 强提示**（宁可误报不漏报）——此为普通连接的**确认路径**，只读连接走下方 fail-closed 拦截路径 |
| 树节点操作 | 删表/删列/删索引 | 统一确认 Modal（输入名称匹配），生产环境额外显示红条 |
| 只读连接 | ConnectionManager 层 | 写语句/变更集直接拒绝（`E_READONLY`）；**fail-closed**：无法证明语句是读（AST 解析失败且正则不可判）时一律拒绝，防注释混淆/方言特性绕过；UI 置灰只是第一道防线 |
| 危险等级 | — | 只读连接 + prod 环境的组合可配置为“完全禁止写”（默认关闭） |

### 5.9 表结构编辑器（DDL，v0.2.4 新增，M8-B2）

对表的增删改（新建 / 修改结构 / 删除）与列的增删改，统一收敛在一个**表结构编辑器**页面（新建与修改共用，列操作内嵌其中）；删除列支持从树列节点确认后直删。模型、驱动接口、安全例外详见[驱动开发规范 §3/§10](./驱动开发规范.md)；交互线框见[交互设计稿 §12](./交互设计稿.md)。

| 项 | 设计 |
|---|---|
| 能力开关 | `capabilities.supportsDdlEditor`（驱动声明；未声明时树菜单不出现入口，编辑器页面提示不支持） |
| 统一模型 | `TableSpec { name, comment?, columns: ColumnSpec[] }`；`ColumnSpec { name, dataType, nullable, isPrimaryKey, autoIncrement?, defaultValue?, comment?, ordinal }`（驱动方言类型原文，见规范 §3） |
| 语句生成 | **驱动负责**：`buildCreateTable(db, spec)` / `buildAlterTable(db, obj, spec, current)`（可选方法，@since）。驱动自行 diff 出 ALTER 序列；`current` 由 Host 在**预览与执行前分别实时**从 `listColumns` 派生（避免基于过期基线生成变更，DDL 无乐观锁） |
| RPC | `ddl.load { connId, db, obj? }` → `{ kind: 'create'\|'alter', spec }`；`ddl.preview { connId, db, obj?, spec }` → `{ kind, statements: DdlStatement[] }`；`ddl.execute { connId, db, obj?, spec }` → `{ executed, failed? }`。**预览与执行同源**：execute 由 Host 重新调用同一 builder 生成语句，不信任 Webview 回传 SQL |
| 执行 | 复用驱动 `query()` 逐条执行、失败即停并定位语句序号（DDL 多数服务端隐式提交、无法单事务回滚——UI 明示）；成功后 `invalidateDb` + 树刷新（§7.5 DDL 失效联动） |
| 危险护栏 | `DdlStatement.destructive` 由驱动标记（删列/改类型等可能丢数据的语句）；任一 destructive 或 kind=alter → dev/test 确认 Modal、prod 输入表名确认（§5.8 延伸）；DROP TABLE / TRUNCATE 树操作走 §6 危险确认 Modal（输入名称匹配） |
| 只读连接 | 编辑器只读打开（可看可改不可执行——Host 层 `E_READONLY` 拦截执行，同 §5.8 第一道防线语义） |
| 范围外（P2+） | 索引/外键的可视化编辑、列排序（AFTER）、分区与存储引擎选项、结构对比 |

### 5.10 操作日志（v0.2.13 新增，M8 后续优化）

数据库连接、查询等操作的 info/error 级日志进 VSCode 自带输出面板（Output）——`createOutputChannel('Database Explorer', { log: true })` 的 **LogOutputChannel** 原生形态：info/warn/error/debug 分级、自动时间戳、面板右上角级别过滤下拉与 error 徽标。

| 项 | 设计 |
|---|---|
| 门面 | Extension Host 侧 `services/logger.ts` 的 `Logger` 类包装 LogOutputChannel，各服务经门面打点、**不直接持有 channel**；保留 `[源标签]` 前缀（conn/console/ddl/dangerGuard/rpc/form/export/query）便于 grep；webview 侧不打点（日志只在 Extension Host） |
| 统一拦截（v0.2.14） | **DriverHost 装饰器** `LoggingDriverHost`（ADR D-05「core 调用驱动的统一入口」）：fetchRows / query / applyChanges 全量 info（用户口径——所有查询动作都记录）、previewChanges debug（高频、非实际执行）、失败 error（code 可见）、E_CANCELED info；connId 经懒连接缓存回查（`ConnectionManager.connIdOf`）。Console/DDL/表格取数/编辑提交/导出全部经同一实例；**事务内语句不经 DriverHost**（SessionManager.execute 直连驱动 ISession），由 SessionManager 自行打点。与 Console run 汇总日志粒度不同（动作级 vs 批次级），并存不冲突 |
| 点位 | **连接域**：建连成功/失败（connId、连接名、驱动、host:port、耗时）、断开、自动重连（断开保护窗口内建连）、SSH 隧道建立/失败、连接表单「测试连接」成功/失败；**查询域**：执行完成/取消（语句数、行数、耗时）、执行失败（DriverError code + message）、危险语句判定/确认/拦截（§5.8）；**DDL**（§5.9）：执行/删表/删列完成与失败（含耗时）；**导出**（§5.7）：任务开始/完成/取消/失败（回执同点） |
| 级别约定 | info/error 为主，高频路径 debug——完成/确认/绑定类 → info；拦截与协议异常（fail-closed 拒绝、prod 确认未通过、横幅取消、非法 RPC 帧）→ warn；失败（连接/执行/DDL/导出/补全预热）→ error；高频路径（补全数据源耗时）→ debug（面板默认 Info 过滤不显示） |
| 脱敏（C-10） | 日志永不出现密码/凭证/连接串密钥部分：只打 host:port 等非敏感地址信息，`options` 整体不打；错误经 `describeError` 输出 DriverError code + message（C-6 文案映射层已保证不含凭证） |
| 与错误码关系 | 日志是 DriverError 错误码链路的**补充**（诊断面板可 grep），不改变 C-6 错误码与 UI 错误映射行为 |
| 面板入口 | 不自动 show()（不打断用户）；命令面板「数据库: 打开日志」（`dbExplorer.showLog`）聚焦频道 |
| 范围外 | telemetry（§6 #15）、日志落盘文件、webview 日志桥接、按级别配置项（LogOutputChannel 自带面板级过滤） |

### 5.12 AI 辅助（v0.2.29 新增，M9-AI / D-24）

BYOK（用户自带 key）的 AI 辅助，OpenAI 兼容 chat completions 单 provider 抽象。设计四原则（细节与状态机见交互稿 §15）：**① 副驾驶不是聊天窗**——AI 嵌在写 SQL / 读 SQL / 修 SQL 三个既有痛点处，不自建聊天面板；**② AI 产物一律可审计、绝不直接执行**——生成/修复的 SQL 只以草稿或 diff 进编辑器，执行仍走既有链路（DangerGuard、prod 输表名确认、只读拦截、参数化照常），AI 不降级任何护栏；**③ C-10 延伸到 prompt**——API 密钥只进 SecretStorage，默认只发表结构、不发任何数据行；**④ 未配置不占 UI**——入口保留可发现性，点击后引导配置。

- **AiProvider 抽象**（core 服务层）：`complete({ system, prompt, signal, onDelta })` 流式接口；首实现 `OpenAICompatProvider`（fetch 直连 + SSE 流式解析；endpoint/model 取自配置、key 取自 SecretStorage `dbExplorer.secrets.ai`）。VSCode LM API 等其他 provider 实现按需后续追加（接口已预留）
- **三能力**：
  - **NL→SQL（生成）**：编辑器 CodeLens「✨ 生成 SQL」（与「▶ 执行」并排）/ 快捷键 `Alt+\` / 命令面板 → QuickPick 输入自然语言 → 结果**直插编辑器并选中新文本**（无预览确认一步——SQL 反正要人工审改后才执行，护栏在执行侧兜底）；绑定库 >50 表先 QuickPick 圈选上下文表
  - **SQL 解释（读）**：编辑器右键「DB Kit: AI 解释 SQL」（选区优先、无选区解释光标所在语句）→ Console 结果面板「**AI 解释**」Tab 流式渲染 Markdown（消息通道扩展，结果面板单例跟随心智不变）
  - **错误修复建议（修）**：消息 Tab 错误 item 尾部动作「✨ 修复建议」（仅有文档来源的执行错误显示）→ `ai.fixError` → **diff Modal**（原 SQL vs 建议 SQL）→「替换原语句 / 插入为新语句 / 不采用」；替换经 `ai.applyFix` 按 fixId 应用（Host 校验文档版本 + 语句偏移，失配 `E_STATE_LOST` 引导重新生成）；替换/插入仅为文档编辑，**不自动执行**
- **上下文与隐私**：prompt = 方言说明（driverId）+ schema 摘要（MetadataCache：表/列/类型/注释）。组装收口 Host 侧纯函数 `aiPrompt.ts`（单测断言：密钥/密码/连接串/主机信息永不入 prompt——C-10 审计点新增）；**数据行任何 v1 路径不发送**（采样行 opt-in 列 P2）；AI 调用日志 info（方法/绑定/耗时/token 用量），prompt 内容与密钥不落日志
- **RPC（C-5）**：`ai.getSettings`（只回 `hasKey`，永不回传明文）/ `ai.saveSettings`（apiKey 缺省不修改）/ `ai.testSettings`（按表单当前值测试连通）/ `ai.fixError` / `ai.applyFix`。生成与解释走编辑器 Host 命令 + console item 推送，不经新 RPC
- **错误码（C-6 扩展）**：新增 `AiErrorCode` 族 `E_AI_NOT_CONFIGURED`（[去配置]）/ `E_AI_REQUEST_FAILED`（[查看详情][重试]）/ `E_AI_ABORTED`（用户取消，静默）——与 DriverErrorCode 并列、UI 仍按 code 映射；`E_STATE_LOST` 复用 RPC 层既有码
- **命令**：`dbExplorer.settings`（设置中心总入口）/ `dbExplorer.ai.settings`（转发 AI 分类）/ `dbExplorer.ai.generateSql` / `dbExplorer.ai.explainSql`（§5.6 同步）
- **配置**：`dbExplorer.ai.endpoint` / `dbExplorer.ai.model`（设置中心 AI 分类读写，§13 同步）；AI 设置是**设置中心**（v0.2.31，交互稿 §16）的分类之一——分类侧栏 + 内容区，代理编辑 VSCode settings 走白名单（`settings.*` RPC）

### 7.3 稳定性设计

| 风险 | 对策 |
|---|---|
| 驱动阻塞 Extension Host | 所有驱动调用强制超时 + AbortSignal（7.6）；进程隔离预案就绪（D-05） |
| 大结果集撑爆内存 | 分页 + 行数上限 + 流式导出 |
| 连接泄漏 | `ConnectionManager` 统一持有连接池，窗口关闭 / 插件 deactivate 时 `dispose()` |
| Webview 崩溃/重载 | `retainContextWhenHidden: true` + Host 快照恢复（5.4.5），ChangeSet 不丢 |
| 驱动异常 | 统一映射为 `DriverError`（错误码），UI 展示用户可读文案 + “查看详情”跳输出面板 |
| 激活耗时 | `activationEvents: onView` 懒激活；驱动按需 import，未用到的驱动不加载 |

### 7.4 Webview ↔ Extension RPC 协议（v0.2 新增）

#### 7.4.1 帧格式

单一 `postMessage` 通道，三类帧：

```ts
interface RpcRequest  { kind: 'req'; id: string; method: string; params?: unknown }
interface RpcResponse { kind: 'res'; id: string; ok: boolean; result?: unknown;
                        error?: { code: string; message: string; detail?: string } }
interface RpcEvent    { kind: 'evt'; event: string; payload?: unknown }   // Host → Webview 单向推送
```

- 请求超时：Webview 侧默认 30s，按 method 可覆盖（长交互 method 置 0 不设限：`console.execute` 靠事件推送保活、`export.run` 含 SaveDialog 用户交互——M8 起导出本体在 Host 后台执行，回执即时）
- 取消：`rpc.cancel(reqId)`，Host 转为 AbortSignal 下传驱动 → 驱动返回 `E_CANCELED`
- 错误码：复用 `DriverErrorCode`（含 `E_VALIDATION`），RPC 层仅另加 `E_UNKNOWN_METHOD`、`E_STATE_LOST`

#### 7.4.2 方法注册表（初始清单）

| method | 说明 |
|---|---|
| `sys.handshake` | Webview 就绪/重载恢复：入参 `{ stateId? }`，返回快照（视图参数 + ChangeSet + 选中态） |
| `table.fetchRows` | 分页取数（FilterCondition / sorts / search / cursor） |
| `table.previewChanges` | 生成将执行的 SQL 预览（与 applyChanges 同源） |
| `table.applyChanges` | 提交变更集 |
| `table.revertChanges` | 撤销全部/指定行 |
| `meta.getColumns` | 列元数据（列设置、编辑器类型渲染） |
| `export.run` / `export.cancel` | **M8 后台化**：run 在 SaveDialog 后立即回执 `{ exportId, canceled? }`，导出后台执行；cancel 按 exportId 取消任务 |
| `ddl.load` / `ddl.preview` / `ddl.execute` | **M8-B2 表结构编辑器（§5.9）**：载入当前结构（create 时空白）、生成语句预览（驱动 buildCreateTable/buildAlterTable，预览与执行同源）、逐条执行（失败即停 + 危险确认 + 缓存失效联动） |
| `er.getGraph` / `er.openTable` | **M8-ER ER 图查看（§5.11）**：库级关系图（表节点 + FK 边 + Host 分层布局坐标，scope all/selection）；节点双击打开表格视图（复用 openTablePanel 链路） |
| `ai.getSettings` / `ai.saveSettings` / `ai.testSettings` | **M9-AI AI 辅助设置（§5.12 / D-24）**：BYOK 配置读写与连通测试——getSettings 只回 `hasKey` 永不回传明文；saveSettings 的 apiKey 缺省 = 不修改现值（key 只进 SecretStorage）；testSettings 按表单当前值（含未保存密钥）发最小请求 |
| `ai.fixError` / `ai.applyFix` | **M9-AI 错误修复建议（§5.12）**：fixError 按错误 item 定位语句文本 + 错误码 + 脱敏 message → 返回 `{ fixId, originalSql, suggestedSql, note? }`；applyFix 按 fixId 应用（mode: replace/insert），Host 校验文档版本 + 语句偏移，失配 → `E_STATE_LOST` |
| `console.execute` | 执行 SQL（结果面板 Webview） |
| `console.getState` | Console 状态（结果面板引导/恢复；consoleId 空 = 最近执行） |
| `conn.getStatus` | 连接状态（工具栏徽标） |

事件：`evt:changeset.updated`（N 变化，工具栏角标）、`evt:conn.status`、`evt:export.progress`（逐批行数/字节）、`evt:export.done`（M8：导出终态回执，成功/取消/失败三路）、`evt:row.error`（提交失败行定位）。

#### 7.4.3 校验与治理

- 消息 schema 定义在 `@db-explorer/protocol`（zod），**双端运行时校验**：Host 校验请求，Webview 校验响应
- 校验失败 → 返回 `E_VALIDATION` 并输出到日志通道，**不崩溃、不静默**
- 协议带 `protocolVersion`（handshake 协商），不兼容时 Webview 显示“插件与视图版本不一致，请重载窗口”

### 7.5 元数据缓存设计（v0.2 新增）

```
层次：connection → databases(60s) → objects(手动失效) → columns/keys/indexes(5min)
存储：内存 Map + TTL；不落盘（避免过期结构误导，P2 再评估 workspaceState 持久化）
```

> **持久化评估结论（M7 收尾，关闭遗留 #6）：维持内存 + TTL，不落盘。** 理由：① 离线浏览结构是低频场景，重连后元数据懒加载重建成本可接受；② 过期结构误导是真实风险（表结构已变而用户据旧结构写 SQL/编辑），持久化必须引入 staleness 语义，复杂度大于收益。未来若做（触发条件：离线浏览成为真实需求），形态限定为：workspaceState 按 `connId+db` 存 JSON（带 schema 版本 + 抓取时间戳），仅在连接失败时降级展示并明示「离线快照 · 抓取于 xx」。

| 事件 | 失效动作 |
|---|---|
| 树节点手动刷新 | 仅失效该子树 |
| 全局 Refresh | 清空全部缓存并重载展开路径 |
| Console 执行 DDL（AST 判定 CREATE/ALTER/DROP） | 失效该库 objects + 该表 columns，并联动树刷新 |
| applyChanges 成功 | 仅失效该表 `rowEstimate`（列结构未变） |
| 补全预热 | 打开 Console 后台拉取当前库表+列，显示“补全加载中”占位 |

并发防护：同一 key 的加载请求合并（in-flight dedup），避免展开一棵树触发 N 次相同查询。

### 7.6 进程隔离与阻塞防护（v0.2 决策 D-05）

- **抽象先行**：core 从 M0 起经 `DriverHost` 接口调用驱动（`InProcessDriverHost` 为默认实现），方法签名与 `IConnection` 一一对应，切换成本 ≈ 0
- **MVP 策略**：驱动运行在 Extension Host 进程内；所有调用强制超时（默认 15s）+ AbortSignal 取消
- **隔离预案**：`UtilityProcessDriverHost`（基于 `vscode.UtilityProcess`），触发条件（满足其一即评估切换）：
  1. 驱动 CPU 密集操作（大结果集解析/序列化）导致 UI 命令响应 P95 > 200ms
  2. 某驱动 native 依赖崩溃，进程内无法兜底
- 观测手段：遥测记录驱动调用耗时分布（遥测关闭时仅本地输出面板可见）

## 8. 安全设计

| 项 | 方案 |
|---|---|
| 密码存储 | `vscode.SecretStorage`（OS 钥匙串），永不写入 settings/日志/遥测 |
| 连接配置存储 | `globalState`（不含密码），导出时密码以 `${secret}` 占位，导入时提示补录 |
| SQL 注入 | 表格编辑路径**强制参数化**（驱动生成 `?` / `$1` 占位），筛选下推同理；禁止字符串拼接用户输入值 |
| 只读模式 | 在 ConnectionManager 层拦截写操作，非 UI 层禁用（防绕过）；语句无法证明是读时一律拒绝（fail-closed，见 5.8） |
| 危险操作 | 统一 `DangerGuard`（5.8）：AST 检测 + 确认流程（普通连接），解析失败降级正则；只读路径 fail-closed |
| 生产环境 | `env === 'prod'`：二次确认（输入表名）+ 编辑器标题栏红条 + 强制变更预览；该约束内置不可配置关闭 |
| 日志脱敏 | 输出面板/错误信息中 DSN、密码、Token 一律打码 |
| 网络 | 默认启用 SSL 校验，允许显式关闭并打警告 |
| 遥测 | 默认关闭；开启时不采集 SQL 内容与数据，仅事件计数与耗时 |
| 导出 | 仅写本地文件，无网络行为 |

## 11. 关键决策记录（ADR，v0.2 新增）

> v0.1 第 11 章“开放问题”全部在此关闭。格式：决议 / 理由 / 代价与缓解。若后续推翻某条决策，在此追加记录，不改写历史。

### D-01 表格视图：Webview（React + TanStack Table）
- **决议**：Webview 实现，TreeView 不承担表格职能
- **理由**：排序/筛选/行内编辑/列冻结/虚拟滚动是网格能力，TreeView 无法承载（v0.1 的倾向项，正式确认）
- **代价与缓解**：需维护 webview-ui 包与 RPC 协议；Webview 资源全部本地打包（不走 CDN，CSP 收紧到 `default-src 'none'`），崩溃恢复由 Host 快照兜底（5.4.5）

### D-02 SQL Console：原生 Editor（MVP）+ 独立结果 Webview
- **决议**：方案 A；编辑器交互封装为 `ConsoleEditor` 门面，保留迁移 Monaco 的预案
- **理由**：免费获得语法高亮/主题/快捷键/IME 兼容；Monaco in Webview 的主题与快捷键维护成本高
- **代价与缓解**：结果无法默认内联在编辑器正下方——结果面板为 Webview Panel（用户可拖到下方编辑组），`Ctrl+Alt+R` 快速聚焦结果

### D-03 无主键表编辑：默认只读，可开关“全列匹配”
- **决议**：`dbExplorer.edit.allowNoPrimaryKey`（默认 false）；开启后以**全部列原始值**作 WHERE，affectedRows ≠ 1 即视为冲突回滚；含二进制列的表即使开启也不可编辑。**有主键表的乐观锁 WHERE = 主键 + 变更列原值**（字段级并发，评审确认：不同列的并发编辑互不冲突，同行同列可检出）；原值为 NULL 的列用 `IS NULL`；DELETE 仅按主键
- **理由**：无定位键的 UPDATE 本质是全表扫描级风险，默认必须关闭；开关满足“必须改”的场景
- **备注**：以 UNIQUE 索引作 RowKey 的增强放 P2 评估

### D-04 跨库 JOIN 补全：P2
- **决议**：M5 补全上下文解析仅处理单库 + 别名；跨库（`db.table.column`）放 P2
- **理由**：跨库需要一次性拉取多库元数据，预热成本高、命中率低

### D-05 驱动进程隔离：MVP 进程内 + DriverHost 抽象预留
- **决议**：M0 引入 `DriverHost` 抽象，默认进程内实现；满足 7.6 触发条件时切换 `vscode.UtilityProcess` 实现，驱动代码零改动
- **理由**：mysql2/pg/ioredis 均为纯 JS 异步 IO，真正阻塞 EH 的是 CPU 密集序列化，且导出已流式化；过早隔离增加调试与序列化成本
- **裁决时点**：M6（Redis 驱动接入后）复查
- **复核记录（2026-10-02，M6）**：按 §7.6 两个触发条件对 Redis 驱动实测，**结论：不启用 UtilityProcess，维持进程内实现**。实测（node-redis v5 / Redis 7.2 / 本机 localhost）：
  - 条件 1（CPU 密集序列化致 UI 命令 P95 > 200ms）：**未触发**——5 万 field hash 全量取数（最重的序列化场景）进行中，同进程模拟 UI 命令（PING）P95 = 0.3ms（空载基线同为 0.3ms）；1MB string Value 取回 7.5ms；hash 5000 行单页 17~33ms。await 边界让出事件循环，序列化不阻塞命令调度。
  - 条件 2（native 依赖崩溃）：**不适用**——node-redis 纯 JS、无原生模块（driver-mysql 的 mysql2 亦纯 JS）。
  - 复测入口：`D05_EVAL=1 npx vitest run packages/driver-redis/src/d05.eval.test.ts`（非门禁用例）。
  - 后续再评估触发点：新增 native 依赖的驱动接入（规范 §10），或引入同步/大缓冲驱动路径（如 SQLite 大库全表导出）时重跑本用例口径。
- **复核记录（2026-10-04，M7 收尾）**：批次 B/C 引入 ssh2 与 exceljs，按本记录口径复核：
  - 条件 2（native 依赖崩溃）：**不适用**——exceljs 纯 JS；ssh2 本体纯 JS，`cpu-features` 为可选 native 加速（try/catch require，缺省降级）且 esbuild 标 external，不构成强制 native 依赖。
  - 条件 1（CPU 密集序列化）：**未触发**——SSH 隧道（网络 IO）与 xlsx 流式写出（磁盘 IO）均为异步边界，不在事件循环热路径上做 CPU 密集序列化；导出管线维持批量生成器 + 背压。
  - 结论：**维持进程内实现**；下次复核触发点不变（新增 native 依赖的驱动接入）。
- **复核记录（2026-10-09，M8-SQLite）**：SQLite 驱动（D-16，sql.js 同步引擎）接入，D-05 此前预埋的「同步/大缓冲驱动路径」触发点到点复核。实测（sql.js 1.14 / 本机 arm64）：
  - 条件 2（native 依赖崩溃）：**不适用**——sql.js 为 WASM 纯 JS 加载 + .wasm 静态资产，无 .node 原生模块。
  - 条件 1（CPU 密集序列化致 UI 命令 P95 > 200ms）：**大结果集场景触发，常规路径未触发**——空载 ping P95 = 0.2ms；整库载入 6MB/40MB = 4.4/12.8ms；40MB 库 100 行写批次（含整库原子落盘）= 98.1ms；全表 COUNT(*) = 38.4ms，均远低于阈值。**5 万行单次取数 = 205.6ms 期间，调度的模拟 UI 命令体感延迟 P50 = 144.3ms / P95 = 234.5ms → 触发**（同步执行在微任务突发内完成，timer 类 UI 命令只能等事件循环空出）。
  - 结论：**维持进程内实现**，与 D-16 的工程约束配套生效——限用中小库（建议 ≤ 100MB）、表格取数恒带 LIMIT（分页量级阻塞窗口毫秒级）、默认不执行全表 COUNT（C-9）；5 万行级大结果集属导出/极端路径，非浏览主路径。若未来大库/大导出常态化，重评估 UtilityProcess（本 ADR 预留）。
  - 复测入口：`D05_EVAL=1 npx vitest run packages/driver-sqlite/src/d05.eval.test.ts`（非门禁用例）。
- **复核记录（2026-10-09，M8-Mongo）**：MongoDB 驱动（D-17，官方 mongodb Node 驱动）接入，按本记录口径复核：
  - 条件 2（native 依赖崩溃）：**不适用**——官方 mongodb 驱动纯 JS、无原生模块（与 mysql2/node-redis/pg 同口径，esbuild 整体打包）。
  - 条件 1（CPU 密集序列化）：**未触发**——驱动为网络异步 IO，BSON 编解码在 await 边界分批让出事件循环；浏览路径取数恒带 LIMIT（cursor 分页），单页编解码阻塞窗口毫秒级（与 M6 Redis 实测同构），无需专项评估用例；5 万行级大结果集属导出路径，既有导出管线（流式分批 + 背压，§5.7）已覆盖。
  - 结论：**维持进程内实现**；下次复核触发点不变（新增 native 依赖的驱动接入）。

### D-15 PG schema 上树：schema 映射 database 层（M8-PG，2026-10-06）
- **决议**：PostgreSQL 驱动的 `listDatabases()` 返回连接库内**非系统 schema**（排除 `pg_*` 前缀与 `information_schema`），树 database 层即 schema；`IConnection` 全部方法的 `db` 参数在 PG 驱动 = **schema 名**，`obj` 恒为裸表/视图名；SQL 生成对对象引用显式 `"schema"."table"` 限定（PG 连接协议绑定单库，无跨库语义）；连接表单「默认库」= 连接字符串真库名，经 FormSchema hint 与树上「库」（schema）消歧
- **理由**：① Host 侧删表路径按 `q(db).q(obj)` 生成（ddlService），本方案恰好输出合法 PG `DROP TABLE "schema"."t"`——PG 无三段名，folder 方案下该路径生成非法语句；② 核心/树/RPC/Console 绑定/补全/元数据缓存零改动，菜单 when 子句零新增 contextValue（P-40 风险归零）；③ `obj` 恒为裸名，无 `schema.table` 全限定名拆分，含点标识符（`"a.b"`）天然安全；④ PG 单连接恒绑定一个数据库，真实库名不因映射丢失（连接节点 tooltip 展示）
- **代价与缓解**：`DatabaseMeta` 在 PG 驱动承载 schema（语义注记写入驱动规范 §3/§5.2，树节点 description 可标注）；用户手写未限定语句依赖 search_path——`QueryRequest.db` ≠ 默认 schema 时经池内专用连接 `SET search_path` 后执行、用毕 RESET（P-36 同族防池污染）；系统 schema 硬过滤，如需浏览系统表后续加配置开关（P2）
- **否决案（folder 节点）**：库下加 schema folder 层 + `obj` 全限定名——树多一层、Host 删表/`TableSpec.name` 均需处理点号拆分或驱动接管删表，改动面与边角风险显著更大，收益仅为多展示一层真实库节点（PG 单连接恒一库，无信息增量）

### D-16 SQLite 执行引擎与持久化：sql.js（WASM）单引擎 + 写批次原子落盘（M8-SQLite，2026-10-09）
- **决议**：SQLite 驱动采用 **sql.js（WASM）单引擎**——整库载入内存执行，**限用中小库（建议 ≤ 100MB）**；同步执行：`supportsCancel = false`（契约组自动跳过取消组）、`supportsMultiStatement = false`（Console 按 Host 切分单语句执行）。持久化：**每个写批次后原子落盘**（序列化整库字节 → 写临时文件 → rename 覆写；applyChanges 批次 / Console 写语句批次 / 交互式事务 commit 各为一个批次，只读连接与未提交会话不落盘）。树层级（§5.1.3）：`listDatabases()` 恒返回单节点 `main`（SQLite 逻辑主库，ATTACH 附加库为后续扩展口），`db` 参数恒为 `main`；连接表单「数据库文件路径」为 string 字段（支持 `~/` 与相对工作区路径，文件必须已存在不自动创建）；无认证字段、不涉 SecretStorage。
- **理由**：零 native 依赖——D-05 条件 2（native 崩溃）不适用，VSIX 保持平台无关（.wasm 为静态资产随包分发，无 Electron ABI 重编译/平台分包），且 sql.js 本就是 D-12 驱动清单列项；引擎与内嵌 SQLite 版本随驱动固定（sql.js 1.14 内嵌 SQLite 3.49），不随宿主 VSCode 的 Electron/Node 版本漂移，行为矩阵可测可控；「编辑即持久」由写批次落盘保障，符合数据库工具「提交即落盘」的用户预期。
- **node:sqlite 可行性结论（2026-10-09，用户裁决收口）**：新版宿主（Electron 35+ / Node ≥ 22.14）探测可用、API 面实测够用（BigInt 通道/数组行/只读打开均验证通过），但 **不作直接依赖**——① D-11 基线 `engines.vscode ^1.85`（Node 18）宿主完全缺失该模块，直接依赖即崩溃，留用则必然引入兜底第二引擎；② Node 22.x 仍标 experimental，特性跨版本漂移（BigInt 通道/数组行/列名 API 需逐一特性探测）；③ 内嵌 SQLite 版本随宿主漂移，行为矩阵不可控。
- **代价与缓解**：① 同步执行阻塞 Extension Host、不可中断——中小库与常规语句阻塞窗口为毫秒~百毫秒级；重查询（大库加载/全表扫描）期间 UI 命令排队，量化复核按 D-05 口径实跑（复核记录随后续批次提交追加）；缓解 = docs 声明限用中小库、fetchRows 恒带 LIMIT、默认不执行全表 COUNT（C-9）；未来若需大库支持，重评估 UtilityProcess（D-05 预留口子）或 better-sqlite3（触发 D-05 条件 2 复核 + VSIX 平台分包）。② 整库驻留内存 + 写放大（每次落盘序列化整库字节）——按批次合并落盘、原子覆写（temp+rename）防半写损坏；落盘耗时随库体积线性，由「限中小库」口径覆盖。
- **否决案**：better-sqlite3（native：D-05 条件 2 复核 + Electron ABI 重编译 + VSIX 平台分包三重成本，收益仅真流式大库——当前限中小库口径下不需要）；`node:sqlite` 直接依赖（见上「可行性结论」）；「node:sqlite 优先 + sql.js 兜底」双引擎（本条修订前的草案：为单一优化点维护两套引擎路径与双份契约面，复杂度不成比例，否决）。
- **修订记录**：2026-10-09——初版（同批次 c89d43f）曾定为「node:sqlite 优先 + sql.js 兜底」双引擎；经用户裁决（评估 node:sqlite 直接依赖可行性后）收口为**仅 sql.js 单引擎**，本条按最终决议改写并在此注记历史（ADR 不改写原则下的修订留痕）。

### D-17 MongoDB 驱动：只读浏览 + mongosh 命令控制台（M8-Mongo，2026-10-09）
- **决议**：MongoDB 驱动（driverId `mongodb`，官方 `mongodb` Node 驱动，纯 JS）首批为**只读浏览器**，五项岔口经用户确认（2026-10-09）：
  1. **能力边界 = 只读优先**：`editable = false`（`previewChanges`/`applyChanges` 抛 `E_UNSUPPORTED`，契约变更集组按 P-19 探针整组跳过）；文档编辑（ChangeSet 行编辑语义对文档模型的映射：整文档 `replaceOne` vs 字段级 `$set`、以 `_id` 为 RowKey 的乐观锁）留后续批次专项设计。
  2. **文档展示 = 动态列**：采样推断顶层字段并集作列集（`_id` 恒为首列，采样上限 200 篇、首见序）；字段缺失按 NULL 语义（`isNull` 同时命中显式 `null` 与缺失字段——文档模型口径）；嵌套文档/数组按 C-7 渲染为 `json` 列。列集随采样波动是文档模型的既定口径（翻页可能补出新列）。
  3. **分页 = cursor**：游标自包含排序位点与批内位置（opaque base64url(BSON)，P-27 教训——初始态≠取尽态）；默认 `_id` 升序兜底（P-10 追加口径：用户排序存在时 `_id` 作末位 tiebreak，不前置）；带排序键翻页按「排序值 + `_id`」复合位点 resume（防同值字段跳行）；`offset` 兼容翻译为 `skip`（契约 offset 组实跑）。
  4. **契约实例 = `MONGO_URI` 门控（PG 先例）**：本地经环境变量注入实例实跑、未设 skip；CI 增 `mongo:7` service 恒跑（§12.5）。fixture 库 `cf_mongo` 由测试自持（drop 重建 + 种子经 mongodb 客户端写入，驱动本身只读）。
  5. **Console = mongosh 命令域**：`supportsSQL = false`，每行一条命令（与 Redis 同构）；**首批只读——非读命令一律 `E_UNSUPPORTED`**；危险判定由 core 新增命令白名单 `mongoCommands` 执行（provablyRead fail-closed：`aggregate` 管道含 `$out`/`$merge` 视为写、`runCommand` 仅读命令子集；dangerous：`drop`/`dropDatabase`/`deleteMany`/`updateMany`/`insertOne`/`createIndex` 等写命令给横幅原因）；`use <db>` 由 Host 拦截改 Console 绑定不下发（P-36 同构）；`show dbs`/`show collections` 为驱动实现的只读帮助命令。
- **理由**：① 只读优先贴合 C-4 批次节奏，Redis 当年同口径，编辑语义（文档替换粒度）值得独立设计轮；② 动态列是 Compass 同款体验、与 FilterOp 顶层字段下推天然对齐，`_id + document` 两列形态牺牲文档库核心浏览价值；③ Mongo 无 offset 语义的原生分页，`skip/limit` 深翻页 O(n) 且易漂移，游标是文档库正确解，且契约组 `runCursorPaginationChecks` 可实跑闭环（`primaryKey=['_id']` 非空）；④ 本机无容器运行时（P-28），用户供给远程实例走 `MONGO_URI` 门控 = PG 先例的既有机制，CI service 保底防「契约静默缺考」；⑤ mongosh 是 MongoDB 事实标准交互面，命令白名单先例（core `redisCommands` + editGuard 命令模式）可直接同构复用。
- **代价与缓解**：① 动态列列集不稳定 → `_id` 恒首列保证 RowKey/游标索引恒定（树/契约按首列取主键），列设置按列名缓存不受补列影响；② mongosh 参数为 JS 字面量（非 JSON）→ 驱动自建受限字面量解析器（对象/数组/字符串/数字/布尔/null + `ObjectId()/ISODate()/NumberLong()/NumberDecimal()/BinData()` 构造器 + `function(){}` 源码按 BSON Code 透传），解析失败 `E_SYNTAX` fail-closed，**禁用 eval**；③ 游标翻页期间修改排序属未定义（位点失义）→ Webview 改排序即重置游标（既有查询状态机行为）；④ 远程共享实例的取消组用有界 `$where` 忙循环模板（自终止，客户端 abort 先行返回 `E_CANCELED`），不留永久服务端负载。
- **否决案**：`_id + document` 两列保守形态（Redis 内容表先例——Redis 单值模型适配良好，Mongo 文档模型按字段浏览/筛选的价值是核心需求，两列形态使筛选器与字段目录失去意义）；`skip/limit` offset 分页（深翻页性能与漂移，契约 cursor 组无法实跑）；首批含文档编辑（编辑粒度映射未定稿，摊薄本批契约面）；连接表单 URI 串模式（含密码的 URI 与 C-10 SecretStorage 拆分增加表单复杂度，分字段最小集覆盖单机直连场景，Atlas `mongodb+srv` 留后续批次）。

### D-18 MongoDB 文档编辑：字段级 $set 乐观锁 + 逐条失败即停 + Console 文档写放开（M8-Mongo B2，2026-10-10）
- **决议**：D-17 预埋的编辑批次落地，四岔口经用户确认（2026-10-10）：
  1. **更新映射 = 字段级 `$set`**：`updateOne({ _id, <变更列>: 原值 }, { $set: { 字段: 新值 } })`——乐观锁 = RowKey + 变更列原值，与 SQL 驱动 D-03 字段级口径完全同构（不同列并发互不冲突、同列并发可检出）；原值 null/缺失统一条件 `{ f: null }`（与读侧「缺失=NULL」口径自洽）；matchedCount ≠ 1 → `E_CONFLICT`。否决整文档 `replaceOne`（任意列被并发改过即冲突，并发面大且与 D-03 口径不一致）。
  2. **单元格清空 = `$set null`**：不引入 `$unset`（读回与缺失无观察差异，乐观锁边界单一）。
  3. **事务 = 逐条 + 失败即停**（`supportsTransaction = false`）：多文档事务需副本集、standalone 不支持；按 §8-5 既有语义顺序执行、首个失败即停（错误含 kind/tempId/rowKey 定位，message 注明已应用项数）；契约组「混合事务原子性」两项检查按能力跳过（套件扩展 `supportsTransaction` 选项，缺省不跳过、向后兼容）。
  4. **Console 文档写放开**：撤 D-17 首批 `E_UNSUPPORTED` 兜底——`insertOne/insertMany/updateOne/updateMany/replaceOne/deleteOne/deleteMany/findOneAnd*` 走既有 editGuard 链（dev/test 危险横幅、prod Modal、只读连接 fail-closed，core dangerous 表与横幅文案首批已就绪）；**结构类命令（drop/createIndex/createCollection/renameCollection/eval/mapReduce 等）恒 `E_UNSUPPORTED`**。
- **理由**：字段级乐观锁是本产品 SQL 驱动的既定并发口径（D-03），文档模型的顶层字段天然对应「列」，映射零发明成本；standalone 兼容使契约可在用户实例本地实跑（C-3 红绿不押 CI）；Console 放开避免「表格可编辑、命令行被拒」的双入口口径分裂。
- **代价与缓解**：无事务批次的「部分成功」——失败错误 message 注明已应用项数（§8-5 如实口径），失败行定位走 ChangeErrorMeta 既有链路；动态列采样波动不影响编辑正确性（original 取自页面行的真实读取值，乐观锁条件与服务器状态一致）；`_id` 不可编辑、json 列（嵌套文档）整值替换（编辑器 JSON 文本）、二进制/ObjectId 编辑回传经既有 `toBsonValue` 转原生；preview 文本 = mongosh 伪语句（`?` 占位符 + params 等长，P-22 回填口径）。
- **范围边界**：insert 允许缺省 `_id`（服务器生成后回填 rowKey，§8-3）；`$unset`、嵌套子文档字段级编辑（`a.b.c` 路径）、bulkWrite 命令域入口留后续评估。
- **修订记录**：2026-10-10（M8-DBDDL，D-19）——命令控制台放行面调整：`dropDatabase` 经危险护栏（dev/test 横幅、prod Modal、只读 fail-closed）后可执行（树删库与命令行同一护栏口径），其余结构类命令（createCollection/drop collection/createIndex/renameCollection/eval 等）仍恒 `E_UNSUPPORTED`。

### D-19 库级 DDL：三方法契约 + 驱动自定义表单 + Webview 动态表单弹窗（M8-DBDDL，2026-10-10）
- **决议**：树上库级「新建 / 编辑 / 删除」，三岔口经用户确认（2026-10-10）：
  1. **首批驱动矩阵（按能力各取所需，方法存在性裁剪菜单）**：MySQL 建/改/删库（`CREATE/ALTER/DROP DATABASE`，charset/collation 表单）；PostgreSQL 建/删 schema（D-15 树上「库」即 schema——`CREATE SCHEMA` / `DROP SCHEMA … CASCADE`（标 destructive），无 ALTER）；MongoDB 删库（`dropDatabase`；建库 = 写数据隐式创建、无表单无编辑，命令控制台放行面随 D-19 修订）。redis（库数固定）/sqlite（单 `main`）天然不参与。
  2. **契约 = 完整面**：core 可选方法族 `buildCreateDatabase(spec)` / `buildAlterDatabase(db, spec, current)`（无差异返回空数组）/ `buildDropDatabase(db)`（语句为方言原文、destructive 标记、标识符 fail-closed `E_VALIDATION`，同 buildCreateTable 口径）+ `getDatabaseFormSchema()`（驱动自定义表单，形状同 §3.1 FormFieldSchema；编辑时 Host 以 `DatabaseMeta` 预填）+ `capabilities.supportsDatabaseDdl`；`DatabaseSpec { name, charset?, collation? }`；`DatabaseMeta` 增 `collation`（MySQL 编辑预填）。

- **代价与缓解**：`DROP SCHEMA CASCADE` 连带删表（destructive 红条 + 名称确认 + 表单 hint 明示）；MySQL `ALTER DATABASE` 仅字符集/排序规则维度（重命名需迁移语义，留后）；树 database 节点追加 `dbddl`/`dbddl-alter` 令牌触及既有锚定 when 正则——逐条排查扩展（P-40 教训重演区，AGENTS 同步）。

### D-21 SQL Server 驱动：mssql/tedious + schema 上树（D-15 同构）+ OUTPUT 回填（M8-MSSQL，2026-10-11）
- **决议**（四岔口经用户确认，2026-10-11）：
  1. **技术选型 = npm 包 `mssql` ^11（tedious ^18 内核）**：纯 JS 无 native 硬依赖（D-05 条件 2 不适用，VSIX 保持平台无关）；TDS 协议原生实现，`request.cancel()` 发送 ATTENTION 支持真实取消（`supportsCancel = true`，CI service 实跑验证）。可选依赖 `msnodesqlv8`（Windows native 路径）不在 `require('mssql')` 打包图内、运行时永不触达（P-43 同族，无需 external）。
  2. **三层命名映射 = D-15 同构（「库」= schema）**：连接绑定单一数据库（表单「默认库」= Initial Catalog，缺省 `master`）；树上 database 层 = 当前库内**非系统 schema**（排除 `sys` / `information_schema` / `guest` / `db_*` 固定角色架构）；全部接口的 `db` 参数 = **schema 名**、`obj` 恒为裸名，驱动生成语句显式 `[schema].[table]` 两段名限定；Console 用户手写**未限定名按登录默认 schema 解析**（SSMS 同款行为，文档声明），跨库查询手写三段名 `[db].[schema].[table]`（`USE` 语句由 Host 层 P-36 拦截兜底、驱动 README 禁用——池化下 USE 语义不可靠）。
  3. **INSERT 主键回填 = `OUTPUT INSERTED.<主键列>`**（PG `RETURNING` 同构语义）：覆盖 IDENTITY 自增 / DEFAULT 约束 / `NEWID()` 全部生成列场景，读回经值编码契约整形（bigint 安全转数值）；已知约束如实声明——目标表带**启用触发器**时带 OUTPUT 的 INSERT 被服务端拒绝（T-SQL 约束），该类表的表格新增行会失败（更新/删除不受影响），降级方案（`sys.triggers` 探测 + SCOPE_IDENTITY 回落）留后续评估。
  4. **SSMS 风格 `GO` 批首版不支持**：`GO` 是客户端伪指令而非 T-SQL 语句，core `sqlScript.ts` 扫描器（`;` 切分、语句定位、CodeLens/注记偏移）不动——粘贴含 `GO` 的脚本按普通语法错误处理，驱动 README 声明该限制。
- **理由**：① tedious 是微软生态外事实标准的纯 JS TDS 实现，D-12 驱动清单同口径；② D-15 在 PG 上已验证「schema 映射 database 层」的核心零改动路径（树/RPC/Console 绑定/补全/元数据缓存全不动），SQL Server 连接协议同样绑定单库，映射语义自洽，Host 删表路径 `q(db).q(obj)` 恰好输出合法两段名；③ OUTPUT 是 T-SQL 对「写语句返回行」的原生机制，与现有 §8-3 回填契约（`items[].rowKey`）零协议改动；④ GO 支持需要动 core 扫描器并全链路回归（切割/定位/危险判定/注记），收益（粘贴 SSMS 脚本）与成本不成比例。
- **代价与缓解**：① 树上不展示跨库（单库浏览）——与 PG 同口径，多库场景按连接拆分，跨库查询经三段名可用；② 表单默认不加密（encrypt=false，对齐 pg 口径）——Azure SQL 等强制 TLS 场景手动开启 `ssl`，自签环境配 `sslInsecure`（表单 hint 风险标注）；③ 编辑回传日期时间文本经 tedious 原生类型显式绑定（DateTime2/Date/Time）——规避字符串直传受会话 DATEFORMAT 影响的非确定性隐式转换；④ T-SQL 约束名（PK__/DF__ 前缀随机后缀）无法从 TableSpec 推导——`buildAlterTable` 连接层先查 `sys.key_constraints`/`sys.default_constraints` 再传入纯函数生成层；⑤ IDENTITY 不可原地增删（引擎限制）——结构编辑器对该差异抛 `E_UNSUPPORTED` 提示重建表。
- **契约与 CI**：`MSSQL_HOST` 等环境变量门控（同 PG/MONGO/MYSQL 口径：本地 skip、CI `mcr.microsoft.com/mssql/server:2022-latest` service 实跑）；fixture 专用库 `cf_test`（三段名全限定建表——mssql 池下 `USE` 只改写单个物理连接，P-36 同族教训前置规避）；契约面与 mysql/pg 对齐（connection/metadata/pagination/filter-pushdown/changeset/cancellation/sql-value-encoding/ddl/database-ddl/interactive-transaction 十组全实跑）。
- **否决案**：树库层 = 真实 database（树/Host 删表路径/RPC 均需改动，且 schema 层无处安放——再加 folder 层则树多一层、P-40 when 子句风险重演）；`SCOPE_IDENTITY()` 回填（仅覆盖单列数值 IDENTITY，复合主键/uniqueidentifier 场景无回填）；core 扫描器支持 GO（见决议 4）；Azure SQL Edge 本地实例（用户已确认完全依赖 CI，本机 ARM 无容器运行时 P-28）。

### D-22 ER 图：自绘 HTML+SVG 混合渲染 + core 分层布局纯函数 + 关系收集零新增驱动方法（M8-ER，2026-10-15）
- **决议**（五岔口，随本设计稿定稿）：
  1. **渲染 = 自绘「HTML 节点层 + SVG 边层」混合**（同一 transform 容器、同一坐标系；pan/zoom 经外层 transform、节点卡片为常规 DOM、边为 SVG path），**零新增图形库依赖**；CSP/nonce（C-11）与语义 token（C-12）全走既有口径。
  2. **布局 = core `services/erLayout.ts` 简化 Sugiyama 分层纯函数**（最长路径分层 + 层内重心排序 + DFS 确定性打环；自引用边不入分层约束）——同输入同输出、快照可测；布局在 Host 侧计算（C-13 口径），Webview 只做视口变换 / 节点拖拽 / 命中高亮（交互纯函数化，有单测）。
  3. **关系收集 = core `services/erModel.ts`，零新增驱动方法**——只消费既有 `listObjects`/`listColumns`/`listKeys` 自省（FK 数据表设计器批次 B 已契约化）；FK 按约束名合并逻辑自 `tableSpec.specFromTable` 上移为共享纯函数（上移不复制）。
  4. **能力 = `capabilities.supportsErDiagram?: boolean`**（声明 = listKeys 的 FK 元数据完整可用；未声明树无入口）。首批矩阵：mysql / pg / mssql / sqlite / mock ✓；redis / mongo ✗。
  5. **协议 = `er.getGraph`（scope: all / selection）+ `er.openTable`**，zod 单一来源（C-5/D-06），无事件帧；批次 1 只实现 all/selection（表节点邻接入口为 P2，届时再扩 scope）。
- **理由**：
  - React Flow（@xyflow/react）+ elkjs（ER 图惯例组合）评估：交互覆盖远超需求（minimap/端口系统/连线拖拽），代价是 webview bundle 增量 + 默认样式硬编码色值需逐项覆写回 token（C-12 治理面）+ 三个新依赖的升级与打包面，而本批所需交互（缩放/平移/节点拖拽/适应画布/悬停高亮）自绘数百行可覆盖；自定义节点卡片（表名 + 列清单）本就是主体工作量、任何方案都逃不掉。与仓库自研基建先例（P-24 切分器、自研轻量建议/补全组件、自研 RPC）一致；P2 导出 SVG 在自绘路径上也更直接（DOM 即图源）。
  - Canvas / WebGL：为万级节点设计，本批 ≤300 节点（数千 DOM 元素）常规 DOM 完全承载；命中测试、无障碍、文本排版全手工的成本不成比例，且导出 SVG 需双轨实现。
  - 分层 vs 力导向：ER 边有语义方向（FK 多端 → 被引用一端），分层图保留方向感、层内阅读秩序，可读性显著优于力导向；且确定性输出是纯函数快照测试的前提（力导向迭代收敛结果不稳定，测试只能断言分布性质）。
  - 零新增驱动方法：新增 `getRelations` 类方法会重复 listKeys 已契约化的同一自省面，且要动五驱动 + 契约组（大批次）；能力布尔声明 + 既有方法消费让本批改动面集中在 core/protocol/webview。
- **代价与缓解**：① 自研交互的维护面（缩放/命中/边路径）——交互逻辑纯函数化（视口变换/命中测试/降级档位/锚点计算）进 vitest；无 minimap 等高阶件（P2 按实机反馈评估）。② 分层布局边交叉质量低于完整 Sugiyama（无精确交叉计数优化）——重心法多轮扫描 + 层距常量调优，快照基线人工评审；环形 FK（循环引用）打环后存在回边，路径锚点按垂直兜底。③ 表节点邻接入口（P2）需动 table 节点 7 条既有 when 正则——P-40 影响面大，首批只动 database 节点 3 条锚定正则（清单见交互稿 §13.1）。④ 大库护栏——表 300 硬上限 + 三档渲染降级 + 选择模式（交互稿 §13.2）；列 ≤ 256/表。⑤ Webview 重载不恢复画布状态——元数据走缓存重拉毫秒级，刻意从简（§12.7 同口径）。
- **否决案**：React Flow + elkjs / dagre（理由见上，非「库不好」而是需求面小 + token 治理成本 + 自研路径对导出/确定性的顺承）；d3-force 力导向（方向感丢失 + 非确定性）；Canvas/WebGL 自绘（万级节点过度设计）；新增 `IConnection.getRelations` 驱动方法（重复 listKeys 自省面，五驱动 + 契约批次成本不成比例）；导出进首批（P2，设计保留在交互稿 §13.9）。

### D-23 Oracle 驱动：node-oracledb thin + PDB service 连接绑定 + schema 上树（D-15/D-21 同构）+ 一次全量（M8-Oracle，2026-10-18）

> 状态：**设计定稿草案——九岔口推荐方案待用户确认**（确认后按本 ADR 进实现批次；契约实例摸底记录见文末，全部结论为常驻真实实例实测）。

- **决议**（九岔口，2026-10-18 落盘，待确认）：

  1. **技术选型 = `oracledb`（node-oracledb）^7，thin 模式（默认，纯 JavaScript）**：6.0 起 thin 为默认连接模式，无需 Instant Client（native），符合 D-05/D-12 纯 JS 口径；要求数据库 12.1+（摸底实例 19.19 实测连通）。npm 包内捆绑的 thick 预编译二进制**永不触达**（不调 `initOracleClient()`）——esbuild 标 `oracledb` external + 构建期闭包物化到 `dist/node_modules`（P-32/P-35 同族，ssh2/exceljs 先例）。thick 模式直接否决（native：D-05 条件 2 + VSIX 平台分包 + Instant Client 安装负担）。

  2. **库层语义（本批次最大岔口）= 连接绑定单个 PDB（service 寻址）+ 树 database 层 = schema（D-15/D-21 同构）**：
     - Oracle 拓扑：实例（listener）→ CDB → PDB → schema（≈user）。应用级连接按业界惯例直接绑定目标 PDB（`host:port/<service_name>`），**树 database 层 = 当前 PDB 内的非系统 schema**；全部接口 `db` 参数 = schema 名、`obj` 恒为裸表/视图名，驱动生成语句显式 `"schema"."table"` 两段名限定——Host 删表路径 `q(db).q(obj)` 恰好输出合法两段名（D-15 论证①原样适用），树/RPC/Console 绑定/补全/元数据缓存零改动。
     - `listDatabases()` = `ALL_USERS` 排除 `ORACLE_MAINTAINED='Y'`（19c 实测该列存在）——**全量业务 schema 上树**（含当前无可见对象的 schema；展开无权限时报 E_PERMISSION，比静默隐藏更可诊断）。`PDBADMIN`（PDB 本地管理员，`ORACLE_MAINTAINED='N'`）视同业务 schema 保留（与 mssql `dbo` 保留同口径）。
     - 连接表单**「服务名」字段承载寻址**（`serviceName`，必填）——Oracle 无「连接后切换库」语义，连接即绑定 PDB；SID 与 service 是两种寻址形态（EZConnect `host:port/name` 两者均可命中，listener 先按 service 后按 SID 解析），表单单一字段 + hint 消歧（摸底实例：CDB 服务 `ORCLCDB` 与 SID 同名直填可达，PDB 用其注册服务名 `orcl`）。高级组 `connectString` 字段承载完整 EZConnect/TNS 描述符覆盖（填写后忽略主机/端口/服务名——RAC/SCAN/LDAP 等场景逃生口）。高级组 `role` 下拉（normal ‖ sysdba，缺省 normal）——SYSDBA 连接用于管理场景（如全库浏览），thin 模式支持 `privilege: SYSDBA`（实测）。
     - `dynamicOptions='databases'` / `listDatabaseOptions` **首批不实现**：树上「库」（schema）与连接寻址（service/PDB）不是同一层——把 schema 列表填进服务名建议框反而误导；服务名输入保持自由手输 + placeholder 示例（P2 再评估经 `v$services` 的特权建议数据源）。

  3. **首批范围 = D-21 一次全量**（非 D-17 只读先行拆批）：连接/测试、元数据自省、分页取数、筛选下推、**变更集（短事务 + 字段级乐观锁 + RETURNING 回填）**、Console（`supportsSQL`）、表结构编辑器（create/alter 全 Tab）、库级 DDL（建/删 schema）、ER 图（`supportsErDiagram`）、交互式事务会话、取消（break）、方言补全词表（C-14）。理由：① Oracle 是 SQL 数据源，编辑链路与既有 SQL 驱动完全同构（无 Mongo 文档模型映射的独立设计轮需求——D-17 拆批的动机不存在）；② 常驻真实实例在手，C-3 红绿可本地闭环不押 CI（用户既定口径）；③ 机制不确定性已在摸底轮全部实测消除（见文末摸底记录），「只读先行探路」的信息价值为零；④ D-21 是形态最接近的先例（schema 上树 + 纯 JS 驱动 + 一次全量交付）。

  4. **空串即 NULL（C-7 裁剪，Oracle 引擎本质）**：Oracle 无「空串 ≠ NULL」——`''` 存入即 NULL（实测 `INSERT ''` → `IS NULL` 命中），空串**永远读不回**。口径：① 编辑/新增输入空串 → 落 NULL（与 Oracle 生态工具惯例一致），**预览/提交回执提示「空串已按 NULL 存储」**（一次性文案，不阻断）；② 值编码契约 §5 的新增注记：Oracle 驱动「空串 ↔ NULL 单向折叠」，契约套件值编码组的 `c_empty` 用例对 Oracle 特化为「写 `''` → 读回 `null`」断言（不是简单裁剪——把引擎语义测死）；③ `NULL` ⇄ 空串右键切换（交互稿 §4.5）在 Oracle 上「切换为空串」入口隐藏（引擎无该值域），其余驱动不变。
     - 同族推论（编辑链路自洽性）：乐观锁 WHERE 的「变更列原值 = ''」恒等价 NULL → 生成 `IS NULL`，D-03 口径无特化分支。

  5. **标识符大写存储（如实返回，不做视觉折叠）**：未加引号标识符一律折叠为大写存储（实测 `LowerCol` → `LOWERCOL`，引号名原样保留）。`listObjects`/`listColumns` **返回存储形态**（大写），树上/网格/补全如实显示——所见即所得，DDL/SQL 生成与库内一致；契约 fixture 建表用无引号小写名（`cf_users` → 存储为 `CF_USERS`），套件断言一律按 `listColumns`/`listObjects` 返回名对齐（套件自洽，零裁剪）。

  6. **NUMBER 精度（fetchRows 保真 + Console 限制声明）**：thin 模式默认把 NUMBER 取回为 JS number——`9007199254740993` 实测丢精度为 `…992`（>2^53 失真，mssql Decimal 同族）。口径：
     - **fetchRows（表格/编辑主路径）：执行级 `fetchInfo` 按列指定 STRING 取回**（实测保真返回 `'9007199254740993'`）——列集来自 `listColumns` 先行自省，NUMBER → string 后由驱动按列声明整形（scale=0 且 \|v\| ≤ 2^53 → integer number；否则 decimal string 保精度）。同路 CLOB→string、BLOB/RAW→Buffer（实测均生效）。
     - **query（Console 路径）：列集执行前未知，接受 JS number 形态**——>2^53 NUMBER 在 Console 结果失真，README 已知限制声明 + 契约值编码组取安全精度（mssql tedious Decimal 先例同口径，§5.6）。
     - 否决：全局 `oracledb.fetchAsString`——实测有效但为**进程级污染**（L2/L3 第三方驱动同进程运行，D-05；P-44 pg 全局 setTypeParser 否决同精神）。另实测 thin 模式连接级 `conn.fetchAsString` 与 `fetchTypeHandler` 回调被静默忽略（见摸底记录③）。

  7. **分页 = `OFFSET ? ROWS FETCH NEXT ? ROWS ONLY`（12c+）**；取消 = **`connection.break()`**：thin 要求数据库 12.1+，OFFSET/FETCH 恒可用（ROWNUM 包装的 legacy 兼容分支不需要，不做）。`break()` 实测下发 OOB 取消（ORA-01013）且**连接可复用**——`supportsCancel = true`（如实声明，契约取消组实跑；mysql 无 OOB 声明 false 的对照先例）。实现模式：在途查询期间从池 checkout 专属连接持有，abort 信号 → `break()` → 归还（P-36 池化语义下 break 必须定向到在途连接）。

  8. **DDL 查看 = `DBMS_METADATA.GET_DDL`（transform 减噪）**；表结构编辑 = 生成器自研（`buildCreateTable`/`buildAlterTable`——表设计器契约必需，diff 生成与 GET_DDL 无关）。**库级 DDL = `CREATE USER`（建 schema，表单含密码 + USERS 表空间配额）与 `DROP USER … CASCADE`（标 destructive，删库级联删对象）**；ALTER 不做——Oracle 用户不可重命名（`ALTER USER` 仅口令/配额/角色维度，无改名语义），「编辑库」菜单不出现（方法存在性裁剪，D-19 口径）。`GET_DDL` 权限：自有对象免角色（实测），跨 schema 需 `SELECT_CATALOG_ROLE`——README 权限矩阵声明。

  9. **契约门控 = `ORACLE_HOST`/`ORACLE_PORT`/`ORACLE_SERVICE`/`ORACLE_USER`/`ORACLE_PASSWORD`（+ `ORACLE_ADMIN_USER`/`ORACLE_ADMIN_PASSWORD`，fixture 重建用）**：PG/MONGO/MYSQL/MSSQL 五先例同口径——本地（常驻实例 env 注入）实跑、未设 skip；**CI 用 `gvenzl/oracle-free`（slim-faststart 变体）service 实跑保底防「契约静默缺考」**。fixture = 专用 schema `cf_test`：beforeAll 经管理连接（SYSDBA）`DROP USER cf_test CASCADE` → `CREATE USER … QUOTA UNLIMITED ON USERS` → 授权 → 以 cf_test 连接写种子；契约组主连接 = `ORACLE_USER`（应用账号），跨 schema 用例 `db='CF_TEST'`；afterAll `DROP USER CASCADE` 清理（mssql cf_test 整库重建同构）。应用账号权限矩阵（README 声明）：`CREATE SESSION`、`RESOURCE`（表/序列/过程）、`CREATE VIEW`（**19c 的 RESOURCE 不含 CREATE VIEW，实测缺它建视图 ORA-01031**）。
     - **CI 磁盘预算**：oracle-free 镜像数 GB 级（slim 变体约 1~2GB）+ 现有 5 个数据源 service 已在 14GB runner 上——**Oracle 契约放独立 job**（`services: oracle-free` + ORACLE_* env 注入），主 CI job 不加 service：互不拖慢、磁盘隔离，失败定位面也窄。

- **值编码映射（设计定稿，实现批次平移驱动规范 §5.7）**：

  | Oracle 类型 | NormalizedType | 编码形态 |
  |---|---|---|
  | NUMBER(p,0) 且 \|v\| ≤ 2^53 | `integer` | number（fetchInfo STRING 取回后整形） |
  | NUMBER 整数超限 / NUMBER(p,s)/FLOAT | `decimal` | 字符串保精度 |
  | BINARY_DOUBLE / BINARY_FLOAT | `float` | number |
  | CHAR/NCHAR/VARCHAR2/NVARCHAR2 | `string` | 原样；**空串恒为 NULL（岔口 4）** |
  | CLOB / NCLOB | `string` | fetchInfo STRING 取回（超长截断展示，`lazyCell` P2） |
  | DATE | `datetime` | `'YYYY-MM-DD HH:mm:ss.000'`（秒精度补 `.000`） |
  | TIMESTAMP(n) | `datetime` | `'YYYY-MM-DD HH:mm:ss.SSS'` |
  | TIMESTAMP WITH (LOCAL) TIME ZONE | `datetime` | UTC 渲染、原始偏移丢失（mssql datetimeoffset 同口径，README 声明） |
  | RAW / BLOB | `binary` | base64（fetchInfo BUFFER → base64） |
  | ROWID / UROWID | `string` | rowid 原文 |
  | LONG / LONG RAW | `string` / `binary` | 遗留类型尽力支持（大取数慢，README 限制） |
  | XMLType / 对象 / 集合类型 | `unknown` | 原样文本尽力展示（README 限制） |
  | INTERVAL 类型 | `unknown` | 字符串化 |
  | 日期口径 | — | thin 模式把 DATE/TIMESTAMP 转 JS Date 按**客户端进程本地时区**解释（实测无视会话 `TIME_ZONE`）——驱动按 Date 本地组件格式化墙上时间（无时区后缀），tooltip「按连接时区解释」；编辑回传 datetime 文本 → 驱动转原生参数（绑定 DATE/TIMESTAMP 文本字面量参数化，禁拼接） |

- **变更集要点**：短事务 = 池 checkout 单连接承载整个批次（BEGIN 隐式于首条 DML，COMMIT/ROLLBACK 显式，**归还前必须终结事务**——实测 pool release 未 commit 即回滚，安全默认但要显式化）；乐观锁 WHERE = RowKey + 变更列原值（NULL → `IS NULL`，D-03 原样）；INSERT 回填 = `RETURNING <主键列> INTO :out`（实测 thin 生效）；IDENTITY 列（`GENERATED … AS IDENTITY`，`all_tab_identity_cols` 自省 autoIncrement）——契约套件「混入 insert 跳过自增主键列」已通用（mssql P-54① 先例），生成器用 `GENERATED BY DEFAULT AS IDENTITY`。
- **元数据自省**：`all_tables`/`all_views`（对象）、`all_tab_columns`（列——data_type + data_precision/data_scale/char_length 组装 `NUMBER(12,2)`/`VARCHAR2(64 BYTE)` 原文；`data_default` 为 LONG 型可读，字符串默认值带引号 → 去引号 roundtrip，P-49 同族）、`all_constraints`+`all_cons_columns`（PK/UK/FK，FK 经 `r_constraint_name` 回链引用侧、`ALL_CONSTRAINTS` 列序 = position）、`all_indexes`+`all_ind_columns`（二级索引；函数索引列表达式跳过）、`all_tab_comments`/`all_col_comments`（注释）、`all_tab_identity_cols`（自增）、`all_tables.num_rows`（行估算——**无统计信息时为 NULL，实测**：rowEstimate 缺省不 COUNT（C-9）；可选 `DBMS_STATS` 收集不在驱动职责内，README 注记「行估算依赖优化器统计」）。admin 账号（DBA 角色）经同一 all_* 视图获全库可见性（实测），最小权限账号见自有 schema——权限即视图边界，无需两套自省。
- **Console 与危险判定**：`supportsMultiStatement = false`（core 逐语句执行，mysql/pg/mssql 同口径）；`USE` 语句不存在于 Oracle 方言（无该语句语义——连接绑定 PDB 恒定，P-36 拦截分支天然不触达，schema 限定靠两段名）；PL/SQL 匿名块（`BEGIN…END;`）作为单语句下发执行（危险判定沿用 sqlDanger AST+正则降级，PL/SQL 块形状的误判属既有限制不特化）。
- **理由**：① thin 纯 JS 是 Oracle 生态在 D-05 约束下的唯一解（Instant Client 否决即 thick 否决）；② schema 上树是 D-15 在 PG、D-21 在 mssql 两次验证过的零改动路径，Oracle 的 CDB/PDB 拓扑不改变「连接协议绑定单容器」的事实（PDB service 即连接单元）；③ 一次全量的三个前提（同构性、实例在手、机制已实测）全部成立；④ fetchInfo 是 thin 模式下唯一不污染进程的按列取回控制面（实测三机制对比后唯一有效路径）。
- **代价与缓解**：① 空串=NULL 是全产品唯一「输入值 ≠ 读回值」的驱动——预览/回执提示 + §4.5 入口裁剪 + 契约测死引擎语义（岔口 4）；② Console 大数失真（README + 契约安全精度，mssql 先例）；③ CI 镜像体积——独立 job + slim 变体（岔口 9）；④ TSTZ 偏移丢失与客户端时区解释——README 时区行为声明（§13 checklist 既有项）；⑤ `data_default`/函数索引列表达式为 LONG 型——node-oracledb 可读（实测）但每列一次往返，自省 SQL 保持按表单查询不受影响；⑥ 大写折叠对「小写偏好」用户的心智成本——hint/README 说明（Oracle 无配置可改存储大小写，如实呈现是唯一诚实口径）。
- **否决案**：thick 模式 + Instant Client（native 三重成本，岔口 1）；PDB 上树（需 C## common user + `ALTER SESSION SET CONTAINER`，池化下容器切换即 P-36 同族 ×10，且应用账号惯例在 PDB 内）；schema folder 两层 + `obj` 全限定名（D-15 否决案重演）；全局 `oracledb.fetchAsString`（进程级污染，岔口 6）；`ROWID` 作为无主键表 RowKey（技术上可行——实测可读——但 ROWID 随行迁移/导出导入漂移，且与 D-03「无主键默认只读」的全驱动一致性冲突，**P2 评估**：若做，仅作 Oracle 驱动的可开关增强并 README 风险声明）；D-17 只读先行（岔口 3）；`DBMS_LOCK.SLEEP` 取消组模板（EXECUTE 默认未授予 PUBLIC）——用 `DBMS_SESSION.SLEEP(n)`（12.2+ PUBLIC 可执行）。
- **摸底记录（2026-10-18，常驻实例实测，实现批次的坑位索引——届时随实现更新 AGENTS）**：
  - **实例拓扑**：`100.125.188.135:1521`，SID/service `ORCLCDB`（CDB$ROOT，19.19.0.0.0 EE，CDB=YES），PDB `ORCL`（READ WRITE，注册服务名 `orcl`）；已建应用账号 `dbkit` / 契约账号 `cf_test`（`CREATE SESSION`+`RESOURCE`+`CREATE VIEW`+`USERS` 无限配额；dbkit 另有探针用 `SELECT ANY TABLE`——实现批次按最小权限口径复核）。契约门控 env 与之对齐：`ORACLE_HOST=100.125.188.135 ORACLE_PORT=1521 ORACLE_SERVICE=orcl ORACLE_USER=dbkit ORACLE_PASSWORD=… ORACLE_ADMIN_USER=sys ORACLE_ADMIN_PASSWORD=…`（测试实例凭据，m6cipass 先例可入文档）。
  - **thin 行为三坑**：① `conn.execute(sql, binds, undefined)` 第三参显式传 `undefined` → `NJS-005`（省略第三参即可）；② 连接级 `conn.fetchAsString`（含 NUMBER）与 `fetchTypeHandler` 回调 thin 模式**静默忽略**，全局 `oracledb.fetchAsString` 有效但进程级污染——按列控制一律走执行级 `fetchInfo`（键 = metaData 返回列名，未引号列大写）；③ DATE/TIMESTAMP → JS Date 按**客户端进程本地时区**解释（实测 `ALTER SESSION SET TIME_ZONE` 不影响该转换），驱动侧本地组件格式化。
  - **语义实测**：空串存入即 NULL、`WHERE col=''` 恒空；`LowerCol` 折叠 `LOWERCOL`；OFFSET/FETCH 生效；`RETURNING id INTO :out` 生效；`break()` → ORA-01013 且连接可复用；`num_rows` 无统计为 NULL；`ALL_USERS.ORACLE_MAINTAINED` 存在；19c `RESOURCE` 不含 `CREATE VIEW`；池连接 close 未提交即回滚；`DBMS_METADATA.GET_DDL` 返回 LOB 对象（须 STRING 取回）且自有对象免角色。

### D-24 AI 辅助：就地嵌入 + BYOK OpenAI 兼容 provider（M9-AI，2026-10-23）

- **背景**：遗留 #3（AI provider 抽象）到达 P2 启动时点；§6 #10（NL→SQL / SQL 解释 / 错误修复建议）立项。四岔口用户确认（2026-10-23）：交互形态 = **SQL 编辑器就地嵌入**（否决自建聊天面板与 chat participant 首批方案）；provider = **BYOK**（否决 Copilot LM API 首选——零配置收益不抵订阅强依赖，LM API 降为可选后续实现）；范围 = **三能力齐做**；呈现 = 生成**直插编辑器**、修复走 **diff 确认**。
- **决议**：
  1. **Provider**：core `AiProvider` 抽象（`complete({ system, prompt, signal, onDelta })` 流式）+ 首实现 `OpenAICompatProvider`（OpenAI 兼容 chat completions，fetch 直连 + SSE 流式解析）——一家接口覆盖 OpenAI/DeepSeek/Moonshot/ollama/vLLM/企业网关。endpoint/model 落 `dbExplorer.ai.endpoint` / `.model`（settings，可同步）；key 只进 SecretStorage（`dbExplorer.secrets.ai`），设置页不回显明文、saveSettings 缺省不修改。**不内置任何默认 endpoint**。
  2. **交互形态**：三入口全嵌既有面——CodeLens「✨ 生成 SQL」（sqlCodeLens 同源语句定位）/ 编辑器右键 / 消息 Tab 错误 item 动作；呈现面复用编辑器（直插 + 选中）与 Console 结果面板（「AI 解释」Tab，消息通道扩展）。不自建聊天面板（否决案），`@dbkit` chat participant 列 P2。
  3. **护栏不变式（本 ADR 最重条款）**：AI 产物一律作为**草稿或 diff**，**绝不直接执行、绝不自动替换**——生成直插后由用户审改自行执行；修复 diff 需显式选择「替换/插入」。执行链路零改动：DangerGuard 危险判定、prod 输表名确认、只读拦截、参数化全部照常生效（AI 生成的无 WHERE DELETE 照样被拦）。applyFix 带 fixId = 文档版本 + 语句偏移绑定，失配 `E_STATE_LOST` 拒绝应用。
  4. **上下文与隐私（C-10 延伸）**：默认只发 schema（MetadataCache 表/列/类型/注释），数据行任何 v1 路径不发送（采样行 opt-in 列 P2）；prompt 组装收口纯函数 `aiPrompt.ts`（单测断言密钥/密码/连接串/主机不入 prompt）；>50 表 QuickPick 圈选（会话级记忆）。设置页固定隐私说明文案（表结构将发送给你配置的服务）。
  5. **错误码（C-6 扩展）**：新增 `AiErrorCode` 族 `E_AI_NOT_CONFIGURED` / `E_AI_REQUEST_FAILED` / `E_AI_ABORTED`，与 DriverErrorCode 并列；UI 仍按 code 映射不解析文本（errors.ts 扩展文案表）。日志打点 info（方法/绑定/耗时/token 用量），prompt 内容与密钥不落日志。
  6. **协议（C-5）**：`ai.getSettings / ai.saveSettings / ai.testSettings / ai.fixError / ai.applyFix`；生成与解释走编辑器 Host 命令 + console item 推送（不经新 RPC）。
- **理由**：① 就地嵌入与产品「可解释、可审计」气质一致，实现面复用三个既有模式（CodeLens / Console 消息通道 / 变更预览 Modal 骨架）；② BYOK 把 provider 选人权交给用户（含本地模型），插件不碰订阅绑定与 key 托管，密钥面仍收敛在 SecretStorage 单点；③ 三能力共享同一 provider/上下文/错误码基建，齐做省两次脚手架。
- **代价与缓解**：① schema 外发隐私——设置页明示 + 只发元数据不发数据 + 大库圈选裁剪；② BYOK 配置门槛——未配置入口引导（不隐藏，保可发现性）+ 测试连接即时反馈；③ SSE/网络层实现面——纯 fetch 无新依赖，流式仅解释 Tab 消费，生成/修复等全量返回；④ token 成本不可见——日志记 token 用量，配额治理列 P2。
- **否决案**：自建 AI 聊天侧栏（UI 成本最高、与 VSCode 生态重复）；Copilot LM API 首选（订阅强依赖 + 模型池受限，转可选后续实现）；chat participant 首批（产出仍要「插入到 Console」一步，游离在数据界面外）；默认预置任何第三方 endpoint（隐私与合规风险）；采样行默认开启（数据外发必须显式 opt-in）。

### 12.2 驱动契约测试（必过清单，节选）
1. 连接：错误密码 → `E_AUTH`；不可达 → `E_CONN`
2. 元数据：列含 PK 标记、ordinal 有序；索引/键可列出
3. 分页：offset 翻页结果稳定（按 PK 排序）；`totalCount` 可缺省
4. 筛选下推：每种 `FilterOp` 生成**参数化**语句，结果与内存过滤一致
5. 变更集：insert 回填生成主键；update 冲突 → `E_CONFLICT` 且事务回滚（无半提交）；含 NULL 原值的行正确生成 `IS NULL` 匹配
6. 取消：AbortSignal 生效 → `E_CANCELED`
7. 值编码：每种 `NormalizedType` 写入→读出往返一致（4.4 契约）

套件提供 `runDriverConformanceSuite({ createConnection })`，各驱动在自己的 CI 中调用。

### 12.3 安全用例（专项）
- 全文检索仓库与导出文件：不得出现明文密码/DSN（含错误信息路径）
- 只读连接：穷举所有写入口（表格/Console/树操作）均被 Host 层拒绝
- prod 连接：所有危险路径均触发确认，且无法通过改配置绕过
