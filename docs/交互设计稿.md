## 1. 信息架构与导航

```
活动栏
└── 🛢 数据库（viewContainer: dbExplorer.container）
    ├── 数据库连接树（TreeView，主视图）
    ├── 查询历史（TreeView，P1，历史/收藏两个节点组）
    └── 视图标题栏按钮：[＋新建连接] [⚙ 设置] [⟳ 刷新] [⇕ 全部折叠]

编辑器区
├── 表格视图     → Webview Tab，标题 "表名 @ 库 (连接名)"，图标按驱动
├── SQL Console → 原生 untitled sql 文档 Tab
└── 结果面板     → Webview Panel（用户可拖拽到任意编辑组，如编辑器下方）
```

- 单击表节点 = 打开表格视图（US-01：树聚焦 → 单击，2 次操作）
- 同一表重复打开复用已有 Tab（按 `connId/db/table` 去重），不无限开新 Tab
- 编辑器 Tab 上有未提交变更时显示圆点标记（同未保存文件的脏标记语义）

### 3.2 规则

| 项 | 规格 |
|---|---|
| 字段渲染 | 完全由驱动 `FormSchema` 驱动；无 schema 的分组整体隐藏 |
| 校验时机 | 失焦即时校验；`保存`/`测试` 前全量校验；错误字段红框 + 下方一行错误文案 |
| 校验规则 | required 为空、number 越界、validator（port 1-65535 / host / regex） |
| 测试连接状态机 | `idle → testing(按钮转圈，其余禁用) → ok(状态行绿色 ✓ "连接成功 · 12ms · MySQL 8.0.36"，2s 后淡出) / fail(状态行红色 ✗ + 错误码文案 + "查看详情"链接)` |
| 测试与保存独立 | 测试成功不自动保存；保存不强制先测试，但未测试过时保存按钮旁提示“尚未测试连接” |
| 密码字段 | 永不回显（编辑时显示占位 `●●●●●●`，留空 = 沿用原密码）；不写入任何本地明文 |
| 编辑模式 | 标题变“编辑连接”；删除连接需确认 Modal（§6 简化版，不用输名称） |
| 未保存离开 | 表单有改动时关闭 → 确认“放弃未保存的修改？” |
| 驱动切换 | 切换驱动类型即重渲染字段，已有值按 key 保留，其余丢弃并提示 |
| 动态建议字段（v0.1.8，M8-PG B5） | `dynamicOptions='databases'`（驱动规范 §3.1）：**聚焦时**经 `conn.dbOptions` 拉取服务器库列表，输入框下方浮出建议列表（按当前输入子串过滤、点击回填）；按表单参数指纹（host/port/用户名/密码/驱动）缓存去重，参数变化后重新聚焦才重拉；**全程无感**——拉取中不显示加载态、失败不显示任何错误（建议不出现而已），输入与保存不受影响，手输始终可用；编辑态密码留空 = 沿用已存密钥拉取 |
| 文件选择字段（v0.1.13，M8-SQLite） | `type='file'`（驱动规范 §3.1 枚举首次落地）：渲染为**输入框 + 次级「浏览…」按钮**（左右排列，输入框占满余宽）；点击按钮经 Host `sys.pickFile` 打开原生文件对话框（单选），选中回填绝对路径、**取消不改动现值**；输入框保持自由编辑（手输/粘帖/`~/` 展开路径均有效）——浏览只是加速器不是唯一入口；宿主方法不可用（版本不匹配）时按钮无感降级为纯手输；文件类型过滤由调用方按需传入 `filters`，缺省不过滤（选错文件由驱动的打开校验兜底，如 SQLite 魔数校验 E_VALIDATION） |

## 4. 表格视图

### 4.1 视图状态机（顶层）

```
loading ──数据到达──▶ ready ◀──刷新/翻页──┐
                      │  ▲               │
                      编辑│  │再编辑        │
                      ▼  │               │
                    dirty ──提交──▶ committing ──成功─▶ ready（Toast + 刷新当前页）
                      │                └─失败─▶ error（ChangeSet 保留，错误行高亮，
                      │                                  行内"重试/放弃"操作）
                      ├──预览──▶ preview ──确认──▶ committing
                      │            │ 取消
                      │            ▼
                      │        （关闭弹层，回 dirty）
                      └─撤销全部─▶ ready
```

- 提交（`✓`）**直接单事务落库**（v0.1.3）；`◉` 预览仅查看不提交，需要先核对语句时使用
- `dirty` 态：工具栏 `✓`（提交变更）图标高亮 + 轻微脉冲动画；Tab 标题显示 `表名 ●`
- `error` 态：错误行左侧红条 + 行首 ⚠ 图标；悬停显示错误文案（错误码 → 文案映射见 §9.2）；行级操作 `重试 | 放弃该行`
- 关闭视图且 `dirty` → 确认弹窗“有 N 条未提交变更，放弃并关闭？”

### 4.4 自由条件栏（v0.1.3：WHERE / ORDER BY 手写输入，取代筛选构造器）

```
WHERE [ status = 'active' AND (amount > 100) ✕ ]  ORDER BY [ created_at DESC, id ✕ ]   [▶]
```

- 输入框有内容时右侧出现 ✕（清除该输入框内容，Enter/▶ 重新应用）；无独立清空按钮

- 两个手写输入框：WHERE 条件片段与 ORDER BY 片段，直接拼接到最终查询语句
  （WHERE 以括号包裹与结构化条件/全局搜索保持 AND 语义）
- **ORDER BY 与列头排序双向联动**（输入框为唯一权威）：
  - 列头点击 → 三态切换（无→升→降→移除）并**规范化回写输入框**，箭头指示器同步；
  - 输入框为**自由表达式**（函数/CASE/无法解析到实际列）时，列头排序停用并提示，
    绝不静默覆盖手写内容，指示器不显示（片段仍生效）；
  - 排序参数只走 orderBySql 一路；片段未含主键时，驱动在末尾追加主键升序兜底
    （保证翻页稳定 P-10，且不会压过用户排序）
- 输入时**语法高亮**（prism，与预览/DDL 同一配色）与**补全**：列名（带类型）+ 上下文关键字
  （WHERE：AND/OR/LIKE/IN/IS NULL/…；ORDER BY：ASC/DESC）；↑↓ 选择、Enter/Tab 采纳、Esc 关闭
- Enter（非补全态）= 应用；未应用的改动以蓝点提示；应用即服务端拼接并回到第 1 页
- 语法错误/未知列在应用时由驱动返回 E_VALIDATION：**已有数据时不整页报错**（保留旧数据），
  webview toast 展示具体错误（含语法错误位置），Host 层同时经 VSCode 全局通知呈现（可点开展开详情）
- 补全为 webview 内自研轻量组件（VSCode 未向 webview 开放独立补全组件；嵌入 Monaco 体积过大，
  与两个单行输入不成比例）
- WHERE/ORDER BY 随视图状态持久化（崩溃恢复回放）；导出与表格所见一致（同参数拼接）
- 手写片段属用户自撰 SQL（等同 Console 的权限语义），不做转义/参数化；清除走输入框内 ✕（全局搜索在搜索框内清除）

### 4.5 NULL / 空串切换

- 单元格右键菜单：`设为 NULL`（当前为空串/值时）、`设为空串`（当前为 NULL 时）、`复制值`、`复制为 WHERE`
- 设为 NULL 即进入 ChangeSet（可撤销）

### 4.7 分页栏细则（评审补充）

- `totalCount` 已知：`第 1-50 行 / 共 12,345 行` + 页码跳转
- `totalCount` 缺省（不做全表 COUNT）：显示 `第 1-50 行`；元数据行估算（`rowEstimate`）可得时附 `约 12.3k 行`（“约”字必须带，与精确值区分）；隐藏页码区，仅「上一页/下一页」，翻到空页提示“已是末页”
- 每页行数选择：50 / 100 / 200 / 500

### 4.8 导出进度 chip（v0.1.3，M8 后台化）

- 发起导出（SaveDialog 确认）后工具栏右侧出现 chip：`导出中… N 行 [✕]`，N 随 `evt:export.progress` 逐批增长；`[✕]` 取消该任务（`export.cancel`，终态经 `evt:export.done` 清除 chip）
- 导出为**后台任务**：不阻塞表格任何操作（翻页/编辑/再发起导出均可，多个导出任务并发，各自的进度在 VSCode 通知中心呈现并可在通知上取消）
- chip 只跟随本视图最近发起的任务（按 exportId 过滤）；再次发起导出后 chip 切换到新任务，旧任务继续在后台（通知中心可见）
- 完成：Host Toast `已导出 N 行 → 文件名`（[定位文件] 跳系统文件管理器）；失败：Host Toast 错误信息；取消：静默（chip 清除）

## 5. 变更预览 Modal

入口：工具栏 `◉`（预览提交 SQL）。`✓`（提交变更）为直接提交，不经过本弹层（§4.1 v0.1.3）。

```
┌─ 提交预览（3）─ myapp.users ─────────────────────┐
│ ██ 目标环境：测试 (test) · 连接：本地 MySQL        │  ← 环境色条（prod 为红条）
│                                                  │
│ 2 条 UPDATE · 1 条 INSERT · 0 条 DELETE           │
│                                                  │
│ ┌ ▸ UPDATE users SET name=?, email=?            │ │
│ │     WHERE id=1 AND name=? AND email=?          │ │  ← 参数化语句（SQL 语法高亮），可展开
│ │     参数: ["张三改","z@x.com","张三","z@x.com"]  │ │
│ ┌ ▸ INSERT INTO users (name, email) VALUES (?,?) │ │
│ └ ▸ …                                            │ │
│                                                  │
│ ⓘ 全部语句在单事务内执行，失败自动回滚               │
│                                                  │
│              [展开全部 ▾]   [取消]  [确认提交]      │
└──────────────────────────────────────────────────┘
```

- prod 环境：确认按钮初始禁用，需在环境条旁输入框输入**表名**（匹配后启用），同时无“展开全部”快捷——预览强制逐条可见（概要设计 5.8）
- 语句按行分组：UPDATE 显示 `旧值 → 新值` 摘要行；点击展开看完整 SQL 与参数
- 预览行直接展示**参数回填后的语句**（`?` 按序替换为参数字面量，仅展示层；实际执行仍为参数化语句），展开详情附原始参数列表
- 所有 SQL 展示（预览语句、DDL 查看器等）统一经 `sqlHighlight` 语法高亮，配色映射语义 token（§11）
- 变更超过 50 条时列表默认折叠（仅显示统计行 + 首组），展开后虚拟滚动，1000+ 条不卡顿
- ESC = 取消；确认后 Modal 关闭，表格进入 `committing`（工具栏按钮转圈，禁止编辑）

## 7. SQL Console

### 7.1 编辑器绑定

- 新建 Console = untitled `sql` 文档 + Host 内存绑定 `{ connId, db }`（树上入口已由「查询」目录取代，v0.1.9；历史重跑仍按此创建 untitled 文档）
- 状态栏（编辑器右下）常驻：`🛢 本地 MySQL · myapp ▾`，显示**当前活动编辑器**的绑定（每个 .sql 文件绑定独立，切标签跟随；tooltip 带当前文件名，v0.1.15），点击切换连接/库（列出该连接的库）
- 未绑定连接时执行 → 提示“请先选择连接”并聚焦状态栏选择器
- 另存为 `.sql` 文件后，绑定持久化到 `workspaceState`，重新打开文件自动恢复；**状态栏改绑与执行时选库同样持久化**（v0.1.15：file 文档写 fileBindings——此前仅内存、重启悄悄回退旧绑定）
- 树「查询」目录打开的文件：**目录即事实源**（v0.1.15）——文件位于 `<connId>/<db>/` 目录，绑定与目录不一致（文件被移动/复制、早期绑定残留）时打开即自动校正并持久化（§8.2）

### 7.2 执行

- `Ctrl+Enter`：有多行选区 → 执行选区；否则执行光标所在语句（`node-sql-parser` 切分定位）
- **CodeLens「▶ 执行」（v0.1.11）**：每条可执行语句上方显示执行动作，点击执行该语句——与 `Ctrl+Enter` 同一执行链（未绑定时同样先提示选择连接；语句定位复用字符串/注释感知的切分器，注释内分号不误切）
- **行内执行结果注记（v0.1.12）**：执行完成后语句行尾内联显示结果（装饰器渲染，**不写入文档内容**，类 GitLens 行内 blame）——成功：耗时（如 `  12ms`）**绿色** + 行号左侧绿色 ✓ 图标；失败：错误消息（截断 60 字符，完整内容 hover 可见，含错误码）**红色斜体** + 行号左侧红色 ✗ 图标；取消：灰色「已取消」。文档一经编辑注记即清除（语句偏移失义）；新一轮执行以最新结果为准（先清后标）；多语句批量执行逐语句各自标注；Ctrl+Enter / CodeLens / 选区执行均生效（结果面板重跑与历史重跑无文档来源，不标注）
- 执行中：状态栏转圈 + 可点击取消（转为 AbortSignal，`E_CANCELED` 静默提示“已取消”）
- 结果面板未打开时自动在当前编辑组右侧打开；已打开则复用（D-02）

┌ 结果面板 ────────────────────────────────────────┐
│ [结果 1 (50 行)] [结果 2] [消息]        [⇩导出] [⨯] │

### 8.3 库级操作（v0.1.16，M8-DBDDL / 概要 D-19）

- **菜单显隐（按驱动能力，P-40 regex）**：连接节点「新建库」（`supportsDatabaseDdl` 且驱动实现 buildCreateDatabase——MySQL/PG）；database 节点「编辑库」（实现 buildAlterDatabase——仅 MySQL）与「删除库」（实现 buildDropDatabase——MySQL/PG/Mongo）。只读连接一律拒绝（Host 层 fail-closed）
- **新建/编辑库 = Webview 动态表单弹窗**（`databaseDesign` 单例面板，tableDesignPanel 同构）：字段由驱动 `getDatabaseFormSchema()` 提供（MySQL：名称必填 + 字符集/排序规则下拉；PG：仅名称，hint 明示「库」= schema（D-15））；编辑态以 `listDatabases` 当前值预填（name 只读、charset/collation 可改，无差异提交提示「无变更」）；底部「预览 SQL」→ destructive 语句红条（复用表结构编辑器样式）→ 执行逐条失败即停，成功后关面板 + 缓存失效 + 树刷新
- **删除库 = 树右键原生确认**（不进面板）：InputBox 输入库名完全匹配（同删表口径）；prod 环境追加分级确认；destructive 语句（DROP SCHEMA CASCADE）在确认文案明示「将连带删除库内全部表」
- **回撤口径**：新建/编辑失败不回滚已执行条（DDL 隐式提交），错误提示「第 N 条失败（code）」；删除库取消（输入不匹配/Esc）无任何副作用

## 12. 表结构编辑器（表设计器，概要设计 §5.9；Tab 化修订 2026-10-13）

对表的增删改与列的增删改共用一个页面：**新建表**与**修改表结构**是同一编辑器的两种初始态。编辑器按 **Tab 组织：列 / 键 / 外键 / 索引**，各 Tab 共同编辑同一份 `TableSpec`（单一状态源：Tab 间切换不丢改动，权威语句集始终由驱动对整份 spec diff 生成）。入口（M8-B2 起始，Tab 化不变）：

- 库节点 / 「表」目录右键 → **新建表**（create 态：空白模板，表名必填）——目录节点仅此一个动作
- 表节点右键 → **修改表结构**（alter 态：预载库内当前结构）/ **删除表**（不进编辑器，直接走 §6 危险确认 Modal）
- 「列」目录右键 → **新增列**；列节点右键 → **编辑列 / 新增列 / 删除列**
  - **新增列 / 编辑列**：复用表结构编辑器（alter 态）——打开后落在**列 Tab**，新增列自动追加空行、编辑列定位到目标列，均滚动可见并聚焦列名输入框；权威语句集始终由驱动 diff 生成
  - **删除列**：不进编辑器——§6 输入**列名**匹配确认后，直接生成并执行 ALTER（语句经驱动同源 diff，自动处理删主键列需先 DROP PRIMARY KEY 的顺序），成功后元数据失效 + 树刷新
- 驱动未声明 `supportsDdlEditor` 时以上入口不出现（能力降级，同 §4.1.1 原则）
- Tab 显隐按驱动能力裁剪（§12.2 能力矩阵）：未声明对应能力的驱动，编辑器回落为纯「列」Tab（v0.2.1 形态），无感降级

### 12.2 Tab 与驱动能力矩阵

驱动在 `capabilities.tableDesign` 声明能力，`ddl.load` 以下发 `features`（Tab 显隐）与 `dataTypes`（列 Tab 类型建议词表）透传；未声明的 Tab 隐藏，三方驱动无感降级为纯列编辑。

| Tab / 能力 | MySQL | PG | MSSQL | SQLite | mock | 三方未声明 |
|---|---|---|---|---|---|---|
| 列 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓（随 supportsDdlEditor） |
| 键 · 主键（alter 变更） | ✓ | ✓ | ✓ | ✓（走表重建序列） | ✓ | 随列 Tab（既有） |
| 键 · 唯一键 | ✓ | ✓ | ✓ | ✓（走表重建序列） | ✓ | 隐藏 |

- SQLite 无原地 `ALTER TABLE ADD/DROP CONSTRAINT`：外键 alter 态只读展示基线外键 + 黄条「SQLite 不支持原地修改外键；可在新建表时声明，或经 SQL Console 重建表」；唯一键 alter 与列结构变更同走表重建序列（标 destructive）。

### 12.3 列 Tab

| 项 | 规格 |
|---|---|
| 列网格 | 行内编辑（复用表格编辑交互：失焦即确认、Esc 取消）；行尾 ✕ 删除该列（删除行红底可撤销）；「＋添加列」追加空行并聚焦列名 |
| 字段级错误位（本轮修订） | 错误显示在**出错字段正下方**（列名错 → 列名下、类型错 → 类型下），不再统一挂在列名上。每个输入单元格下方**固定预留一条错误位（约 14px，等高）**：无错误时空白，有错误时红字填入——行高恒定，输入框任何时刻保持垂直居中、不跳动。底部状态行继续汇总第一条错误（既有） |
| 校验规则 | 列名非空、行内唯一；类型非空。字符合法性由驱动 fail-closed 校验（`E_VALIDATION`，含引号/分号等 → 执行/预览时报错定位到列）——前端仅做即时提示，不做白名单（方言差异交给驱动） |
| 类型建议下拉（本轮修订） | 输入框形态不变（仍可自由输入），聚焦时弹出当前方言类型建议面板（宽度同输入框，最多 8 项、超出滚动）：键入过滤（子串大小写不敏感）、↑↓ 移动、Enter/Tab 回填、Esc 仅关面板、点击外部关闭。词表项含形参提示的回填模板并定位光标（`varchar()` 光标落括号内、`decimal(,)` 落两参之间），无参项直接回填。词表外类型照常手输——建议不是白名单 |
| NOT NULL 复选（交互修订） | 列网格原「NULL▾」下拉改为「NOT NULL」复选框：**选中 = NOT NULL，不选 = NULL**（spec `nullable` 布尔不变）——勾选语义与主键/自增列统一，免去下拉展开 |
| 控件可见性 | 全部输入框/下拉框带可见边框（`--color-border`）——无值也可辨识可交互；错误态仍以 `border-destructive` 覆盖 |
| 主键/自增 | 主键列网格 checkbox 保留（与键 Tab 主键区同一状态的两个视图）；自增仅 MySQL 语义、勾选时提示「需为主键」；alter 态改主键 → 驱动生成 DROP/ADD PRIMARY KEY（标 destructive） |
| 默认值语义 | 默认值列留空 = 无默认值；输入 `abc` 即字符串字面量（**无需自带引号**，驱动负责加引号与方言转义，fail-closed 校验）；数值与 `CURRENT_TIMESTAMP` 原样使用 |

| 项 | 规格 |
|---|---|
| 卡片结构（成对映射修订） | 每卡一条外键，自上而下：**第 1 行** [名称（留空自动 `fk_<表名>_<n>`，可改）] [引用表 输入+▾] + 组级移除 ✕（**组右上角**）；**第 2 行** 「列对应（本表列 → 引用列）」可变数组——每行一组 [本表列 单选▾] → [引用列 单选▾]，`＋ 添加对应` 增行、行尾 ✕ 删行（仅 >1 组时显示）；**第 3 行** [ON DELETE ▾] [ON UPDATE ▾]。「＋添加外键」追加空卡 |
| 列对应语义 | 每行表达一对列的对应关系（`columns[i] ↔ refColumns[i]`，spec 侧平行数组不变）；不完整组提交前由校验拦截，`buildSpec` 防御性剔除未完成组 |
| 引用表选择 | **输入与选择统一为单控件**（修订二稿）：可输入建议框——聚焦弹主题化表清单、键入过滤、点击/Enter 回填，与列 Tab 类型建议同款交互（**不用原生 datalist**——弹层漂移且暗色主题下发白）；**聚焦时经 `listObjects` 拉取**（复用 `dynamicOptions='databases'` 的数据源链路与降级语义：失败无感降级为手输）；支持手输完整名，存在性由 DB fail-closed 校验。首版范围当前库内引用（跨库引用后续按方言评估） |
| 引用列选择 | 随所选引用表经 `listColumns` 拉取，单选（每组对应各选一列）；类型兼容性由 DB 校验（不前端白名单） |
| 动作选项 | ON DELETE / ON UPDATE：`（无动作）`（不生成子句）/ `RESTRICT` / `CASCADE` / `SET NULL` / `NO ACTION`；驱动经 `refActions` 声明子集裁剪 |
| SQLite alter 态 | 内容区替换为只读基线视图 + 黄条提示（§12.2）；create 态正常内联 `FOREIGN KEY ... REFERENCES` |
| 校验 | 分字段就地显示：名称行内不重复（名称旁）、引用表非空（引用表旁）、每组对应两侧齐全（该行旁，`至少需要一组列对应` 仅首组提示）；组级汇总进状态行与 Tab 红点 |

### 12.6 索引 Tab

| 项 | 规格 |
|---|---|
| 列表 | 每行 [名称（留空自动 `idx_<表名>_<n>`，可改）] [列多选] [唯一 ☐] [类型 ▾（按 §12.2 裁剪，无类型选项时隐藏该列）] [✕]；「＋添加索引」追加空行 |
| 管口径 | 索引 Tab 只管**二级索引**（独立 CREATE/DROP INDEX 语义）；唯一约束归键 Tab（避免唯一索引/唯一约束双入口改同一对象） |
| 生成语义 | MySQL 建表内联 `KEY` / `ALTER ADD·DROP INDEX`；PG/MSSQL/SQLite 生成独立 `CREATE INDEX`/`DROP INDEX` 语句（CREATE TABLE 之后追加进语句集） |
| 校验 | 至少 1 列、名称行内不重复；错误位口径同列 Tab |

### 12.7 通用规则（基线、校验与执行链路）

| 项 | 规格 |
|---|---|
| alter 态基线（本轮扩展） | 打开时经 `ddl.load` 预载当前结构：**列之外，键/外键/索引经 `listKeys`/`listIndexes` 回读进基线**（红线：不回读则 alter 会把库内既有键当「用户删除」误删）。**执行前 Host 重新拉取基线**（防打开期间结构已被他人变更，概要 §5.9）——若基线变化，状态行黄字提示「结构已变更，将基于最新结构重新生成语句」 |
| 删除语句红线 | DROP 约束/索引语句只允许由「基线中存在且用户在编辑器中移除」驱动生成；`listKeys` 未实现（Tab 隐藏）的驱动天然不产生键/索引语句 |
| 校验汇总 | 任一 Tab 校验失败：该 Tab 标题旁红点徽标 + 底部状态行显示第一条错误；「SQL 预览/执行」禁用（`canExecute` 语义扩展） |
| 变更统计 | alter 态按对象类型计数：「新增 1 列 · 修改 1 列 · 新增 1 外键 · 删除 1 索引」（前端按 spec 对比已载入基线粗算，仅供预览前参考；权威语句集以驱动 diff 为准） |
| destructive 口径 | 删列/改类型/主键变更标红（既有，可能丢数据）；删外键/唯一键/索引不丢数据**不标红**，但 alter 态全量确认流照旧 |
| SQL 预览 | 复用 §5 变更预览 Modal 样式（`sqlHighlight` 高亮、逐条折叠）；**destructive 语句红条 + 汇总「N 条语句可能造成数据丢失」**；预览仅展示不提交 |
| 执行确认 | 任一 destructive 或 alter 态：dev/test 确认 Modal；prod 输入表名确认（§6）。CREATE 无 destructive → 直接执行 |
| 执行态 | 执行按钮转圈、全 Tab 禁改；逐条执行失败即停 → 状态行红色定位「第 N 条失败：{错误码文案}」，已执行语句不回滚（DDL 隐式提交，明示「库内结构可能处于中间态，请检查后重试或手工恢复」） |
| 成功后 | Toast「表结构已更新（N 条语句）」→ 自动关闭编辑器 → 元数据缓存失效 + 树刷新（表名列名即时更新） |
| 未保存关闭 | 编辑器有改动（含任意 Tab）时关闭 → 确认「放弃未保存的结构修改？」（同连接表单 §3.2） |
| 只读连接 | 编辑器可打开可修改但「执行」禁用，Tooltip「只读连接，执行被拒绝」；Host 层兜底 `E_READONLY`（§5.8） |
| Webview 重载 | 不恢复编辑中内容（结构编辑非长事务场景，丢失代价可接受；与表格 ChangeSet 恢复策略不同，刻意从简） |

### 12.8 实现锚点与批次拆解

1. **批次 A（快赢，可独立发布）**：列 Tab 字段级错误位 + 类型建议下拉。协议仅加 `ddl.load.dataTypes` 可选字段；驱动 `completion.ts` 升级 `DATA_TYPES`；webview 纯层建议状态机（`dbSuggest` 同构）+ 单测。
2. **批次 B（Tab 化主体）**：core `TableSpec` 扩展可选 `uniqueKeys`/`foreignKeys`/`indexes`（**core 先行、protocol 镜像两处同改，P-41**）→ 契约组 `runDdlChecks` 扩展键/外键/索引 roundtrip 用例跑红（C-3）→ 五驱动生成器与 `capabilities.tableDesign` 声明 → 基线 `listKeys`/`listIndexes` 回读 → Tab 框架 + 三 Tab UI → webview-visual-test 场景脚本同步（P-47）。
3. 概要设计 §5.9 与 ADR（TableSpec 扩展口径）随批次 B 落；AGENTS.md 锚点表「表结构编辑」行随实现更新。

## 13. ER 图（M8-ER）

库级 ER 图**查看**（概要设计 §5.11 / ADR D-22）：给定库 → 表节点 + FK 关系边 + 自动分层布局，用于理解表间关系。首批只做**查看**（浏览 + 布局 + 缩放拖拽 + 基本交互）；图上编辑同步、导出、多库合并等 P2 项在 §13.10 列出且**首批明确不做**。图数据全部来自元数据自省（不触数据行），只读连接照常可用。

### 13.1 入口与打开

- **database 节点右键 →「查看 ER 图」**（首批唯一入口）：按驱动能力显隐——`capabilities.supportsErDiagram` 为 true 时树 database 节点 contextValue **追加后缀令牌 `er`**（令牌序：`database [ddl] [dbddl] [dbddl-alter] [er]`）。首批矩阵：MySQL / PostgreSQL / SQL Server / SQLite / mock（契约基准）= ✓；Redis / MongoDB = ✗（无关系模型，无入口）。
- **P-40 口径——when 子句逐条扩展清单（实现照此执行，不得凭记忆）**：

  | 菜单项 | 既有 when | 扩展后 |
  |---|---|---|
  | `refreshNode` | `viewItem =~ /^connection connected/ \|\| viewItem =~ /^database( ddl)?( dbddl(-alter)?)?$/` | 第二支改为 `^database( ddl)?( dbddl(-alter)?)?( er)?$` |
  | `alterDatabase` | `viewItem =~ /^database( ddl)?( dbddl)? dbddl-alter$/` | `^database( ddl)?( dbddl)? dbddl-alter( er)?$` |
  | `createTable` | `viewItem =~ /^database ddl( dbddl(-alter)?)?$/ \|\| viewItem =~ /^folder-table ddl$/` | 第一支改为 `^database ddl( dbddl(-alter)?)?( er)?$` |
  | `dropDatabase` | `viewItem =~ /^database( ddl)? dbddl/`（**前缀式，尾部不锚定**） | 天然安全不改；实现时仍全量 grep `viewItem` 逐条复核 |
  | 新增「查看 ER 图」 | — | `viewItem =~ /^database( ddl)?( dbddl)?( dbddl-alter)? er$/` |

- 打开即**单例 Webview 编辑器 Tab**（viewId = `erDiagram:<connId>/<db>` 去重，已开则 reveal，tableDesignPanel 同构）；标题 `ER 图 · <db>（连接名）`。
- 表节点右键「以该表为中心展开 N 度邻接」为 **P2**（table 节点加令牌需扩 7 条既有 when 正则，P-40 影响面大；大库局部查看诉求先由 §13.2 选择模式覆盖，等首批实机反馈再评估）。

### 13.2 图范围与大数据量降级

- **首批范围 = 库内全部基础表**（`listObjects` kind=table；视图 / collection 不入图）+ 表间 FK 关系（`listKeys` kind=FK）。
- **硬上限 300 表**：树命令打开时 Host 先经元数据缓存 `listObjects` 判数——≤ 300 直接出图；> 300 先弹**选择表**（QuickPick 多选，默认全选、支持输入过滤反选），选择结果以 selection scope 出图（打开前完成引导，无白屏往返）。
- 渲染降级三档（工具栏「完整 / 紧凑」按钮可手动切换；默认按表数自动选档）：

  | 档 | 条件 | 节点形态 |
  |---|---|---|
  | 完整 | ≤ 60 表 | 表名标题栏 + 列清单（每节点最多显 12 行 +「+N 列」尾行；PK/FK 行标识见 §13.4）；节点标题双击折叠 / 展开 |
  | 紧凑 | 61 – 150 表 | 仅标题栏 + 列数徽标；完整列清单 hover tooltip 展示 |
  | 选择模式 | > 150 表 | 不自动出图，画布中央引导选择表子集（同打开引导语义，面板内复选清单） |

- selection 模式下端点不全的 FK 边不绘制，状态行计数提示「N 条跨选区关系未显示」；FK 数据量天然远小于表数（每表数条），不设独立上限。

### 13.5 边视觉规范

| 项 | 规格 |
|---|---|
| 方向与基数 | 从 **FK 子表（多端）** 指向 **被引用父表（一端）**；多端 = 鸦爪（crow's foot）三叉符号、一端 = 双竖线——基数固定标注 N:1（由 FK 语义推导）；1:1 识别（FK 列集恰为唯一键）为 P2 |
| 路径 | 水平三次贝塞尔：出边锚点 = 子表右缘中点、入边锚点 = 父表左缘中点；同层边 / 打环反转产生的回边改垂直锚点兜底；锚点计算为 webview 纯函数（有单测） |
| 复合 FK | 按约束名**合并为单边**（sourceColumns / targetColumns 列序对齐——MySQL 逐行返回合并且 PG 列序口径沿用表设计器批次 B 经验）；tooltip 列出列映射 `col → refCol` |
| 自引用 FK | 保留绘制：右缘出、环绕回右缘下部的自环弧；不参与分层约束（布局忽略，见 D-22） |
| 悬停 | 边高亮 `--color-primary` + tooltip（约束名、列映射、基数）；节点 hover = 相邻边与邻接节点保持高亮、其余节点/边降透明度（25%）——大图快速聚焦局部关系 |
| 颜色 | 边线默认 `--color-border-strong`，高亮 `--color-primary`；淡化态 opacity 0.25；全 token（C-12） |
| 外键动作标注 | ON DELETE / ON UPDATE（tooltip 附注）依赖 `KeyMeta` 契约扩展——**P2**，首批边 tooltip 不含动作（§13.10） |

### 13.7 加载 / 错误 / 空态

| 态 | 呈现 |
|---|---|
| 加载 | 画布中央「正在读取表结构…（N / M 表）」；元数据缓存命中时毫秒级直出无感 |

### 13.8 刷新与缓存失效

- 面板数据默认走元数据缓存（概要 §7.5：objects 手动失效 / columns·keys TTL 5min），同库重复打开毫秒级。
- 工具栏「刷新」= 绕缓存重拉（失效该库 objects / columns / keys 后重建，等同树节点刷新语义）。
- Console / DDL 执行后的缓存失效联动（概要 §7.5）**不自动重绘**已打开的 ER 面板（用户手动刷新；自动跟随列 P2 评估）。

### 13.9 导出（✅ 已交付，v0.2.33 单元格查看器批次③）

- **SVG**：画布是「HTML 节点 + SVG 边」混合结构、无法直接序列化——独立 SVG **从图数据模型直接生成**（`webview lib/erExport.ts buildErSvg` 纯函数；几何/高度复用 erCanvas 纯函数防双源漂移；色值由页面解析 `--color-*` token 后经 palette 注入，token 单一来源不动）→ base64 → `sys.saveFile`（Host SaveDialog + 写文件）。
- **PNG**：webview 内 canvas 光栅化（SVG blob → `drawImage` → `toDataURL`，2x 缩放）→ base64 → `sys.saveFile`。
- **C-13 边界确认**：SaveDialog 与文件写入恒在 Host；光栅化发生在 webview 属「渲染行为的延伸」（单张图、内存有界），不属于「大批量数据处理」——不违反重活不进 Webview 的口径。无 native 依赖（不引 node canvas，D-05 口径不变）。
- 工具栏入口「导出 SVG / 导出 PNG」（空图禁用）；结果提示在状态行（已导出 → 路径 / 已取消 / 导出失败），6s 自动消失；悬停/搜索等视图态不进导出（全图全透明度）。

### 13.11 实现锚点与批次拆解

## 14. Oracle 特化（M8-Oracle）

> 设计定稿草案（2026-10-18 落盘，待用户确认）；决议与摸底记录见概要 ADR D-23。Oracle 19c+（thin 驱动要求数据库 12.1+），连接绑定单个 PDB，树上「库」= schema（D-15/D-21 同构）。本章只写与通用交互的差异面，未提及处沿用既有章节。

### 14.1 连接表单

```
┌─ 新建连接 ────────────────────────────────────┐
│ 数据库类型：… ┃ 🅾 Oracle ┃ …                  │
│ 名称 * [Oracle 测试____________]               │
│ ─ 连接参数 ──────────────────────────────    │
│ 主机*[100.125.188.135]  端口*[1521]            │
│ 服务名*[orcl      ]     ⓘ                      │
│ 用户名*[dbkit   ]       密码 [●●●●●● 👁]        │
│ ▸ 高级选项                                     │
│   ─ 连接描述符 ─                               │
│   ☐ 使用自定义连接串（connectString）           │
│     [host:port/service 或 (DESCRIPTION=…)__]   │
│   ─ 身份 ─                                     │
│   ☐ 以 SYSDBA 连接（管理场景）                  │
│   ─ 超时与连接池 ─                             │
│   连接超时(ms)[15000]  连接池上限[4]            │
│ ─ 环境与保护 ─（通用，§3.1 不变）               │
└───────────────────────────────────────────────┘
```

| 项 | 规格 |
|---|---|
| 字段集 | `host` / `port`（默认 1521）/ `serviceName`（必填）/ `username` / `password`；高级组：`connectString`（string，toggle 开关）/ `role`（sysdba 布尔开关）/ `connectTimeout` / `poolMax` |
| 服务名 ⓘ | 「Oracle 服务名（service name）或 SID：PDB 应用连接填其注册服务名（如 `orcl`）；CDB 默认服务与 SID 同名可直填（如 `ORCLCDB`）。树上展开的「库」为该容器内的 schema」 |
| 无「默认库」字段 | Oracle 连接即绑定容器（service 寻址），无连接后切库语义——`serviceName` 即承载「默认库」角色（驱动规范 §3.1 的默认库硬性约定由它满足）；**不提供** `dynamicOptions='databases'` 建议（树上「库」= schema 与寻址不是同一层，建议列表反而误导） |
| 自定义连接串 | 开关开启后显示 `connectString` 输入（EZConnect `host:port/service` 或完整 `(DESCRIPTION=…)` 描述符）；填写后忽略主机/端口/服务名三字段（表单校验同步放行其留空）；RAC/SCAN、LDAP 命名、CONNECT_TIMEOUT 等高级参数的逃生口 |
| SYSDBA 开关 | 缺省关（normal）。开启 hint：「以数据库管理员身份连接，用于管理场景（如浏览全部 schema）；普通应用账号保持关闭」——thin 模式 `privilege: SYSDBA` 承载 |
| 测试连接状态卡 | 通用（§3.2）；成功行版本号展示 `Oracle Database 19c …`（`v$version` banner 截取） |
| 密码 | 通用（§3.2）：不回显、SecretStorage、导出占位 |

### 14.2 资源树层级与命名显示

```
▾ 🟢 Oracle 测试 (connection)          description: Oracle Database 19c / 已连接
  ▾ 📁 DBKIT (database)                ← schema 上树（D-15/D-21 同构）
    ▾ 📂 表
      ▸ 📋 CF_USERS                    ← 大写如实显示
    ▾ 📂 视图
  ▾ 📁 CF_TEST
  ▾ 📁 PDBADMIN                        ← PDB 本地管理员视同业务 schema（mssql dbo 同口径）
```

| 项 | 规格 |
|---|---|
| database 层 | schema 列表 = `ALL_USERS` 排除 `ORACLE_MAINTAINED='Y'`；description 不显示字符集（Oracle 无 per-schema 字符集语义），保持空 |
| 大写显示 | 标识符**如实返回存储形态**（未引号名一律大写），树上/网格/补全不做视觉折叠——所见即所得，SQL/DDL 生成与库内一致（D-23 岔口 5）；hint 场景（建表输入小写）不阻断，由引擎折叠并如实回显 |
| 展开失败 | 无权限 schema 展开报 E_PERMISSION（错误码文案 §9.2）——不静默隐藏 schema（可诊断性优先） |
| 表/视图 | `kind='table' | 'view'`；物化视图首批不入树（P2，README 声明） |
| 行估算 | 表节点不上树（通用 §8.1）；分页栏「约 N 行」取 `all_tables.num_rows`——**无优化器统计时缺省不显示**（实测无统计为 NULL），驱动不执行 COUNT（C-9） |

### 14.3 空串即 NULL：编辑与展示口径（C-7 裁剪，D-23 岔口 4）

| 场景 | 规格 |
|---|---|
| 读 | 空串**永远读不回**（引擎存 NULL）——NULL 单元格按通用 §4.2 灰色斜体展示；不存在「空串 ·」形态 |
| 写（编辑/新增输入空串） | 落 NULL 不阻断；**变更预览 Modal 与提交成功回执附一次性提示「Oracle：空串已按 NULL 存储」**（预览在语句列表上方黄条；回执在 Toast 文案尾缀） |
| NULL ⇄ 空串切换（§4.5） | 单元格右键「切换为空串」入口**隐藏**（引擎无该值域）；「设为 NULL」照常 |
| 筛选 | 值筛选输入空串等价 isNull 语义由驱动下推承载（`''` 参数化绑定即 NULL）；UI 无特化 |
| 乐观锁 | 变更列原值空串 ≡ NULL → `IS NULL`（D-03 无特化分支，引擎语义天然自洽） |

### 14.4 能力矩阵与菜单裁剪

| 能力 / 入口 | Oracle | 说明 |
|---|---|---|
| Console（`supportsSQL`） | ✓ | 方言 TNS/PL-SQL 词表（C-14 三份词表）；多语句关闭（core 逐条执行）；PL/SQL 匿名块按单语句下发 |
| 表格编辑（`editable`） | ✓ | 短事务 + 字段级乐观锁（D-03 同构）+ `RETURNING` 主键回填；IDENTITY 列新增行自动跳过（套件通用口径） |
| 取消（`supportsCancel`） | ✓ | abort → `break()`（实测连接可复用）；工具栏/进度取消语义与 mysql 差异：mysql 无 OOB 不可中断（声明 false），Oracle **真实服务端取消** |
| 分页 | offset | `OFFSET/FETCH`（12c+） |
| 查看表 DDL（`supportsDdl`） | ✓ | `DBMS_METADATA.GET_DDL`（transform 减噪）；视图走 `all_views.text`？——否：GET_DDL('VIEW') 统一口径 |
| 表设计器（`supportsDdlEditor` + `tableDesign`） | 全 Tab ✓ | 列/键/外键/索引全能力（`foreignKeyAlter=true`——Oracle 有 `ADD/DROP CONSTRAINT`）；索引类型下拉 `NORMAL / BITMAP`；外键动作：ON DELETE 支持 `NO ACTION/CASCADE/SET NULL`，**ON DELETE RESTRICT 与 ON UPDATE 全列隐藏**（Oracle 无对应语法，`refActions` 声明裁剪） |
| 类型建议词表（`DATA_TYPES`） | ✓ | `VARCHAR2(n)/NVARCHAR2(n)/CHAR(n)/NUMBER(p,s)/NUMBER/DATE/TIMESTAMP(n)/TIMESTAMP(n) WITH TIME ZONE/CLOB/NCLOB/BLOB/RAW(n)/FLOAT(n)/BINARY_DOUBLE/BINARY_FLOAT/ROWID/UROWID/INTERVAL YEAR TO MONTH/INTERVAL DAY TO SECOND`（按常用度排序） |
| 库级 DDL（`supportsDatabaseDdl`） | 建 ✓ / 删 ✓ / **编辑 ✗** | 新建 schema = `CREATE USER`（表单：名称必填 + 密码必填 + hint「schema 即用户（占 USERS 表空间，无限配额）」）；删除 = 树右键名称确认（`DROP USER … CASCADE` 标 destructive，确认文案明示「将连带删除该 schema 全部对象」）；「编辑库」不出现（用户不可重命名，方法存在性裁剪 D-19）；只读连接拒绝（通用 §8.3） |
| ER 图（`supportsErDiagram`） | ✓ | listKeys FK 自省完整（`all_constraints` 回链引用侧）；`collectRelationGraph` 零改动消费 |
| 交互式事务 | ✓ | `openSession`（SessionManager 空闲超时回收，§4.6/D-09）；Oracle 读不锁写（MVCC），「未提交不可见」契约照常 |
| 树节点 contextValue | 沿用 | connection `dbddl`；database `dbddl`/`dbddl-alter`（**alter 未实现 → 只挂 `dbddl`**，方法存在性显隐）——新增令牌逐条排查 P-40 锚定正则（AGENTS 既有清单） |

### 14.5 已知限制与后续批次（P2）

| 项 | 说明 |
|---|---|
| TCPS / 非对称加密 | 首批无 SSL 字段（Oracle 原生 TLS 走 TCPS 端口 2484 + wallet，测试与摸底实例均未配置）——P2 评估 |
| Console 大数精度 | >2^53 的 NUMBER 在 Console 结果失真（JS number 形态）；表格路径经 `fetchInfo` 保真无此问题（README 已知限制） |
| 时区口径 | DATE/TIMESTAMP 按客户端进程本地时区解释（thin 驱动语义，实测无视会话 TIME_ZONE）；`TIMESTAMP WITH TIME ZONE` 渲染 UTC 墙上时间、原始偏移丢失——tooltip「按连接时区解释」+ README 声明 |
| XMLType / 对象类型 / 集合 | 尽力文本展示（`unknown`）；对象列表/嵌套表不入树（P2） |
| LONG / LONG RAW | 遗留类型尽力支持；超长取数慢（README 声明） |
| ROWID 作 RowKey | 无主键表维持 D-03 默认只读（全驱动一致性）；ROWID 定位增强（行迁移漂移风险）P2 评估（D-23 否决案留痕） |
| 跨 PDB / Datapump / PL-SQL 调试器 | 范围外（批次边界提醒）：跨库查询可手写全局对象名（如 `other_schema.t`，同 PDB 内）；跨 PDB 需 database link，不做 |
| 物化视图 | 树不入、浏览不做（P2） |

## 15. AI 辅助（M9-AI）

> 上游：概要 §5.12 / ADR D-24（2026-10-23 四岔口用户确认：就地嵌入 / BYOK / 三能力齐做 / 生成直插 + 修复 diff）。
> 设计四原则：**① 副驾驶不是聊天窗**——AI 嵌在写 SQL（生成）/ 读 SQL（解释）/ 修 SQL（修复）三个既有痛点处，不自建聊天面板；**② AI 产物一律可审计、绝不直接执行**——生成/修复的 SQL 只以草稿或 diff 进编辑器，执行仍走既有链路（DangerGuard、prod 输表名确认、只读拦截、参数化照常），**AI 不降级任何护栏**；**③ C-10 延伸到 prompt**——API 密钥只进 SecretStorage，默认只发表结构、不发任何数据行；**④ 未配置不占 UI**——入口保留可发现性，点击后引导配置。

### 15.1 AI 设置页（BYOK 配置）

- **入口**：设置中心「AI 辅助」分类（见 §16）；AI 入口未配置的「去配置」引导深链直达该分类；命令 `dbExplorer.ai.settings` 同源
- **形态**：设置中心的内容区之一（分类框架与导航见 §16），字段与交互规则如下

| 字段 | 必填 | 说明 |
|---|---|---|
| API 地址 | ✓ | OpenAI 兼容 base URL（placeholder `https://api.openai.com/v1`），落 `dbExplorer.ai.endpoint` |
| API 密钥 | ✓ | 密码输入（eye 切换明文，§3.1 同款）；**只进 SecretStorage（`dbExplorer.secrets.ai`）**，不落 settings、**不回显明文**——已配置时占位符「••••••••（已配置，留空保持不变）」，行尾次级动作「清除」 |
| 模型 | ✓ | 模型名（placeholder `deepseek-chat`），落 `dbExplorer.ai.model` |

- **测试连接**：次级按钮，按**表单当前值**（含未保存的密钥）发最小请求——成功 Toast「连接成功 · {模型} · {耗时}」；失败在按钮下方行内错误（§15.5 文案），不改表单值
- **保存**：`ai.saveSettings`（apiKey 缺省 = 不修改现值；「清除」提交 `clearKey`）；成功 Toast
- **隐私说明（固定文案，不可关闭）**：「使用 AI 功能时，当前库的**表结构**（表 / 列 / 类型 / 注释）将发送给你配置的服务；**表数据不会发送**。」置于表单底部灰字
- **未配置引导**：三个 AI 入口在未配置（缺 endpoint/model/key 任一）时点击 → 信息弹窗「AI 功能需要先配置模型服务」[去配置] [取消] → 打开设置页（入口不隐藏，保可发现性）

### 15.2 生成 SQL（自然语言 → SQL）

- **入口**（三路同源命令 `dbExplorer.ai.generateSql`）：
  - CodeLens「✨ 生成 SQL」——每条语句上方与「▶ 执行」并排（§7.2 同款语句定位）；文档无语句时显示于首行；**光标跟随**（v0.1.20，二修）：仅当光标聚焦**空白行**时在该行补生成入口（语句行不重复显示）
  - 快捷键 `Alt+\`（光标处插入；**不占用** VSCode 内置 inline chat 的 `Ctrl+I`，避免与 Copilot 冲突）
  - 命令面板「DB Kit: AI 生成 SQL」
- **输入**：QuickPick 输入框，title「生成 SQL · {连接名} · {库}」（未绑定时显示「未绑定连接——生成将不携带表结构」），placeholder「如：查询最近 30 天下单超过 3 次的用户」；`Esc` 取消
- **上下文圈选**：绑定库 ≤50 表自动携带全部 schema；**>50 表**先弹多选 QuickPick（标题「选择提供给 AI 的表（当前库共 N 张）」，支持键入过滤，会话级记忆上次选择）
- **生成中**：Notification 通知「AI 正在生成 SQL…」（右下角常驻、可取消 → AbortController，静默中止不落任何文本）；锚点语句行尾同时显示 spinner 装饰（渲染不入文件）
- **结果呈现：直接插入编辑器并选中新插入文本**——插入锚点：CodeLens 触发 = 该语句之前；快捷键/命令 = 光标处。**无「预览确认」一步**：SQL 本就要人工审改后才执行，插入即草稿，护栏在执行侧兜底（原则 ②）。插入后通知附「**放弃这次修改**」：应用文本未被后续编辑才一键还原原文，否则提示用 Ctrl+Z（v0.1.20）
- 生成结果为纯 SQL（prompt 约束不带解释性废话）；失败 → Toast（§15.5），原编辑器内容零改动

### 15.3 解释 SQL

- **入口**：编辑器右键「DB Kit: AI 解释 SQL」（命令 `dbExplorer.ai.explainSql`）——有选区解释选区，无选区解释光标所在语句（切分定位与 §7.2 同源）
- **呈现**：Console 结果面板新增「**AI 解释**」Tab（消息通道扩展；结果面板单例跟随最近执行的 Console 心智不变）——**流式渲染 Markdown**，生成中闪烁光标占位；完成后尾部灰字注记「由 AI 生成，仅供参考」+「复制」动作
- **以最近一次为准**：重复触发取消上一轮流式（AbortController），Tab 内容整体替换；面板未打开时与执行结果同规则自动打开
- 解释输出为中文 Markdown：语句意图 / 逐子句说明 / 涉及表与关联 / 注意事项（索引、全表扫描风险等）
- 上下文与 §15.2 同源（>50 表同样先圈选）

### 15.4 错误修复建议（v0.1.20 三修：编辑器内联 diff 预览，Modal 下线）

- **入口**（双路同源 `ai.fixError`）：
  - 消息 Tab 错误条目尾部动作按钮「✨ 修复建议」
  - **编辑器内**：执行失败的语句行 CodeLens「✨ 修复建议」（复用执行注记的失败结果，文档一经编辑即消失）
  - 两路均**仅当该错误来自有文档来源的执行**（历史重跑 / 结果面板重跑无文档来源，不显示）
- **定位**（用户日志定因，P-66）：主路径 = **执行时的语句范围快照**（裸语句终点，不含尾分号）——文档版本与执行时一致即直通命中；版本不同再校验偏移处原文；回退全文语句匹配；有快照时**直接用快照 uri 打开文档**（反查重建的 URI 在含空格路径上编码往返不等，比对会假失配）
- **呈现 = 编辑器内联 diff 预览（C 方案）**：生成后建议 SQL **真实插入**到原语句尾分号之后（另起两行）——
  - 原语句段：整段**红底 + 删除线**（diffEditor.removedTextBackground 主题色）
  - 插入段：整段**绿底**（diffEditor.insertedTextBackground）——真实文本、多行、语法高亮
  - 原语句行首 CodeLens：「**✓ 保留更改**」「**✕ 放弃**」；右下角通知同款双按钮（「已生成修复建议，请在编辑器中选择保留或放弃」）双入口
- **保留更改**：删除 [原语句起, 插入段止) 整段并替换为建议 SQL（建议顶替原位置），应用前按「段内文本仍为原语句+插入段形状」终校验；**放弃**：删除插入段还原文档；**预览期间编辑文档 → 自动放弃并按内容定位还原插入段**（偏移漂移不依赖）
- 生成中 withProgress 通知（可取消）；失败经 Toast/通知呈现（§15.5）
- **不自动执行**：保留更改仅是文档编辑，用户自行 `Ctrl+Enter` 执行——危险判定与 prod 确认照常（原则 ②）
- 一次一条（单例预览，新建议顶掉旧建议）；预览期间文档处于「已修改」态（编辑器脏标记属预期）

### 15.5 AI 错误码 → 文案（§9.2 扩展，`AiErrorCode`）

| code | 文案模板 | 附带动作 |
|---|---|---|
| E_AI_NOT_CONFIGURED | AI 功能需要先配置模型服务 | [去配置] |
| E_AI_REQUEST_FAILED | AI 服务请求失败：{message} | [查看详情] [重试] |
| E_AI_ABORTED | （静默——用户取消不提示） | — |

- 呈现位置按触发面：生成（QuickPick/withProgress）与设置页测试走 Toast / 行内错误；修复在 Modal 内行内错误区；解释在「AI 解释」Tab 内错误态（含「重试」按钮）
- `E_STATE_LOST`（applyFix 文档失配）复用 RPC 层既有码，文案见 §15.4

### 15.6 上下文与隐私边界（C-10 延伸）

- prompt 组装收口 Host 侧纯函数模块（`aiPrompt.ts`），单测断言：**密钥 / 密码 / 连接串 / 主机信息永不出现**在 prompt 中——C-10 审计点新增此模块
- **默认只发表结构**（表 / 列 / 类型 / 注释，取自 MetadataCache）；**数据行在任何 v1 路径都不发送**（采样行 opt-in 开关列 P2，§15.7）
- prompt 携带方言说明（绑定 driverId → MySQL/PostgreSQL/… 口径），生成与解释按方言输出
- 日志：AI 调用打 info（方法 / 连接绑定 / 耗时 / token 用量若服务端返回）；prompt 内容不落日志；密钥永不落日志

### 15.7 范围外（P2，首批明确不做）

- `@dbkit` Chat 参与式入口（chat participant，多轮对话）
