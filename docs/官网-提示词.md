# DB Kit 官网制作——提示词模板

> 使用方式：新开会话后，把下方整段提示词发给 agent（或先说「读 docs/官网-提示词.md 并执行其中的提示词」）。

## 任务

为 VSCode 数据库插件 **DB Kit** 制作产品官网（介绍页，非文档站），并部署到 GitHub Pages。这是流量曝光的主阵地：让 30 秒内的访客明白「这是什么、能干什么、怎么装」。

## 已定决策（不要重复询问）

- 技术形态：**Vite + React 单页**（组件化 + 动效），仅中文
- 视觉风格：**深色科技风**——暗底、渐变光晕、玻璃拟态卡片、滚动微动效（Linear / Raycast 式）
- 品牌色：图标渐变 `#2b7fff → #1554c0`（圆角方 + 白描边数据库圆柱，素材在 `packages/extension/media/extension-icon.png|.svg`）
- 部署：GitHub Pages（仓库 Actions 自动部署，默认地址 `https://fengjing95.github.io/vsc-plugin-db/`，Vite `base` 需相应设置）
- 内容语言：仅中文

## 项目事实（内容唯一事实源，禁止虚构）

- 仓库：https://github.com/Fengjing95/vsc-plugin-db （分支 main）
- Marketplace：扩展 ID `db-explorer-dev.db-kit`，详情页 https://marketplace.visualstudio.com/items?itemName=db-explorer-dev.db-kit
- 安装方式：VSCode 扩展面板搜 `DB Kit` / `ext install db-explorer-dev.db-kit` / [GitHub Releases](https://github.com/Fengjing95/vsc-plugin-db/releases) 下载 VSIX（当前 v0.1.1）
- 界面截图（1600×1000 深色）：`docs/images/` 下 `overview-table.png`（主图：资源树+表格）、`console.png`、`schema-editor.png`、`database-ddl.png`、`export.png`
- 详情页文案源：`packages/extension/README.md`（hero 一句话 + 五大亮点：表格工作台 / Console 刹车 / 结构免 DDL / 后台导出 / 开箱即连）

### 已支持（做成能力矩阵卡片，六引擎）

MySQL · PostgreSQL · SQLite · MongoDB · Redis · Mock（内置演示）；
能力维度：资源树浏览 / 表格编辑 / SQL Console 或命令控制台 / 结构编辑 / 库级 DDL / SSL 与 SSH 隧道 / 后台导出——逐格口径以 `packages/extension/README.md` 支持矩阵为准，不得夸大。

### 即将支持（Coming Soon 三卡，带 GitHub issue 反馈链接）

1. **SQL Server** 2. **Oracle** 3. **国产数据库（信创）**——达梦 / 人大金仓 / openGauss 合一卡片
   每卡配「期待它？去 issue 说一句」按钮，链接到仓库 Issues（是否为三个目标预建独立 issue：【决策点，问用户】）

### 已知限制（诚实展示，防差评，一小节即可）

UI 仅中文；桌面版 VSCode（^1.85）；SQLite 限 ≤100MB；MongoDB 结构类命令与 Redis 编辑不支持；无遥测。全文见仓库 CHANGELOG。

## 工程约束

- 站点放独立目录 `website/`（Vite + React + TS；是否并入 pnpm workspace 由你评估后与用户确认，倾向并入以便 CI 门禁覆盖）
- 不修改 `packages/` 插件本体与详情页内容；仓库四道门禁（typecheck/test/lint/build）必须保持绿
- 响应式（桌面 + 移动端）、图片懒加载、SEO（title / description / og:image 用主截图）、可访问性（语义化标签、对比度）
- 新增部署用 GitHub Actions workflow（Pages），上线前先发预览链接给用户确认

## 流程纪律（硬性）

1. **先沟通后动手**：读完本模板后，用 AskUserQuestion 与用户确认【】内开放项 + 页面信息架构（板块顺序/增减），确认后再写码
2. 所有功能声明必须能在支持矩阵或详情页 README 中找到出处，不得虚构数据与用户数
3. 分批提交，提交信息遵循仓库惯例（中文摘要）
4. 完成后交付：预览链接 + 部署地址 + 更新根 README 增加官网入口
